# 开放平台接口（`dev.*` / `/api/dev/*`）

改的是**开放平台后台里的机器人**：昵称、头像、简介、Webhook、IP 白名单。
不是机器人自己的菜单 / 指令——那套走机器人 token（`qq.call`）。

三条路共用同一份实现（`src/dev/`）：

| 入口 | 谁在用 | 前缀 |
|---|---|---|
| HTTP | 面板、外部脚本 | `/api/dev/*` |
| 宿主协议 | dsh-roost、任意语言插件 | `POST /rpc {method:'dev.*'}` |
| 内核插件 | 本进程 JS 插件 | `ctx.dev` |

面板地址默认 `http://127.0.0.1:<端口>/`，同一台机器上带面板令牌访问。

## 一、先搞清楚「能不能干活」

```
GET /api/dev/session?verify=1
```

**永远返回 200**——它是个探针，答案在 `state` / `code` 里。不传 `verify`
就只查本机票据（不发网络请求），传了就真向平台核一次（`list_bots` 有
30 秒缓存，不会把自己打进限频）。

```jsonc
{
  "ok": true,
  "state": "ready",          // 见下表
  "code": "OK",              // 和错误码同一个词表
  "message": "可以改：天道酬勤-测试中（AppID 102055275）",
  "hint": "",
  "loggedIn": true,
  "remembered": true,
  "cooldownMs": 0,
  "bound": { "id": "main", "name": "天道酬勤-测试中", "appid": "102055275" },
  "botCount": 3,
  "matched": true
}
```

| state | 含义 | 下一步 |
|---|---|---|
| `ready` | 登录正常，本机这只在账号里 | 可以改 |
| `logged-in` | 有票，但没核过（`verify=0`） | 需要确认时加 `verify=1` |
| `need-login` | 本机没有票据 | 扫码，或粘 cURL |
| `expired` | 平台说票据失效 | 重新登录 |
| `account-empty` | 账号名下一只机器人也没有 | **登错号** |
| `bot-missing` | 账号里有机器人，但没有本机这只 | 登错号 / AppID 填错 |
| `no-appid` | 本机机器人没填 AppID | 去「机器人」页填 |
| `busy` | 平台限频 | 等 `retryAfterMs` |
| `error` | 其它平台错误 | 看 `code` / `retcode` |

> 为什么不是布尔：`false` 无法区分「没登录」和「登错号」，而这两件事用户
> 要做的动作完全不同。

### 票据为什么会「自己过期」

我们存的是**短期派生票**（`b-token` 等，按小时计），而扫码用的浏览器 profile
里躺着一整套**长期登录态**。所以典型现象是：

- 面板说「登录已过期」，你打开那个浏览器窗口却还是登录状态；
- 因为长期身份还活着，页面一加载就能重新换出一张新的 `b-token`。

因此「cookie 登录」不是坏了，而是**快照不会自己续期**。

### 自动续期（默认开）

平台一回 `retcode:401`，框架就用**同一个 profile** 在**后台（无头模式）**
开一次浏览器，让页面把新票换出来，**拿到立刻关掉**、整份替换票据，然后只重试
刚才那一次请求。用户侧的表现是「卡一下，然后自己好了」，**桌面上不会弹窗**
（`--headless=new`，扫码那条路径仍然是可见窗口）。

- 只对 401 生效：本机没票（`NOT_LOGGED_IN`）、限频（`10000`）、业务错都不会弹窗。
- 20 秒内最多一次；续期期间不重入（续期自身校验失败也会 401）。
- 「导入并验证」期间关闭：那本来就是一次票据校验，自动续期会把「你粘错了」
  变成「看起来成功了」。
- **主动检查**：启动 3 秒后探一次，之后每 30 分钟复查（`services.devTicket`，
  默认开）。票据过期就就地换票，不用等某个请求先撞上 401。本机从没存过票时
  直接跳过——不会凭空开浏览器。
- **换票成功即视为登录恢复**：只顺手试一次原请求，不再「5s / 10s / 20s 连试
  三次」（实测三次全撞 `10000`，连打只会把恢复时间往后推）。这一次仍撞忙就报
  `RENEWED_WAIT`（**不是** `PLATFORM_BUSY`）：文案是「票据已换新，65 秒后自动
  重试」，`hint` 明说「不用重新扫码」。
- 换票成功后会自动排一次 **65 秒后的补拉**（`ROOST_DEV_RENEW_WAIT_MS`）：到点
  再要一次列表，成了就把状态翻回正常；中途只要任何一次请求成功，这发补拉就会
  被取消（不白打）。面板也照这个时间自己刷新一次，用户不用点。
- 限频冷却**递进**：首次 10 秒，连续命中才 20 → 40 → 60 秒，成功一次归零。
  实测恢复常常只要几秒（2.2s / 2.5s / 13s），一律锁 60 秒会变成「平台早好了、
  面板还挂着 60 秒」，用户点一次失败一次。
- 关掉：`ROOST_DEV_AUTO_RELOGIN=0`（只关换票，自检仍会记录「票据不可用」）。
- 无头跑不起来的环境（远程桌面 / 安全软件拦 / 老旧内核）：`ROOST_DEV_REFRESH_MODE=window`
  换成可见窗口，只作排障用。
- 面板回显在 `GET /api/dev/status` 的 `autoRelogin.last`（`ok` / `reason` / `message`）。

> profile 里的登录态也过期了（比如你手动退出过），续期会在 25 秒后收窗并报
> `timeout`，此时只能重新扫码——自动续期不会把人架在「等一个永远不会成功的窗口」上。

## 二、HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/dev/status` | 登录状态 + 扫码进度（不含票据值） |
| GET | `/api/dev/session?verify=1` | 能不能干活（见上） |
| GET | `/api/dev/errors` | 错误码表（含 `hint`） |
| POST | `/api/dev/login/scan` | 起扫码窗口（同步等窗口就绪，1–3 秒） |
| GET | `/api/dev/login/scan` | 轮询扫码进度 |
| POST | `/api/dev/login/scan/cancel` | 取消扫码并关窗 |
| POST | `/api/dev/login/import` | 备选：粘 cURL / cookie |
| POST | `/api/dev/remember` | 登录后改「要不要记住」：立刻写盘 / 删盘，不用重登 |
| POST | `/api/dev/logout` | 清票据（连扫码窗口 profile 一起删） |
| POST | `/api/dev/browser` | 指定扫码用的浏览器路径（空 = 自动探测） |
| GET | `/api/dev/bots` | 账号下的机器人列表 + `bound` / `matched` |
| GET | `/api/dev/bot?appid=` | 单只的详情 |
| POST | `/api/dev/bot` | 改资料 / 连接 / 白名单 |
| POST | `/api/dev/avatar` | 换头像 |
| GET | `/api/dev/scope?appid=` | 体验白名单：测试用户 + 白名单群 |
| POST | `/api/dev/scope` | 加 / 删测试用户或白名单群 |
| POST | `/api/dev/focus` | 把扫码窗口切到该机器人设置页 |

### 只能改「当前机器人」

`/api/dev/bot`、`/api/dev/avatar`、`/api/dev/focus` 的 `appid` **必须等于**
本机 `config/bots/<id>.json` 里的 `appId`（面板 `?bot=<id>` 切哪只就是哪只），
否则 `403 NOT_BOUND`。票据是**账号级**的，允许随手挑等于「一点就把另一只改坏」。

### 改资料

```jsonc
POST /api/dev/bot
{ "appid": "102055275", "patch": {
    "base":    { "name": "新名字", "desc": "新简介" },
    "connect": { "action": 1, "webhookUrl": "https://example.com/cb" },
    "ip":      { "mode": "replace", "addresses": ["1.2.3.4"] }
} }
```

- `base`：只发改动过的字段（`filter` 里对应位置 0/1）。
- `connect.action`：`1` 保存 Webhook / `2` 校验 / `3` 切 WebSocket。
- `ip.mode = "replace"`：先读当前列表再算差集——官方只提供增(1)/删(2)，
  不算差集就变成「只能加不能删」。

### 换头像

```jsonc
POST /api/dev/avatar
{ "appid": "102055275", "dataUrl": "data:image/png;base64,..." }
// 或者 { "url": "https://example.com/a.png" }
// 兜底 { "avatarId": "从官方页面拿到的 id" }
```

官方限制（2026-11 在「修改机器人资料」弹窗核对）：

- 格式：**png / bmp / jpeg / jpg / gif**（不收 webp）
- 大小：**≤ 2 MB**
- 形状：正方形（页面可裁剪），弹窗建议 144×144，创建页要求 ≥ 240×240

面板会先把本地图**居中裁成正方形、缩到 512×512 的 PNG** 再传（官方说 PNG
效果最佳，且带 alpha 不会像 JPEG 那样把透明底压成黑边）。服务端再拦一道，
因为 `url` / `avatarId` 两条路都绕过了前端。

上传接口路径没有公开文档，按候选顺序试一次；全不认时错误码是
`AVATAR_UPLOAD_FAILED`，`hint` 里写明兜底办法（官方页面传一次，把
`avatar_id` 填进来）。

### 体验白名单（测试用户 / 白名单群）

机器人正式发布前，只有名单里的人/群能用它调试。

```jsonc
GET /api/dev/scope?appid=102055275
{
  "ok": true, "appid": "102055275",
  "users":  [{ "uin": "10001", "name": "小明" }],
  "groups": [{ "groupId": "123456", "name": "测试群", "inGroup": true }],
  "limits": { "groups": 20 }
}

POST /api/dev/scope
{ "appid": "102055275", "kind": "users",  "action": 1, "ids": ["10001"] }
{ "appid": "102055275", "kind": "groups", "action": 2, "ids": ["123456"] }
```

- `kind`：`users`（测试用户，填 **QQ 号** 5~11 位）/ `groups`（白名单群，填**群号** 5~10 位）。
- `action`：`1` 添加 / `2` 移除。**一次只动一类、只动一份名单**——平台侧
  「加」和「删」是两个动作，混着发会出现「一半成功」。
- `groups[].inGroup === false` 表示机器人已经不在那个群里（平台允许先把群号
  加进白名单，再把机器人拉进群）。名字为空是同一原因：不在群里时拿不到群名。
- 白名单群上限 **20 个**（官方前端写死的数），超过在本机就拒。

读取用 `bot_scope_manager/scope_cfg/query`（一次把两样都拿回来，分开请求只会
多挨一次限频）；写入是两条不同的 CGI：测试用户走 `white_list/modify`
（`set_friend_whitelist`），白名单群走 `dev_capability/modify`
（`group_admin_action`）。注意后者的 `bot_appid` 官方发的是**字符串**，
其它接口是数字，别「统一」掉。

## 三、错误码

`code` 稳定，`error` 是给用户看的一句话，`hint` 是**下一步该干什么**。

| code | HTTP | 含义 |
|---|---|---|
| `NOT_LOGGED_IN` | 401 | 本机没有票据 |
| `TICKET_EXPIRED` | 401 | 票据失效（平台 401） |
| `NO_COOKIE` | 400 | 粘贴内容里没有 cookie |
| `NO_TICKET` | 400 | 有 cookie 但没有票据键 |
| `BAD_TICKET` | 401 | 票据平台不认 |
| `PLATFORM_BUSY` | 429 | 平台限频（带 `retryAfterMs`） |
| `RENEWED_WAIT` | 429 | 票已换新、平台还没放开；等 `retryAfterMs` 后自动补，**不用重新登录** |
| `PLATFORM_ERROR` | 400 | 平台业务错误（带 `retcode`，如 11001/11002） |
| `BAD_RESPONSE` | 502 | 平台返回非 JSON（多为代理/风控页） |
| `BAD_APPID` | 400 | 缺 `appid` |
| `NO_LOCAL_APPID` | 400 | 本机机器人没填 AppID |
| `NOT_BOUND` | 403 | 不是当前机器人 |
| `ACCOUNT_NO_BOT` | 403 | 账号下一只机器人也没有 |
| `BOT_NOT_IN_ACCOUNT` | 403 | 账号里没有这只 |
| `AVATAR_UPLOAD_FAILED` | 400 | 头像上传失败（带 `attempts`） |
| `BAD_IMAGE` | 400 | 图片格式 / 大小 / 形状不合规 |
| `BAD_SCOPE` | 400 | 白名单的 kind / action / 号码格式不对，或群超过 20 个 |
| `NO_BROWSER` | 400 | 没找到 Chromium 系浏览器 |
| `INTERNAL` | 500 | 本机异常 |

失败响应体统一长这样：

```jsonc
{ "ok": false, "code": "NOT_BOUND", "http": 403,
  "error": "只能改「天道酬勤」（AppID 102055275），不接受 999",
  "hint": "这块面板只改本机跑着的那只机器人；要改别的，先在「机器人」页切过去" }
```

## 四、宿主协议 / 插件

```
dev.status            read     登录状态（不含票据）
dev.session.check     read     能不能干活（verify 才联网核）
dev.bots              read     机器人列表
dev.bot.get           read     单只详情
dev.bot.set           message  改资料 / 连接 / 白名单（显式 appid）
dev.bot.avatar        message  换头像（dataUrl / url / avatarId）
dev.scope.get         read     体验白名单：测试用户 + 白名单群
dev.scope.set         message  加/删白名单成员（kind + action + ids）
dev.bot.focus         read     扫码窗口跳到该机器人设置页
dev.login.*           manage   登录相关（票据 = 全部机器人的管理权）
dev.session.remember  manage   改「记住登录」：立刻写盘 / 删盘
dev.browser.set       manage   换扫码浏览器
```

插件侧走 `ctx.dev`：`status` / `check` / `bots` / `getBot` / `setBot` /
`setAvatar`，**没有登录**——登录只能由人从面板做。

## 五、OneBot 兼容层

| action | 映射 | 说明 |
|---|---|---|
| `set_qq_profile` | `base.name` + `base.desc` + `setAvatar` | `nickname` / `avatar` / `longNick`（或 `personal_note`）；`company`、`email` 等官方无接口 |
| `get_self_longnick` | `getBot().base.desc` | 读简介 |
| `set_self_longnick` | `base.desc` | 写简介 |

`avatar` 支持 `http(s)://`、`base64://`、`file:///`、本地路径；本机先按
官方限制（格式白名单 + 2 MB）拦一道。没登录 / 登错号返回 `1401`，消息里
带「下一步做什么」；参数不对返回 `1400`。

## 六、票据纪律

- 票据**账号级**：一份 cookie 管该开发者名下全部机器人，所以任何写操作都
  必须显式带 `appid`，且面板层只放行本机那只。
- 票据**不进日志、不进返回值、不进错误信息**；`describe()` 只给布尔。
- **默认记住**：登录成功即写 `data/dev-session.json`（0600），否则每次重启
  框架都要重扫一遍。要「只本次进程有效」就把面板上的「记住登录」取消勾选，
  或 `POST /api/dev/remember {"remember":false}`——**立刻删盘、不重登**。
- 命平台限频（`retcode 10000`）后主动停手 60 秒，冷却期不出网。
