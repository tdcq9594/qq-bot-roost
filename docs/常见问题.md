# 常见问题

按「现象 → 原因 → 怎么查」组织。查不到答案时，先看 `logs/bot.log` 最后 50 行。

---

## 启动阶段

### 配好了，但机器人没反应

**先点面板概览页的「体检」。** 它会把凭证、连接、intents、插件目录权限、
下载源、面板暴露面一次查完，有问题的项直接告诉你去哪儿改。

体检里最常见的一条是 **「群聊事件没订阅」**：intents 少了一位，网关连得上、
日志也正常，但群消息一条都进不来。

### 提示「已经有一个实例在跑（PID xxx）」

同一个 AppID 不能同时连两次。两个进程连同一个机器人，服务端会判定冲突、互相踢下线
（关闭码 **4902**），表现是机器人反复掉线、消息时有时无——而且你很难意识到是自己开了两个窗口。

处理方式：

```bash
# Windows：结束那个进程
taskkill /PID <提示里的PID> /F
# 或者直接关掉那个命令行窗口
```

如果确认要同时跑（不推荐，两个实例会抢消息），加 `--force`。

**为什么不做成一刀切禁止多开**：不同 AppID 跑多个机器人是合法需求，
锁的粒度是「AppID」而不是「进程」。真正的多机器人支持见
[架构说明](架构说明.md)。

### 双击 start.bat 没反应 / 窗口一闪就关

先确认一件事：**这台机器装 Node.js 了吗**。本项目不是免安装的独立程序，
`start.bat` 只是帮你调用 `node`，Node 本身必须装在系统里。

```bash
where node     # 有输出才算装了
node -v        # 需要 v22 以上
```

如果 `where node` 没输出，去 <https://nodejs.org/> 装 LTS 版本，**安装时勾选 Add to PATH**，
装完关掉所有命令行窗口重新开（PATH 是启动时读取的）。

如果已经装了但不在 PATH 里，在 `bot/` 目录下建一个 `node-path.txt`，写一行完整路径：

```
C:\Program Files\nodejs\node.exe
```

`start.bat` 会按这个顺序找 node：系统 PATH → 环境变量 `NODE_EXE` → `node-path.txt` →
同目录 `node\node.exe`（便携版）。

> 另一个历史坑：`.bat` 文件如果是 LF 换行，`cmd.exe` 解析带括号的多行块会失败，
> 表现就是双击毫无反应。仓库里已加 `.gitattributes` 强制 `*.bat` 用 CRLF，防止再被改回去。

### 启动就报「需要 Node.js 22 或更高版本」

用到了 Node 22 才有的内置全局 `WebSocket`，低版本跑不起来。

```bash
node -v            # 确认版本
```

去 <https://nodejs.org/> 装一个 LTS 版本即可，**不需要 `npm install`**。

### 启动后没有输出「凭证有效」

| 现象 | 原因 |
|------|------|
| `4014 intents 无权限` | 没开通群聊能力，或 `intents` 填错 |
| `10004 机器人不存在` | AppID 错了 |
| `凭证验证失败` | AppSecret 错了，或复制时带了空格 |

去 <https://q.qq.com> → 你的机器人 → 「功能配置」确认**群聊**能力已开通。
这是最容易漏的一步，不开通连不上。

### 提示「根目录还留着旧的 config.json」

旧版配置在根目录，已经迁移到 `config/bot.json`。确认新配置能正常跑之后，可以删掉旧文件。
**迁移不会自动删旧文件**——里面有 AppSecret，留着当后路。

## 收不到消息

按顺序排查，大多数问题在前两步。

### 1. 机器人有没有被 @

官方群聊的默认规则是**必须 @ 机器人才推送消息**。不 @ 时平台压根不会发事件过来。

先让群里的人 @机器人 发一句 `/ping`。

### 2. 这个群在沙箱配置里吗

**开发中的机器人只收「沙箱群」的消息**。去开放平台把这个群加进沙箱列表。

### 3. 机器人是运行期间被拉进群的吗

`GROUP_ADD_ROBOT` 事件只在**在线时**才收得到。离线期间入群，这个事件会永久丢失。

### 4. 看事件统计

面板「概览 → 事件统计」：

| 显示 | 含义 |
|------|------|
| 一条都没有 | 平台压根没推事件，问题在开放平台配置 |
| 有事件但没有 `GROUP_MESSAGE_CREATE` | 收到的是系统事件，消息事件没开通 |
| 有 `GROUP_MESSAGE_CREATE` 但没回复 | 问题在本程序，看日志有没有报错 |

### 5. 面板里看不到群？

**官方没有「查询机器人所在群列表」的接口**，群只能靠事件被动发现：

| 事件 | 触发条件 |
|------|----------|
| `GROUP_ADD_ROBOT` | 机器人在**运行期间**被拉进群 |
| `GROUP_AT_MESSAGE_CREATE` / `GROUP_MESSAGE_CREATE` | 有人在群里 **@机器人** 说话 |

已知群 openid 时，可以在面板「群组」页底部**手动登记**。

## 发不出消息

### 提示「超过被动回复窗口」

被动回复必须在收到消息后一定时间内发出，**群聊和单聊不一样**：

| | 窗口 | 最多回复 |
|---|---|---|
| 群聊 | 5 分钟 | 5 次 |
| 单聊 | **60 分钟** | **4 次** |

内核会在窗口剩 15 秒时自动降级为主动消息，所以正常情况下你不会看到这个错误——
除非**主动消息额度也用完了**。

> 单聊曾经按群聊的 5 分钟算过，那是 bug：单聊第 6 分钟就被误判超窗，
> 白吃「每个好友 1000 条/天」的额度（被动回复本来不占额度）。
> 2026-10-29 已按会话类型拆开。

### 提示「今天这个会话的主动消息额度已用完」

官方限制主动消息：**单会话 20 条/分钟**，且**每个群 / 每个好友每天最多 1000 条**。
两个维度框架都记着，撞哪个都会报这个错。

解决办法：等用户 @ 一次机器人，就能继续用被动回复；分钟级额度一分钟后就恢复，
日额度每天重置。

查看当前用了多少：群里发 `/status`，或看 `data/bots/<机器人id>/quota.json`。

### 机器人显示离线

WebSocket 断了。面板「概览」页点「重连」，或看日志里的关闭码：

| 关闭码 | 含义 |
|--------|------|
| `4013` | intents 参数无效 |
| `4014` | intents 无权限（多半是没开通群聊能力） |
| `4902` | 同一机器人有多个连接在抢，关掉多余的实例 |

## 面板打不开

### 端口被占用

**新版会自动顺延**：15207 被占就试 15208、15209……实际地址看启动日志那行：

```
INFO [webui] 可视化面板: http://127.0.0.1:15208/
```

如果 20 个端口都占了（`webui.portTries` 可调），会提示面板未启动。
这时先找残留进程：

```bash
# Windows
netstat -ano | findstr 15207
# 拿到 PID 后
taskkill /PID <pid> /F
```

### 浏览器没自动打开

- 命令行加了 `--no-open`？
- `config/bot.json` 的 `webui.openBrowser` 是不是 `false`？
- 手动访问日志里那个地址即可。

### 打开是空白页

前端是原生 JS，没有构建步骤。检查是不是被浏览器插件拦了，或试试无痕窗口。
按 F12 看 Console 有没有报错。

## 权限相关

### 我发了 /claim 但没反应

| 原因 | 解决 |
|------|------|
| 已经有主人了 | `/claim` 只在 `owners` 为空时可用。改 `config/bot.json` 的 `owners` |
| 认领码不对 | 看启动日志那行「认领码: XXXXXX」，面板「日志」页也能看到 |
| 认领码过期 | 每次重启会重新生成，用最新的 |

### 我是群主，为什么没有管理权限

群主是靠消息报文里的 `member_role = owner` 识别的，**只有发过言才能识别**。
先发一条消息（哪怕 `/ping`），系统就会记下来。

如果还是不行，用 `/whoami` 拿到自己的 openid，让主人执行：

```
/admin set <你的openid> 1 group:<群openid>
```

### 为什么不能给自己提权

设计如此。规则是**只能授予数字更大的等级**，也就是只能给比自己权限低的人授权。
`0`（主人）只能改配置文件或认领，命令无法授予。

详见 [权限模型.md](权限模型.md)。

## 插件相关

### 从市场安装插件报「无法执行 git：spawn git ENOENT」

**0.5.4 之前的老版本才有这个问题，升级就好。**

旧版用 `git clone` 拉插件，机器上没装 git 就会报这个。当时的前提假设是
「项目本身是 clone 下来的，git 一定在」——但很多人是下载 zip 解压用的，根本没装。

0.5.4 起改成下载 GitHub 的 tar 包自己解，**不需要 git，也不需要任何外部命令**。
如果升级后还报这个错，说明你跑的还是旧代码，检查一下 `package.json` 里的 version。

### 插件市场打不开 / 列表是空的

市场数据来自 GitHub。国内访问不稳时：

- 面板会显示「离线缓存（N 小时前）」——这是后端用本地缓存兜底，功能仍可用
- 缓存文件在 `data/market-cache.json`，删掉会强制重新拉
- 想换源：全局配置 `plugins.marketUrl` 指向你自己的 `index.json`

### 装了插件但没生效，面板里也看不到

**0.5.5 之前的版本才有这个问题。**

旧版的默认配置是 `plugins: { mode: 'include', list: [] }`，字面意思「一个插件都不启用」。
从市场装的插件不在名单里 → 不加载；而面板又只列已加载的 → 你看不到它、也没法启用。

0.5.5 起：
- 默认改成 `mode: 'all'`（**装了就用**）
- 旧配置（include + 空名单）会自动按 all 处理，控制台会提示一句
- 未启用的插件也会列在面板里，标「已禁用」，点「启用」即可
- 启用/禁用会同步写回配置，重启后依然生效

想精细控制哪个机器人跑哪些插件，编辑 `config/bots/<id>.json`：

```jsonc
"plugins": { "mode": "include", "list": ["dice", "echo"] }  // 只启用这两个
"plugins": { "mode": "exclude", "list": ["kun"] }            // 除了 kun 都启用
"plugins": { "mode": "all", "list": [] }                     // 全启用（默认）
```

### 怎么卸载插件

面板「插件」页，每个插件卡片最右边有「卸载」按钮。

会删掉 `plugins/<id>` 整个目录（代码没了），但**数据保留**——
群档案、插件存档都在 `data/bots/<机器人>/plugins/<id>` 里，重装之后接着用。

想连数据一起清，卸载后手动删那个数据目录。

### 插件加载失败

面板「插件」页会显示错误原因，`logs/bots/<机器人id>/plugins/<id>.log` 有详细日志。

常见原因：

| 现象 | 原因 |
|------|------|
| `既没有 plugin.json 也没有 index.js` | 目录结构不对，参考 `plugins/echo/` |
| `命令 "xxx" 已被插件 yyy 注册` | 命令名冲突，改名 |
| `默认导出必须是 { id, setup(ctx) }` | `index.js` 导出格式不对 |
| Python 插件起不来 | 系统没有 Python，或依赖装失败（日志里会有 pip 原始报错） |

### 自动装依赖很慢 / 失败

首次加载带 `requirements.txt` 的插件会建 `.venv` 并 pip install，慢是正常的。
装完之后哈希记在 `.deps.json`，下次不再装。

装失败时日志里会给出可手动执行的命令，照着跑一遍即可。

想彻底关掉自动安装：`config/bot.json` 里 `plugins.autoInstallDeps = false`。

### 改完插件代码没生效

发 `/reload <插件id>`，或在面板「插件」页点重载。不用重启整个进程。

**注意**：`reload` 会重新 `import` 模块，模块顶层变量会重置。
需要跨重载保留的数据必须放 `ctx.storage`。

### 插件配置在哪改

`config/bots/<机器人id>/plugins/<插件id>.json`。只有插件声明了 `config` 默认值才会生成这个文件。

改完 `/reload <插件id>` 生效。详见 [插件开发规范.md](插件开发规范.md) §5.7。

## 统计

### 统计页显示「统计不可用」

面板「统计」页提示 **当前 Node 不支持内置 SQLite（需要 22.5 以上）**。

统计用的是 Node 自带的 `node:sqlite`，不装任何第三方包。低于 22.5 的 Node
没有这个模块，框架就自动降级成「不统计」——其它功能完全不受影响。

升级 Node 到 22.5+ 重启即可，历史数据从升级那一刻开始记（之前没记就补不回来）。

### 统计里为什么没有消息正文

**有意为之。** 表结构里只有时间、会话 id、用户 id、是否命令、命令名。
正文属于用户隐私，落库只会让人不敢用这个机器人。

想确认的话可以直接看库：

```bash
sqlite3 data/bots/main/stats.db ".schema messages"
```

### 统计数字不准 / 少了消息

两种可能：

1. **写入是缓冲的**，最多延迟 1 秒。面板刷新一下就有了。
2. **被清理了**：`stats.retentionDays` 默认 90 天，超出的明细由清理服务删掉。
   成员档案不清——「很久没来」这个信息本身就有用。

## 插件相关（补充）

### 改了插件代码没生效

0.5.7 起默认开启热重载：存盘后 **2 秒左右**自动重载，日志里会有一行
`[plugin-watch] [main] 插件 xxx 已热重载`。

没生效的话依次看：

| 现象 | 原因 |
|---|---|
| 日志完全没有 plugin-watch | `config/bot.json` 里 `plugins.hotReload` 被设成 `false` 了 |
| 有「待确认」但一直不重载 | 文件还在被写（大文件分片保存），等它写完 |
| 重载了但行为没变 | 插件把状态存在模块顶层变量里了——重载会重建模块，状态该放 `ctx.storage` |
| 改的是 `plugin.json` | 外部插件的配置改动也会触发重载，但如果改坏了 `plugin.json` 会加载失败，看插件日志 |
| 每 2 秒重载一次，停不下来 | 插件在往**自己目录**写文件（缓存/数据库/日志）。框架会在 30 秒内重载 3 次后熔断 60 秒并提示，根治办法是把运行时数据挪到 `ctx.storage` |

不想用热重载就设 `plugins.hotReload: false`，改完在面板点「重载」。

### 插件报「要求框架 xxx，当前是 yyy」

插件在元数据里声明了 `frameworkVersion`，当前框架不满足，**加载前就被拒绝了**。

两条路：

1. 升级框架（面板「概览 → 检查更新」）
2. 确认插件其实不需要那么新的版本 → 改插件里的 `frameworkVersion`，
   或者临时在 `config/bot.json` 里设 `plugins.ignoreFrameworkVersion: true` 硬跑

### 插件加的面板页打开是空白

先看标签在不在：

- **标签都没有** → 插件没注册成功，看日志里有没有 `注册了面板页面`；
  也可能是插件加载失败（面板「插件」页会显示错误原因）
- **有标签但空白** → 页面里的 `fetch` 失败了。检查是不是用了相对路径
  `/api/...`（正确）还是写成了绝对地址（会跨域）
- 插件被禁用或卸载后标签会自动消失，刷新一下面板

## 下载与更新失败

### 插件市场一直转圈 / 安装插件卡住 / 检查更新报「连不上 GitHub」

国内直连 `github.com` 和 `raw.githubusercontent.com` 经常被干扰，表现就是：

- 打开插件市场一直「获取中…」，最后提示超时
- 安装插件下载到一半断掉
- 概览页点「检查更新」报 `连不上 GitHub`

**换下载源就行**，不用改任何代码：

1. 面板「插件」→「插件市场」
2. 看右上角 **下载源**，点旁边的 **测速**（并发打一遍，6 秒内出结果）
3. 按测速结果选一个能用的；选 `auto` 则直连失败时自动切 Gitee 镜像

只有两个真实来源：GitHub 官方和作者维护的 Gitee 镜像
（`gitee.com/tdcq9594/qq-bot-roost` 和 `qq-bot-roost-plugins`，内容与 GitHub
逐字节相同）。**所以别背固定答案，点测速按自己网络选**。

### 想用自己搭的代理

下载源选「自定义前缀」，填你的代理地址即可，只填域名也行：

```
https://my-proxy.example/
```

最终请求会是 `https://my-proxy.example/https://github.com/...`，
和 ghfast 那类公共代理一个格式。自建方案见
[hunshcn/gh-proxy](https://github.com/hunshcn/gh-proxy)。

### 改了下载源，配置存在哪

`config/bot.json` 的 `network` 段。也可以直接改文件再重启：

```jsonc
"network": { "mirror": "gitee" }
```

### 为什么没内置「自动选最快的」

自动选最快意味着**每次请求前先测速**，反而更慢，而且测速本身也会失败。
所以默认是 `auto`（直连优先、失败切 Gitee、记住成功的那个 10 分钟），
要精确就手动点一次测速。

---

### 插件加载失败了，怎么知道是哪一行

面板「插件」页的卡片上会显示一行错误摘要，下面有 **查看堆栈**，点开就是完整的
调用栈（带文件名和行号）。日志里也记了同样的堆栈。

常见的第一行：

| 报错 | 多半是 |
|---|---|
| `Cannot read properties of undefined (reading 'xxx')` | `ctx.xxx` 拼错，或用了当前框架没有的方法 |
| `Cannot use import statement outside a module` | 文件是 CommonJS 写法，插件必须是 ESM（`export default`） |
| `The requested module does not provide an export named` | 导入了不存在的名字，或者 `export default` 写成了 `module.exports` |
| `Unexpected token` | 语法错，堆栈第一行的行号就是出错位置 |

## 数据与备份

### 数据都在哪

| 目录 | 内容 | 备份建议 |
|------|------|----------|
| `config/` | 机器人配置 + 插件配置 | **要备份**（含 AppSecret，注意保管） |
| `data/` | 群档案、权限、额度、插件存档 | **要备份**（丢了等于重置玩家数据） |
| `logs/` | 日志 | 不用备份，会自动轮转覆盖 |
| `plugins/<id>/.venv` | 插件依赖 | 不用备份，可重建 |

**配置和存档分开放**就是为了备份时能分开搬：带走 `config/` 就是带走全部设置，
带走 `data/` 就是带走全部存档。

### 想换一个机器人（换 AppID）

改 `config/bot.json` 的 `appId` / `appSecret`，重启。

**注意**：openid 是**每个机器人独立**的。换机器人后，原来记录的群 openid、
用户 openid 全部失效，权限和群档案要重新配。

### 想重置所有数据

停掉程序，删掉 `data/` 目录，重启。配置不受影响。
