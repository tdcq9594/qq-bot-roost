# 常见问题

按「现象 → 原因 → 怎么查」组织。查不到答案时，先看 `logs/bot.log` 最后 50 行。

---

## 启动阶段

### 提示「已经有一个实例在跑（PID xxx）」

同一个 AppID 不能同时连两次。两个进程连同一个机器人，服务端会判定冲突、互相踢下线
（关闭码 **4902**），表现是机器人反复掉线、消息时有时无——而且你很难意识到是自己开了两个窗口。

处理方式：

```bash
# Windows：结束那个进程
taskkill /PID <提示里的PID> /F
# 或者直接关掉那个命令行窗口
```

如果确认要同时跑（不推荐，两个实例会抢消息），加 `--force`。

**为什么不做成一刀切禁止多开**：不同 AppID 跑多个机器人是合法需求，
锁的粒度是「AppID」而不是「进程」。真正的多机器人支持见
[架构说明](架构说明.md)。

### 双击 start.bat 没反应 / 窗口一闪就关

先确认一件事：**这台机器装 Node.js 了吗**。本项目不是免安装的独立程序，
`start.bat` 只是帮你调用 `node`，Node 本身必须装在系统里。

```bash
where node     # 有输出才算装了
node -v        # 需要 v22 以上
```

如果 `where node` 没输出，去 <https://nodejs.org/> 装 LTS 版本，**安装时勾选 Add to PATH**，
装完关掉所有命令行窗口重新开（PATH 是启动时读取的）。

如果已经装了但不在 PATH 里，在 `bot/` 目录下建一个 `node-path.txt`，写一行完整路径：

```
C:\Program Files\nodejs\node.exe
```

`start.bat` 会按这个顺序找 node：系统 PATH → 环境变量 `NODE_EXE` → `node-path.txt` →
同目录 `node\node.exe`（便携版）。

> 另一个历史坑：`.bat` 文件如果是 LF 换行，`cmd.exe` 解析带括号的多行块会失败，
> 表现就是双击毫无反应。仓库里已加 `.gitattributes` 强制 `*.bat` 用 CRLF，防止再被改回去。

### 启动就报「需要 Node.js 22 或更高版本」

用到了 Node 22 才有的内置全局 `WebSocket`，低版本跑不起来。

```bash
node -v            # 确认版本
```

去 <https://nodejs.org/> 装一个 LTS 版本即可，**不需要 `npm install`**。

### 启动后没有输出「凭证有效」

| 现象 | 原因 |
|------|------|
| `4014 intents 无权限` | 没开通群聊能力，或 `intents` 填错 |
| `10004 机器人不存在` | AppID 错了 |
| `凭证验证失败` | AppSecret 错了，或复制时带了空格 |

去 <https://q.qq.com> → 你的机器人 → 「功能配置」确认**群聊**能力已开通。
这是最容易漏的一步，不开通连不上。

### 提示「根目录还留着旧的 config.json」

旧版配置在根目录，已经迁移到 `config/bot.json`。确认新配置能正常跑之后，可以删掉旧文件。
**迁移不会自动删旧文件**——里面有 AppSecret，留着当后路。

## 收不到消息

按顺序排查，大多数问题在前两步。

### 1. 机器人有没有被 @

官方群聊的默认规则是**必须 @ 机器人才推送消息**。不 @ 时平台压根不会发事件过来。

先让群里的人 @机器人 发一句 `/ping`。

### 2. 这个群在沙箱配置里吗

**开发中的机器人只收「沙箱群」的消息**。去开放平台把这个群加进沙箱列表。

### 3. 机器人是运行期间被拉进群的吗

`GROUP_ADD_ROBOT` 事件只在**在线时**才收得到。离线期间入群，这个事件会永久丢失。

### 4. 看事件统计

面板「概览 → 事件统计」：

| 显示 | 含义 |
|------|------|
| 一条都没有 | 平台压根没推事件，问题在开放平台配置 |
| 有事件但没有 `GROUP_MESSAGE_CREATE` | 收到的是系统事件，消息事件没开通 |
| 有 `GROUP_MESSAGE_CREATE` 但没回复 | 问题在本程序，看日志有没有报错 |

### 5. 面板里看不到群？

**官方没有「查询机器人所在群列表」的接口**，群只能靠事件被动发现：

| 事件 | 触发条件 |
|------|----------|
| `GROUP_ADD_ROBOT` | 机器人在**运行期间**被拉进群 |
| `GROUP_AT_MESSAGE_CREATE` / `GROUP_MESSAGE_CREATE` | 有人在群里 **@机器人** 说话 |

已知群 openid 时，可以在面板「群组」页底部**手动登记**。

## 发不出消息

### 提示「超过 5 分钟被动回复窗口」

被动回复必须在收到消息后 5 分钟内发出。内核会在 4 分 45 秒时自动降级为主动消息，
所以正常情况下你不会看到这个错误——除非**主动消息额度也用完了**。

### 提示「今天这个会话的主动消息额度已用完」

官方限制主动消息**每会话每天 20 条**（默认值，可配）。

解决办法：等用户 @ 一次机器人，就能继续用被动回复。主动额度每天重置。

查看当前用了多少：群里发 `/status`，或看 `data/bots/<机器人id>/quota.json`。

### 机器人显示离线

WebSocket 断了。面板「概览」页点「重连」，或看日志里的关闭码：

| 关闭码 | 含义 |
|--------|------|
| `4013` | intents 参数无效 |
| `4014` | intents 无权限（多半是没开通群聊能力） |
| `4902` | 同一机器人有多个连接在抢，关掉多余的实例 |

## 面板打不开

### 端口被占用

**新版会自动顺延**：15207 被占就试 15208、15209……实际地址看启动日志那行：

```
INFO [webui] 可视化面板: http://127.0.0.1:15208/
```

如果 20 个端口都占了（`webui.portTries` 可调），会提示面板未启动。
这时先找残留进程：

```bash
# Windows
netstat -ano | findstr 15207
# 拿到 PID 后
taskkill /PID <pid> /F
```

### 浏览器没自动打开

- 命令行加了 `--no-open`？
- `config/bot.json` 的 `webui.openBrowser` 是不是 `false`？
- 手动访问日志里那个地址即可。

### 打开是空白页

前端是原生 JS，没有构建步骤。检查是不是被浏览器插件拦了，或试试无痕窗口。
按 F12 看 Console 有没有报错。

## 权限相关

### 我发了 /claim 但没反应

| 原因 | 解决 |
|------|------|
| 已经有主人了 | `/claim` 只在 `owners` 为空时可用。改 `config/bot.json` 的 `owners` |
| 认领码不对 | 看启动日志那行「认领码: XXXXXX」，面板「日志」页也能看到 |
| 认领码过期 | 每次重启会重新生成，用最新的 |

### 我是群主，为什么没有管理权限

群主是靠消息报文里的 `member_role = owner` 识别的，**只有发过言才能识别**。
先发一条消息（哪怕 `/ping`），系统就会记下来。

如果还是不行，用 `/whoami` 拿到自己的 openid，让主人执行：

```
/admin set <你的openid> 1 group:<群openid>
```

### 为什么不能给自己提权

设计如此。规则是**只能授予数字更大的等级**，也就是只能给比自己权限低的人授权。
`0`（主人）只能改配置文件或认领，命令无法授予。

详见 [权限模型.md](权限模型.md)。

## 插件相关

### 插件加载失败

面板「插件」页会显示错误原因，`logs/bots/<机器人id>/plugins/<id>.log` 有详细日志。

常见原因：

| 现象 | 原因 |
|------|------|
| `既没有 plugin.json 也没有 index.js` | 目录结构不对，参考 `plugins/echo/` |
| `命令 "xxx" 已被插件 yyy 注册` | 命令名冲突，改名 |
| `默认导出必须是 { id, setup(ctx) }` | `index.js` 导出格式不对 |
| Python 插件起不来 | 系统没有 Python，或依赖装失败（日志里会有 pip 原始报错） |

### 自动装依赖很慢 / 失败

首次加载带 `requirements.txt` 的插件会建 `.venv` 并 pip install，慢是正常的。
装完之后哈希记在 `.deps.json`，下次不再装。

装失败时日志里会给出可手动执行的命令，照着跑一遍即可。

想彻底关掉自动安装：`config/bot.json` 里 `plugins.autoInstallDeps = false`。

### 改完插件代码没生效

发 `/reload <插件id>`，或在面板「插件」页点重载。不用重启整个进程。

**注意**：`reload` 会重新 `import` 模块，模块顶层变量会重置。
需要跨重载保留的数据必须放 `ctx.storage`。

### 插件配置在哪改

`config/bots/<机器人id>/plugins/<插件id>.json`。只有插件声明了 `config` 默认值才会生成这个文件。

改完 `/reload <插件id>` 生效。详见 [插件开发规范.md](插件开发规范.md) §5.7。

## 数据与备份

### 数据都在哪

| 目录 | 内容 | 备份建议 |
|------|------|----------|
| `config/` | 机器人配置 + 插件配置 | **要备份**（含 AppSecret，注意保管） |
| `data/` | 群档案、权限、额度、插件存档 | **要备份**（丢了等于重置玩家数据） |
| `logs/` | 日志 | 不用备份，会自动轮转覆盖 |
| `plugins/<id>/.venv` | 插件依赖 | 不用备份，可重建 |

**配置和存档分开放**就是为了备份时能分开搬：带走 `config/` 就是带走全部设置，
带走 `data/` 就是带走全部存档。

### 想换一个机器人（换 AppID）

改 `config/bot.json` 的 `appId` / `appSecret`，重启。

**注意**：openid 是**每个机器人独立**的。换机器人后，原来记录的群 openid、
用户 openid 全部失效，权限和群档案要重新配。

### 想重置所有数据

停掉程序，删掉 `data/` 目录，重启。配置不受影响。

## 开发调试

### 没有凭证也想调插件

```bash
node src/main.js --mock          # 命令行发假消息
node src/main.js --mock --serve  # 只开面板，调界面用
```

mock 模式支持：
- 直接输入文本 = 模拟一条群 @ 消息
- `!as <openid>` 切换发送者（测多级权限）
- `!addbot <群openid> <邀请人openid>` 模拟入群
- `!delbot <群openid>` 模拟被移出群

认领码固定是 `TEST01`，方便自动化测试。

### 怎么跑自检

```bash
npm test
```

31 项，覆盖出站调度、多轮会话、中间件、插件配置、浏览器命令。
