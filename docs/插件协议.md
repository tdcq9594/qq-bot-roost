# 外部插件协议 v1

> 用**任意语言**写插件：Python、Node、Go、Rust、C#…只要能读标准输入、写标准输出。

---

## 一、两种插件，按需选

| | 内建插件 | 外部插件 |
|---|---|---|
| 识别方式 | 目录下有 `index.js` | 目录下有 `plugin.json` |
| 语言 | 只能 JavaScript（ESM） | **任意语言** |
| 运行位置 | 主进程内 | 独立子进程 |
| 单条开销 | ~0.13 ms | ~0.4 ms（多一次序列化往返） |
| 崩溃影响 | **拖垮整个机器人** | 只影响自己，可自动重启 |
| 适合 | 简单逻辑、追求极致性能 | 复杂业务、非 JS 语言、需要隔离 |

两者可以混用。默认建议：**能用外部插件就用外部**，隔离性更重要。

---

## 二、协议速查

传输方式：子进程的 `stdin` / `stdout`，**一行一个 JSON**（NDJSON）。

### 核心 → 插件

| 消息 | 何时发 | 插件要不要回 |
|------|--------|--------------|
| `{"t":"init", ...}` | 进程启动后立刻 | 必须回 `ready` |
| `{"t":"msg","seq":1,"msg":{...}}` | 有消息要处理 | 必须回 `handled` |
| `{"t":"shutdown"}` | 准备退出 | 应尽快退出进程 |

### 插件 → 核心

| 消息 | 作用 |
|------|------|
| `{"t":"ready","commands":[...],"menus":[...],"levels":[...],"listen":[...]}` | 声明能力 |
| `{"t":"reply","seq":1,"text":"..."}` | 被动回复（带 msg_id，5 分钟内有效） |
| `{"t":"reply","seq":1,"image":"https://..."}` | 回复图片 |
| `{"t":"push","seq":1,"text":"..."}` | 主动推送（有频次限制） |
| `{"t":"handled","seq":1}` | 这条消息处理完了 |
| `{"t":"log","level":"info","msg":"..."}` | 写进核心日志 |
| `{"t":"error","msg":"..."}` | 报错，会以 ERROR 级别记录 |

## 三、时序

```
核心                          插件进程
 │                              │
 ├── spawn ────────────────────▶│
 ├── {"t":"init", levels:{base:10}} ─▶│
 │◀── {"t":"ready", commands:[...]} ──┤
 │                              │
 ├── {"t":"msg","seq":1,...} ──▶│
 │◀── {"t":"reply","seq":1,...} ─────┤
 │◀── {"t":"handled","seq":1} ───────┤
 │                              │
 ├── {"t":"shutdown"} ─────────▶│
 │◀── (进程退出) ────────────────┤
```

## 四、消息字段

`init` 下发的 `levels` 是你这个插件的**等级号段**（主程序按插件 id 排序分配，重启不变）：

```json
{"t":"init","protocol":1,"id":"my-plugin","config":{},
 "levels":{"base":30,"end":39},
 "coreLevels":{"owner":0,"admin":1,"manager":2,"helper":3},
 "prefix":"/"}
```

`msg` 里的对象：

| 字段 | 说明 |
|------|------|
| `seq` | 序号，回复时必须带上 |
| `id` | 消息 id |
| `kind` | `group` / `c2c` / `guild` / `dm` |
| `group` | 群 openid（私聊为空） |
| `user` | 发送者 openid |
| `name` | 发送者昵称 |
| `content` | 去掉 @机器人 和命令前缀后的正文 |
| `raw` | 原始正文（含 @ 前缀） |
| `command` | 命中的命令名（不是命令则为空） |
| `args` | 参数数组 |
| `mentioned` | 是否 @ 了机器人 |
| `isCommand` | 是否以命令前缀开头 |
| `level` | **你这条消息的权限等级**（数字越小越高，9999 = 无权限） |
| `scope` | 当前作用域，如 `group:xxx` |

## 五、最小示例

### Python

`plugin.json`：

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "description": "一句话说明",
  "runtime": "python",
  "entry": "main.py",
  "protocol": 1
}
```

`main.py`：

```python
import sys, json

def send(o):
    sys.stdout.write(json.dumps(o, ensure_ascii=False) + "\n")
    sys.stdout.flush()

for line in sys.stdin:
    if not line.strip():
        continue
    p = json.loads(line)

    if p["t"] == "init":
        send({"t": "ready",
              "commands": [{"name": "hello", "pattern": "hello [名字]", "desc": "打个招呼"}]})

    elif p["t"] == "msg":
        seq = p["seq"]
        m = p["msg"]
        if m["command"] == "hello":
            who = m["args"][0] if m["args"] else m["name"]
            send({"t": "reply", "seq": seq, "text": f"你好，{who}！"})
        send({"t": "handled", "seq": seq})   # 必须回

    elif p["t"] == "shutdown":
        break
```

### Node.js

```js
// plugin.json: { "runtime": "node", "entry": "main.js" }
const readline = require('node:readline');

const send = (o) => process.stdout.write(JSON.stringify(o) + '\n');

readline.createInterface({ input: process.stdin }).on('line', (line) => {
  if (!line.trim()) return;
  const p = JSON.parse(line);

  if (p.t === 'init') {
    send({ t: 'ready', commands: [{ name: 'hello', pattern: 'hello [名字]', desc: '打招呼' }] });
  } else if (p.t === 'msg') {
    const { seq, msg } = p;
    if (msg.command === 'hello') {
      send({ t: 'reply', seq, text: `你好，${msg.args[0] || msg.name}！` });
    }
    send({ t: 'handled', seq });
  } else if (p.t === 'shutdown') {
    process.exit(0);
  }
});
```

### Go

```go
// plugin.json: { "command": ["my-plugin.exe"] }   —— 先 go build 出可执行文件
package main

import (
	"bufio"
	"encoding/json"
	"fmt"
	"os"
)

func send(o map[string]any) {
	b, _ := json.Marshal(o)
	fmt.Println(string(b)) // 注意：Println 自带换行
}

func main() {
	sc := bufio.NewScanner(os.Stdin)
	sc.Buffer(make([]byte, 1<<20), 1<<20)
	for sc.Scan() {
		var p map[string]any
		if json.Unmarshal(sc.Bytes(), &p) != nil {
			continue
		}
		switch p["t"] {
		case "init":
			send(map[string]any{
				"t": "ready",
				"commands": []map[string]any{
					{"name": "hello", "pattern": "hello [名字]", "desc": "打招呼"},
				},
			})
		case "msg":
			seq := p["seq"].(float64)
			m := p["msg"].(map[string]any)
			if m["command"] == "hello" {
				send(map[string]any{"t": "reply", "seq": seq, "text": "你好！"})
			}
			send(map[string]any{"t": "handled", "seq": seq})
		case "shutdown":
			return
		}
	}
}
```

## 六、声明能力（`ready`）

```json
{
  "t": "ready",

  "commands": [
    { "name": "roll", "pattern": "roll [面数]", "desc": "掷骰子", "admin": false }
  ],

  "menus": [
    { "title": "玩法", "items": [{ "text": "掷骰子", "desc": "群里直接说也能触发" }] }
  ],

  "levels": [
    { "name": "管理员", "level": 30 },
    { "name": "玩家",   "level": 32 }
  ],

  "listen": ["message"]
}
```

| 字段 | 说明 |
|------|------|
| `commands` | 注册命令。`pattern` 第一个词是命令名，`<必填>` `[可选]` 会被自动校验 |
| `menus` | 额外菜单分组（命令会自动进「指令」组，这里放非命令玩法） |
| `levels` | 你的插件自定义的等级，会自动展示在 `/help 插件id` 里 |
| `listen` | `["message"]` 表示要接收非命令消息；不填则只收命令 |

> **等级号段**：`init` 给你的 `levels.base` 是起点，你只能在这个区间内定义等级。
> 例：base=30，可以定义 30/31/32…39。数字越小权限越高。

## 七、并发与超时

**并发模型**

- 不同会话（群 / 私聊）**并行**处理
- 同一会话内**串行**，保证游戏状态不会被打乱

所以你不需要自己加锁。但如果插件内部有多线程，注意共享状态的读写。

**超时**

| 情况 | 默认 | 结果 |
|------|------|------|
| 启动后不回 `ready` | 10s | 判定加载失败 |
| 单条消息不结束 | 15s | 记 warn，视为无回应 |
| 发出 reply 后没有后续 | 0.4s | 自动认为这条处理完了 |

**崩溃**

进程退出后核心会自动重启，**一分钟内最多 3 次**。超过就停止重试，面板标红。
`plugin.json` 里可以写 `"autoRestart": false` 关掉。

## 八、调试

| 做法 | 说明 |
|------|------|
| 调试输出写 **stderr** | 核心会当成插件日志收走，不会破坏协议 |
| 用 `{"t":"log","level":"debug","msg":"..."}` | 直接进核心日志面板 |
| `node src/main.js --mock` | 不连 QQ，本地喂消息测插件 |
| 面板「插件」页 | 看进程状态、pid、加载错误 |

**千万别把调试信息打到 stdout**——那是协议通道，一行脏数据会被当成非法消息。

## 九、常见坑

| 现象 | 原因 |
|------|------|
| 插件加载失败，日志说「没有返回 ready」 | 忘了 `sys.stdout.flush()` / `process.stdout.write` 后没换行 |
| 命令能用但没回复 | 忘了发 `handled`，或 `seq` 对不上 |
| 中文乱码 | 没设 UTF-8。Python 设 `PYTHONIOENCODING=utf-8`（核心已默认加） |
| 改代码不生效 | 外部插件要 `/reload <id>`，会重启进程 |
| 进程反复重启 | 看 stderr，通常是依赖没装或入口路径错 |
| 面板显示「外部 · python」但没命令 | `ready` 里的 `commands` 为空 |

## 十、目录结构

```
plugins/my-plugin/
├── plugin.json        必需，元信息
├── main.py            入口（由 runtime/entry 决定）
├── requirements.txt   可选，Python 依赖（首次加载自动装进 .venv）
├── package.json       可选，Node 依赖（首次加载自动 npm install）
└── ...                其他文件随意
```

`plugin.json` 完整字段：

```json
{
  "id": "my-plugin",          // 必需，与文件夹名一致
  "name": "我的插件",
  "version": "1.0.0",
  "description": "一句话说明",
  "runtime": "python",        // python / node / go / exec
  "entry": "main.py",         // 入口文件
  "command": ["python", "main.py"],  // 可选，直接指定完整命令（优先级更高）
  // runtime: "go" 会用  跑源码；
  // go 可执行文件路径由全局配置 plugins.goBin 指定（或 PATH 里的 go / GO_BIN 环境变量）
  "env": { "FOO": "bar" },    // 可选，附加环境变量
  "autoRestart": true,        // 可选，崩溃是否自动重启
  "config": {                 // 可选，默认配置
    "welcome": "欢迎",
    "maxRetry": 3
  },
  "protocol": 1
}
```

## 十一、配置、日志、数据

| 内容 | 位置 | 插件怎么拿到 |
|------|------|--------------|
| 配置 | `config/bots/<机器人id>/plugins/<id>.json` | `init` 消息里的 `config` 字段 |
| 日志 | `logs/bots/<机器人id>/plugins/<id>.log` | 发 `{"t":"log"}` 协议消息；stderr 也会自动收进去 |
| 存档 | `data/bots/<机器人id>/plugins/<id>/` | `init` 消息里的 `dataDir`，一个专属目录 |

### 存档：用 `dataDir`

外部插件没有 `ctx.storage` 那种读写接口，但 `init` 会下发一个**专属目录**：

```json
{
  "t": "init",
  "dataDir": "C:\\...\\data\\bots\\main\\plugins\\my-plugin"
}
```

这个目录：

- 按机器人隔离（`data/bots/<机器人id>/`），不同机器人互不干扰
- 核心在 `init` 之前已经帮你 `mkdir` 好了，收到就能直接写
- 格式随你：JSON、SQLite、二进制都行

```python
DATA_DIR = None

def on_init(payload):
    global DATA_DIR
    DATA_DIR = payload.get("dataDir")

def load():
    path = os.path.join(DATA_DIR, "players.json")
    return json.load(open(path, encoding="utf-8")) if os.path.exists(path) else {}
```

**写文件建议先写 `.tmp` 再 `os.replace()` 原子替换**，避免进程被杀时留下半个坏文件。
参考 `plugins/kun-py/main.py`。

> 为什么不像内建插件那样给一套 `storage.get/set`：外部插件语言各异，
> 有人要用 SQLite、有人要存二进制。给一个目录比强加一种格式更自由。

### 配置怎么下发

`init` 消息里带的是**合并后**的配置：

```json
{
  "t": "init",
  "protocol": 1,
  "id": "my-plugin",
  "config": { "welcome": "欢迎", "maxRetry": 3 },
  "levels": { "base": 10, "end": 19 },
  "coreLevels": { "owner": 0, "admin": 1, "manager": 2, "helper": 3 },
  "prefix": "/"
}
```

行为与内建插件一致：

- 首次加载按 `plugin.json` 里的 `config` 生成 `config/bots/<机器人id>/plugins/<id>.json`
- 用户改了这个文件，下次启动合并后下发
- 插件升级在 `config` 里加了新项，会自动补进文件

> **注意**：配置在 `init` 时一次性下发，运行中改文件不会热更新，
> 要 `/reload <插件id>` 才会重新读取。

### 依赖自动安装

放了 `requirements.txt`（Python）或 `package.json`（Node），**首次加载自动安装**：

```
plugins/my-plugin/
├── plugin.json
├── main.py
└── requirements.txt     ← 写 requests 之类
```

内核会：

1. 建 `plugins/my-plugin/.venv`
2. 用 venv 里的 pip 装 `requirements.txt`
3. 之后一直用 `.venv` 里的解释器启动这个插件

**不会**碰系统 Python，也不会影响别的插件。依赖文件哈希存在 `.deps.json`，
内容没变就跳过，不会每次启动都联网。

装失败时日志里会贴出 pip 的原始报错和可手动执行的命令。
想关掉：`config/bot.json` 里 `plugins.autoInstallDeps = false`。

### 完整目录示例

```
bot/
├── config/
│   ├── bot.json                    全局配置
│   └── bots/
│       └── main/                   机器人 A
│           └── plugins/
│               └── my-plugin.json  这个插件的配置（自动生成）
├── logs/
│   ├── bot.log                     全局日志
│   └── bots/main/
│       ├── bot.log                 这个机器人的日志
│       └── plugins/
│           └── my-plugin.log       只有这个插件的
├── data/
│   └── bots/main/
│       └── plugins/                插件存档目录（按机器人隔离）
└── plugins/
    └── my-plugin/                  插件代码 + 它自己的 .venv（全局共享）
```
