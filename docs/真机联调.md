# 真机联调：用小号跟机器人真聊

mock 模式（`node src/main.js --mock`）测的是**插件逻辑**，测不出下面这些只有真网关才有的东西：

| 只有真机才测得出来 | 表现 |
|---|---|
| intents 有没有开 | 网关连得上、日志也正常，但群消息一条都进不来 |
| 被动回复 5 分钟窗口 | 超时之后消息发不出去，报错在日志里 |
| `msg_seq` 递增与 5 次上限 | 同一个 `msg_id` 最多回 5 次（`msg_seq` 1–5），第 6 次报 `40034128` |
| @ 判定与免@粘性 | `mentioned` / `addressed` 的实际取值 |
| 群 openid 映射 | 群档案、权限作用域用的是 `group_openid` 而不是群号 |

要测这些，只能让一个**真的 QQ 账号**在**真的群**里 @ 机器人。

---

## 一、思路：小号走 OneBot，我们只跟 OneBot 说话

```
你的小号 ──登录──> SnowLuma / NapCat / Lagrange.OneBot ──HTTP──> scripts/live-test.mjs
                                                                    │
                                                                    │ 发 "@机器人 /help"
                                                                    ▼
                                                        QQ 群（机器人也在里面）
                                                                    │
                                                          官方 WebSocket 网关
                                                                    ▼
                                                        栖 Roost（你的机器人）
```

小号不直接连 QQ 协议，而是交给现成的 OneBot v11 实现去登录。我们这边只调 OneBot 的
HTTP 接口，所以**换哪个实现都不用改代码**。

| 实现 | 说明 |
|---|---|
| [SnowLuma](https://github.com/wsu2059q/SnowLuma) | TypeScript 运行时，Hook 本地 QQ 客户端；有 WebUI（默认 5099）；支持 OneBot v11 的 WS/HTTP |
| NapCat | 无头 QQ NT，装好就能扫码，OneBot v11 实现最全 |
| Lagrange.OneBot | 纯协议实现，不依赖本地客户端 |
| LLOneBot | LiteLoaderQQNT 插件形态 |

> **风控提示**：用小号跑第三方客户端有被限制的风险，这是所有同类工具的共同问题。
> 建议**专门用一个不重要的号**、只在你自己的测试群里用、不要群发、不要高频。
> 官方协议本身没有这条风险，风险来自「非官方客户端登录」这一步。

## 二、准备（一次性）

### 1. 建一个测试群

自己建个群就行，别用有真人的群——测试消息会打扰别人，而且误触发插件不好收拾。

### 2. 把小号拉进群

### 3. 把机器人拉进群

在 QQ 群里：群设置 → 机器人 → 添加机器人 → 搜你的机器人名字。

### 4. 把这个群加进沙箱配置（最容易漏的一步）

**开发中的机器人只收「沙箱群」的消息。** 机器人还没上线时，光把它拉进群没用——
平台压根不会往这个群推事件。去 [QQ 开放平台](https://q.qq.com/) → 你的机器人 →
开发设置 → 沙箱配置，把这个群加进沙箱群列表。

这是「小号 @ 了但机器人没反应」的头号原因，比 intents 还常见。

> 官方机器人**没有**「查询我在哪些群」的接口，所以群档案只能靠事件被动发现。
> 拉进群之后，面板「群组」页会自己出现这一条（或者用「手动登记群」直接填 openid）。

### 5. 确认 intents

面板「配置」页确认 intents 里有 **群聊与私聊（`1 << 25`）**。这一位没开，网关连得上但群消息永远进不来——这也是体检里最常报的一条。

### 6. 记下机器人的 QQ 号

在群里点机器人头像就能看到。后面填 `botUin` 用。
（也可以先留空，`--check` 会从群成员里猜。）

## 三、起 OneBot 服务

### SnowLuma

1. 下载发行包，Windows 跑 `launcher.bat`
2. 打开 `http://localhost:5099`，用启动日志里的初始密码登录
3. 按引导**接入 QQ 进程**，扫码登录小号
4. 在「连接配置」里开一个 **OneBot v11 HTTP 服务端**，记下端口和 access token

> 注意区分两个端口：`5099` 是 WebUI，**不是** OneBot 接口。填错会得到
> 「返回的不是 JSON」，脚本会直接提示这一点。
>
> SnowLuma 默认会建三个连接，名字很像但方向不同：
>
> | 连接 | 方向 | 默认端口 | 是不是我要连的 |
> |---|---|---|---|
> | `http-default` | **服务端**（别人调它） | **3000** | ✅ 是这个 |
> | `ws-default` | 服务端（WebSocket） | 3001 | 备用 |
> | `httppost-1` | **客户端**（它往外面发事件） | 你填的目标地址 | ❌ 不是 |
>
> 要的是 `http-default` 的 access token。`httppost-1` 是「上报」，配了它只会
> 让 SnowLuma 去 POST 一个地址，连不上它。

### NapCat

WebUI → 网络配置 → 新建 **HTTP 服务器** → 记下端口和 token。

## 四、配置

```bash
npm run live -- --init      # 生成 config/live-test.json
```

```json
{
  "baseUrl": "http://127.0.0.1:3000",
  "token": "",
  "group": 123456789,
  "botUin": 10000001,
  "botName": "栖",
  "prefix": "/",
  "timeoutMs": 15000
}
```

`config/live-test.json` 已经在 `.gitignore` 里（含 token，不能入库）。

也可以用环境变量，适合临时切环境：

```bash
ROOST_ONEBOT_URL=http://127.0.0.1:3000 ROOST_GROUP=123456789 ROOST_BOT_UIN=10000001 npm run live
```

## 五、探活

```bash
npm run live -- --check
```

它会依次确认四件事，缺哪个就直接告诉你：

```
✓ 小号已连上：某某（123456）
✓ 小号在 3 个群里
✓ 测试群：栖 测试群（123456789）
✓ 机器人 uin 10000001 在群里：栖
✓ 能读群消息（最近 5 条）
```

没填 `group` 时会把小号所在的群列出来让你挑；没填 `botUin` 时会从群成员里
按「机器人 / bot / 你填的 botName」猜，猜不到就提示你去点头像看。

## 六、跑起来

### 场景套件

```bash
npm run live
```

```
不 @ 的普通消息，不该回复 … ✓ 安静，符合预期
@ 机器人 /help … ✓ 回了 1 条
@ 机器人 未知命令 … ✓ 没有「/roost_live_test_nope」这个命令，发 /help 看看
连发两条 @ 命令 … ✓ 2 条回复
```

四条各自在验证什么：

| 场景 | 通过意味着 |
|---|---|
| 不 @ 的普通消息 | 机器人不会对群里每句话插话；intent 与 `addressed` 判定正常 |
| @ + `/help` | 整条链路通了：网关 → 事件 → 插件 → 被动回复 |
| @ + 未知命令 | 收到不认识的东西有回应，而不是静默 |
| 连发两条 | `msg_seq` 处理正确，第二条没被平台拒 |

> **顺序不能换**：第一条必须在任何 @ 之前跑。@ 过一次会开 180 秒免@粘性窗口，
> 那时候不 @ 也会被当成在跟机器人说话，第一条就测不出东西了。

### 交互对话

```bash
npm run live -- --chat
```

```
小号[@]> /help
  ← 📖 帮助：...
小号[@]> 今天吃啥
  （15 秒内没有回复）
小号[@]> :at          # 切换要不要 @
  以后都不 @
小号[无@]> 攻击
  ← ...
```

默认每条都 @ 机器人（官方机器人多数场景要 @）。`:at` 切开关，`:quit` 退出。

### 单发一条（给自动化用）

```bash
npm run live -- --cmd help                 # 等价于 /help
npm run live -- --cmd "roll 6"             # 等价于 /roll 6
npm run live -- --cmd help --expect "帮助"  # 断言，不包含就退出码 1
npm run live -- --send "随便说句话" --no-at
```

`--expect` 命中返回 0，不命中返回 1，可以直接放进脚本里。

> **为什么有 `--cmd` 还有 `--send`**：Git Bash 会把以 `/` 开头的参数当路径转换，
> `--send "/help"` 到脚本里已经变成 `C:/Program Files/Git/help` 了。
> `--cmd` 不带斜杠，由脚本补前缀，最稳。脚本检测到这种转换会直接提示你改用 `--cmd`。
> 在 PowerShell / cmd 里没有这个问题。

## 七、常见失败

| 现象 | 原因 |
|---|---|
| `连不上 OneBot：ECONNREFUSED` | HTTP 服务端没开，或者端口填成了 WebUI 的 |
| `返回的不是 JSON` | 地址写到了 WebUI 端口 / 路径不对 |
| 所有接口都报 `SQLITE_READONLY` | OneBot 实现自己的消息库坏了（SnowLuma 见过）：停掉程序，把 `data/<uin>/messages.db*` 挪走再启动，它会重建 |
| 参数变成 `C:/Program Files/Git/xxx` | Git Bash 把 `/` 开头的参数当路径转了，改用 `--cmd` |
| `--check` 说群不在列表里 | 群号错，或者小号没进群 |
| `@` 了但 `--send` 一直超时 | **群不在沙箱配置里**（最常见）；或 intents 没开群聊；或机器人没进群。看面板「事件」页计数有没有涨——涨了说明收到了、是插件没回；没涨就是平台没推 |
| 回复只来一条就没了 | 机器人确实只回了一条；多条回复有 900ms 静默期，再长就要调 `timeoutMs` |
| `send_group_msg 失败：retcode 1400` | 实现不认消息段数组，脚本会自动退回 CQ 码再试一次 |
| 读不到群消息 | 有的实现要单独开「历史消息」权限 |

## 八、和 mock 的分工

| | mock | 真机 |
|---|---|---|
| 插件逻辑对不对 | ✅ 快，不用登录 | 慢 |
| 网关 / intents | ❌ | ✅ |
| 被动回复窗口、`msg_seq` | ❌ | ✅ |
| 权限、群 openid | 假数据 | ✅ 真实 |
| 自动化回归 | ✅ `npm test` | 半自动，需要小号在线 |

日常改插件用 `npm run test:plugin`，改内核或怀疑是平台行为时再上真机。

> **跑 `npm run e2e` 之前先停掉真机机器人。** e2e 会自己起一个 mock 服务，
> 端口被线上实例占着时会打到真机器人上，表现是一堆
> 「接口不存在」「请求的资源不存在(用户/群已注销)」的假失败。
