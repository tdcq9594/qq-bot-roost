# 配置参考

配置分**两层**，别放错地方：

| 层 | 文件 | 管什么 | 有几份 |
|----|------|--------|--------|
| 全局 | `config/bot.json` | 面板、日志、插件依赖策略 | 1 份 |
| 机器人 | `config/bots/<id>.json` | 连接、权限、限流、出站、启用哪些插件 | 每个机器人 1 份 |

模板在 `config/bot.example.json` 和 `config/bots.example.json`，复制过去改即可。
字段的权威定义在 `src/config.js` 的 `GLOBAL_DEFAULTS` / `BOT_DEFAULTS`。

> **为什么不合成一个文件**：多个机器人共用面板和日志设置，但 AppID、前缀、权限、
> 启用插件各不相同。分开之后，加一个机器人只要多一个文件，不用动全局。

## 全局配置 `config/bot.json`

首次启动自动生成。面板「配置」页改的就是这里。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `logLevel` | string | `"info"` | `debug` / `info` / `warn` / `error`。debug 会把每条事件载荷都打出来 |
| `cooldownHint` | boolean | `true` | 命令冷却时是否回复提示。关掉就静默丢弃 |
| `webui.enabled` | boolean | `true` | 关掉后完全不启动面板 |
| `webui.host` | string | `"127.0.0.1"` | **保持默认**。改成 `0.0.0.0` 必须同时设 `accessKey` |
| `webui.port` | number | `15207` | 被占用会自动顺延 |
| `webui.portTries` | number | `20` | 最多顺延多少个端口 |
| `webui.accessKey` | string | `""` | 面板访问密钥。为空 = 不校验（仅限本机） |
| `webui.openBrowser` | boolean | `true` | 启动后自动开浏览器 |
| `logs.enabled` | boolean | `true` | 关掉后只输出到控制台，不落盘 |
| `logs.maxBytes` | number | `5242880` | 单个日志文件上限（5 MB），超了轮转 |
| `plugins.autoInstallDeps` | boolean | `true` | 插件声明了依赖是否自动安装。不放心就设 `false`，自己审一遍再装 |

## 机器人配置 `config/bots/<id>.json`

文件名就是机器人 id，创建后不要改（数据目录跟着它走）。

### 基本

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `name` | string | 同 id | 面板显示名 |
| `enabled` | boolean | `true` | `false` 就跳过启动，但配置和数据保留 |
| `appId` | string | — | q.qq.com 管理端「开发设置」里取 |
| `appSecret` | string | — | 同上。**这是凭证，不要提交到仓库** |
| `baseUrl` | string | `"https://api.bot.qq.com"` | 一般不用改 |
| `intents` | number | `33554432` | 订阅哪些事件，见下方 |
| `commandPrefix` | string | `"/"` | 命令前缀。每个机器人可以不同 |
| `owners` | string[] | `[]` | 全局主人 openid，拥有最高权限 |

### intents 怎么算

位掩码，把要订阅的类别按位或起来。默认 `33554432` = `1 << 25` = `GROUP_AND_C2C_EVENT`，
群聊 @机器人 + 私聊消息，**够绝大多数群聊场景**。

| 位 | 值 | 类别 | 权限 |
|----|----|------|------|
| 0 | 1 | GUILDS 频道基础 | 默认可用 |
| 1 | 2 | GUILD_MEMBERS 频道成员 | 默认可用 |
| 9 | 512 | GUILD_MESSAGES 频道全量消息 | 需申请，仅私域 |
| 10 | 1024 | GUILD_MESSAGE_REACTIONS 表情表态 | 需申请 |
| 12 | 4096 | DIRECT_MESSAGE 频道私信 | 需申请 |
| 25 | 33554432 | GROUP_AND_C2C_EVENT 群聊与私聊 | 需开通群聊能力 |
| 26 | 67108864 | INTERACTION 互动事件 | 需申请 |
| 27 | 134217728 | MESSAGE_AUDIT 消息审核 | 需申请 |
| 28 | 268435456 | FORUMS_EVENT 论坛事件 | 需申请，仅私域 |
| 29 | 536870912 | AUDIO_ACTION 音频动作 | 需申请 |
| 30 | 1073741824 | PUBLIC_GUILD_MESSAGES 频道 @消息 | 默认可用 |

**勾了没权限的位，WebSocket 鉴权会被拒并断开（关闭码 4014）。**
面板「配置 → 事件订阅」是勾选式的，不用自己算。

### 访问控制

```jsonc
"whitelist": {
  "enabled": false,   // 开启后只响应名单内的群/用户
  "groups": [],       // 群 openid
  "users": []         // 用户 openid
}
```

### 限流与去重

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `rateLimit.enabled` | boolean | `true` | 单会话每分钟最多触发多少次命令 |
| `rateLimit.perChatPerMinute` | number | `30` | 超过就丢弃 |
| `dedupWindowSec` | number | `120` | 同一条消息重复推送的去重窗口（秒） |

### 出站调度 `outbound`

QQ 对机器人发消息有硬限制，这些参数决定怎么在限制内把消息发出去。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `perSec` | number | `4` | 每秒最多发几条。官方上限 5，默认压到 4 留余量 |
| `dailyActive` | number | `20` | 每会话每天主动消息额度 |
| `downgradeToActive` | boolean | `true` | 被动回复窗口过期时，自动降级成主动消息（消耗额度） |

### 多轮对话 `session`

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `stickySec` | number | `180` | 用户 @过机器人后，多少秒内不用再 @ 也能触发 |
| `promptTimeoutSec` | number | `120` | `ctx.prompt()` 等待用户回复的超时 |

### 消息日志

```jsonc
"messageLog": {
  "enabled": true,
  "muteKinds": []     // 不想记的会话类型：group / c2c / guild / dm
}
```

### 启用哪些插件 `plugins`

三态，决定这个机器人加载哪些插件：

| `mode` | 含义 | 新装插件 |
|--------|------|----------|
| `"all"` | 全部启用 | 自动生效 |
| `"include"` | **只启用 `list` 里的**（默认） | 不生效，要手动加 |
| `"exclude"` | 除了 `list` 里的都启用 | 自动生效 |

```jsonc
"plugins": { "mode": "include", "list": ["dice", "echo"] }
```

> 默认 `include` 是有意的：新机器人不该莫名其妙跑起一堆插件。
> 但**从旧版本迁移过来的机器人会被设成 `all`**，免得升级后插件全停。

插件代码是全局共享的（`plugins/` 只有一份），这里只控制「加载不加载」。

### 群管能力 `groupManage`

```jsonc
"groupManage": { "invited": false }
```

官方群管理接口分两档：

| 档位 | 接口 | 要不要这个开关 |
|------|------|----------------|
| 公开 | 禁言（查/设）、撤回群消息、群基本信息、机器人群内状态 | 不要，随时可用 |
| 内邀 | 群成员列表、群成员信息、批量移除（踢人）、群黑名单 | **要** |

内邀那几个只对白名单机器人开放，没申请就调会返回 `11253`。所以默认 `false`：
没申请的机器人不该去调，调了也只是在日志里刷一堆无意义的报错。

去开放平台申请通过后，到面板「配置 → 群管能力」勾上，**立即生效、不用重启**。

## 环境变量

优先级低于配置文件——文件里写了就不看环境变量。只在没写时兜底。

| 变量 | 对应字段 |
|------|----------|
| `QQ_BOT_APPID` | 机器人的 `appId` |
| `QQ_BOT_SECRET` | 机器人的 `appSecret` |
| `QQ_BOT_BASE_URL` | `baseUrl` |
| `QQ_BOT_OWNERS` | `owners`，逗号分隔 |

> 多机器人下环境变量容易串，**建议只用来做临时调试**，正式配置写文件。

## 从旧版本升级

首次启动会自动迁移，顺序是「读旧 → 写新 → 逐字节校验 → 删旧」，任何一步失败就中止，
旧文件不会被破坏。迁移内容：

1. `config/bot.json` 里的连接字段 → `config/bots/main.json`
2. `data/*.json` → `data/bots/main/`
3. `logs/plugins/*.log` → `logs/bots/main/plugins/`
4. `config/plugins/*.json` → `config/bots/main/plugins/`
5. 全局 `config/bot.json` 重写成只剩全局字段
6. 旧文件删除，空目录清掉

迁移只做一次，写 `data/.migrated` 标记防重复执行。

## 常见问题

**改了配置没生效？**
改机器人配置后需要重启对应的机器人。面板「配置」页保存会提示，但网关重连要几秒。

**两个机器人能共用一个 AppID 吗？**
不能。同一个 AppID 双开会互相踢下线（关闭码 4902）。启动时会直接拒绝并给出 PID。

**`config/bots/<id>.json` 删了数据还在吗？**
在。数据在 `data/bots/<id>/`。想删干净用面板的「删除机器人」，它会连数据和日志一起清。

### 收事件方式 `connection`

```jsonc
// 机器人配置 config/bots/<id>.json
"connection": { "mode": "websocket" }
```

| `mode` | 含义 | 适合 |
|--------|------|------|
| `"websocket"` | **默认**。主动连平台的长连接 | 本地 / 内网 / 家用宽带 |
| `"webhook"` | 平台 HTTP 回调推事件 | 公网服务器 / Serverless / 容器 |

两种模式**发消息都走同一个 HTTP API**，插件代码不用改。
区别只在于「事件怎么进来」。

选 webhook 还需要开全局服务：

```jsonc
// 全局配置 config/bot.json
"webhook": {
  "enabled": true,
  "host": "0.0.0.0",
  "port": 15208,
  "path": "/webhook",
  "publicUrl": "https://bot.example.com"   // 对外地址，配了会在启动日志里打印完整回调 URL
}
```

多机器人**共用一个 webhook 端口**，按 `X-Bot-Appid` 请求头（或 `?appid=` 参数）分流。
所以不需要给每个机器人开一个端口。

### Webhook 模式下必须做的三件事

1. **到开放平台填回调地址**：`https://你的域名/webhook`。
   平台会先发一个 `op=13` 验证请求，框架自动用 AppSecret 做 Ed25519 签名回应，通过后才会推事件
2. **配好 HTTPS**：官方只接受 https 回调。用 Nginx / Caddy 反代到 `webhook.port`
3. **确认防火墙放行**：`webhook.port` 要对公网可达（如果反代在同一台机，只需放 80/443）

### 两种模式怎么选

| | WebSocket | Webhook |
|---|---|---|
| 需要公网入口 | 只要出站 | **要入站** |
| 断线重连 | 框架自动 | 平台超时重推 |
| 空闲占用 | 一条长连接 | 不占 |
| 容器按需唤醒 | 不方便 | **合适** |
| 本地防火墙严格 | 友好 | 要开端口 |

本地跑、NAT 后面、不想开端口 → WebSocket。
有公网 IP / 域名、跑在 Serverless 或 K8s 里 → Webhook。
