# AI 对话插件

把大模型接进 QQ：群里 @机器人 说话、私聊直接说，都能对话。
每个会话（每个群、每个私聊）各自一份上下文，互不串台。

移植自腾讯官方的 [dsh-qqbot](https://github.com/tencent-connect/dsh-qqbot)，
但架构不同——那个是 DSH 的插件、靠 DSH 的 agent loop 调模型；
我们是独立框架，直接打 OpenAI 兼容的 `/chat/completions`。
**不绑定任何一家**：DeepSeek、Kimi、通义、本地 Ollama 都只要改 `baseUrl`。

---

## 快速开始

### 1. 拿一个 API Key

以 DeepSeek 为例：去 [platform.deepseek.com](https://platform.deepseek.com)
注册、充值、创建 API Key（`sk-` 开头）。

### 2. 填进面板

面板「插件 → AI 对话 → 设置」，只填两项就够：

| 字段 | 填什么 |
|---|---|
| `apiKey` | 你的 Key |
| `baseUrl` | `https://api.deepseek.com`（默认就是，不用改） |

不想手输地址和模型名，点面板顶部的**快速填入**——DeepSeek / Kimi / 通义 /
智谱 / 硅基流动 / 火山方舟 / 本地 Ollama 都是一键填好。
只填表不保存，填完检查一下再点保存。

保存后**不用重启**——配置是每轮对话现读的。

### 3. 在群里试

```
@机器人 /ai 你好
```

## 用哪些模型

改 `model` 字段，或者直接发 `/模型` 命令（只影响当前会话）：

| 服务商 | baseUrl | model 举例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat`（日常）、`deepseek-reasoner`（推理） |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |

只要对方兼容 OpenAI 的 `/chat/completions` 就能用。
`baseUrl` 末尾的 `/` 会自动去掉，不用纠结。

---

## 指令

| 指令 | 作用 |
|---|---|
| `/新会话` | 清空当前会话的上下文，重新开始（别名 `/清空` `/重置`） |
| `/模型` | 看当前模型；`/模型 deepseek-reasoner` 换一个（只影响这个会话） |
| `/停止` | 中止正在生成的回答 |
| `/对话状态` | 看这个会话聊了几轮、存了几条、还有多久闲置清空 |
| `/AI帮助` | 用法速查 |

## 怎么跟它说话

**格式是固定的：`/ai` + 你的问题。**

群里：

```
@机器人 /ai 用一句话解释什么是递归
```

私聊：

```
/ai 用一句话解释什么是递归
```

**指令本身不会发给 AI。** 上面那句，模型收到的是「用一句话解释什么是递归」，
不含 `/ai`——否则模型会以为你在让它执行命令，回答容易跑偏。

### 为什么不做「@ 了随便说就接」

试过，问题比好处多：

| 做法 | 问题 |
|---|---|
| @ 一下就接话 | 群里 @ 往往只是提到机器人，不是要它回答，每句都接很吵 |
| @ 过一次后几分钟内不用再 @ | 更糟——那几分钟里群里聊什么都被它吃掉 |
| 私聊直接说 | 这个还行，但和群里的规则不一致，用户要记两套 |

有个明确的 `/ai`，用户清楚自己什么时候在跟 AI 说话，也不会误触发。
代价是每次多打三个字符，值得。

### 上下文还是连着的

连着发几条 `/ai`，它会记得前面聊过什么（同一个会话内）。聊偏了就 `/新会话`。

## 配置项

### 基本

| 字段 | 默认 | 说明 |
|---|---|---|
| `apiKey` | 空 | 必填，留空时只提示怎么配 |
| `baseUrl` | `https://api.deepseek.com` | 接口地址，OpenAI 兼容即可 |
| `model` | `deepseek-chat` | 默认模型 |
| `maxTokens` | `1024` | 单条回复最大 token |
| `temperature` | `1` | 越高越发散 |
| `timeoutSec` | `90` | 单次请求超时，超了就放弃 |

### 人设

| 字段 | 说明 |
|---|---|
| `systemPrompt` | 全局人设，所有会话共用 |
| `groupPrompt` | 群聊额外追加（叠加在 systemPrompt 后面） |
| `directPrompt` | 私聊额外追加 |

比如想让群里的 AI 说话简短、私聊可以详细：

```json
{
  "systemPrompt": "你是一个乐于助人的助手",
  "groupPrompt": "在群里说话要简短，一般不超过 3 句",
  "directPrompt": "私聊可以详细展开"
}
```

### 上下文

| 字段 | 默认 | 说明 |
|---|---|---|
| `historyLimit` | `10` | 保留几轮对话（1 轮 = 一问一答） |
| `idleTimeoutMin` | `30` | 闲置多久清空上下文（分钟） |

**上下文只存内存，不落盘。** 重启机器人就清空，这是有意的：
聊天记录存本地有隐私问题，而且每轮都写文件是白费 IO。

### 访问控制

| 字段 | 默认 | 说明 |
|---|---|---|
| `access` | `open` | `open` 谁都能用；`allowlist` 只白名单 |
| `allowList` | `[]` | 白名单，填 chatId（群 openid 或私聊用户 openid） |

`allowlist` 模式下，不在名单里的会话完全不响应，也不会消耗 token。

### 调试

| 字段 | 默认 | 说明 |
|---|---|---|
| `debug` | `false` | 打开后在日志里打印每轮耗时和 token 数 |

## 和别的插件一起用

框架的规则是：**所有匹配的插件都会被调用，回复合并成一条发出**。

所以群里同时装了「回声」和「AI 对话」时，一条消息可能两个都想回，
最终发出去的是这样一条：

```
【AI 对话】
你好，我是 AI，有什么可以帮你

【回声】
你好呀，我是回声。发 /help 看命令。
```

每个回复都带【插件名】标题，群里分得清哪句是谁说的。
只有一个插件回时不加标题——那种情况下加标题纯属噪音。

**注意**：AI 对话用 `/ai` 显式触发，不会和「回声」这类「接所有消息」的插件抢。
但 echo 仍会对群里的普通消息接话，日常用建议关掉它（它只是示例）。

## 排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 群里 @ 了没反应 | 这个群的分群插件白名单里没有 ai-chat | 面板「群组 → 插件」把它勾上 |
| 提示「还没配 API Key」 | `apiKey` 空 | 面板里填上 |
| 提示「API Key 不对」 | Key 错了或没权限 | 重新复制一遍，注意别带空格 |
| 提示「余额不足」 | 账户没钱了 | 去服务商充值 |
| 提示「请求太频繁」 | 撞上限流 | 等几秒 |
| 回复很慢 | 模型本身慢 / 网络差 | 换 `deepseek-chat` 这类快的模型 |
| 上一轮聊的内容它不记得 | 闲置超时清空了，或发了 `/新会话` | 正常行为 |
| 重启后不记得之前聊的 | 上下文只存内存 | 正常行为 |

## 设计说明

**为什么不做流式输出**：QQ 群聊不支持流式，用户看到的只是最终那条消息。
流式唯一的好处是「打字机效果」，为此引入 SSE 解析、流式缓冲、
分片发送的复杂度不值得。

**为什么不做工具调用**：我们是机器人框架，不是 agent 运行时。
真要做应该是「插件对外提供工具」，那是另一个量级的事。

**为什么不做图片理解**：需要先下载 QQ 的图片（带鉴权的临时链接）、
再调视觉模型，链路长且容易失效。等真有人需要再说。

**为什么上下文不落盘**：见上面「上下文」一节。

**为什么错误都翻译成人话**：`HTTP 401` 对用户没有意义，
「API Key 不对或没有权限，去面板重新填」才有。同理 402 → 余额不足、
429 → 限流、5xx → 服务商问题。

**为什么同会话不排队**：正在生成时又来个问题，直接告诉用户「上一条还在想」。
排队会让后一个问题的回答对不上上下文，反而更乱。
