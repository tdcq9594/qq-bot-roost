# Roost 宿主协议 v1（`roost-host/1`）

> 框架自己的对外协议。给「把整个框架当宿主来用」的程序（dsh-roost 等）准备，
> 和 `src/onebot/` 的 OneBot v11 兼容层是**两条并列的出口**，互不依赖。

## 0. 定位与边界

OneBot 兼容层做的是「把官方机器人**假装成**一个普通 QQ 客户端」，所以要把
openid 翻译成 QQ 号、把不支持的动作逐个拒绝、把消息压成 CQ 段。

宿主协议反过来：**不翻译、不降级、不假装**。事件就是框架内部的 `Message`
结构，方法就是框架自己的对象。官方接口有什么就给什么，框架能管什么就给什么。

明确不做的事：

- 不产出 OneBot v11 的事件 / CQ 码 / `retcode` 响应
- 不做 openid ↔ QQ 号的「合成号」兜底——没绑就是空串，由客户端自己决定怎么办
- 不承诺跨平台兼容，客户端只对接 Roost

## 1. 传输

**WebSocket 为主，HTTP 为辅，同一个端口、同一份方法表。**

`ws` 是**可选依赖**，和 OneBot 兼容层共用同一份按需安装机制
（`src/ext-deps.js`，白名单校验，装到 `data/deps/ext/`；与 OneBot 兼容层共用同一份）。
Node 22 内置的 `WebSocket` 是客户端，服务端要 `ws`，所以只有启用外接功能的
机器才需要点一次「一键安装」。**没装时整个出口不监听**（HTTP/SSE 也在同一个
`http.Server` 上，不单独降级）：宿主程序用 WS 主通道，悄悄降级成只有 HTTP
会让它连上却收不到事件，不如明确报 `missing-deps`。

**为什么不写进 `package.json`**：用户从 GitHub/Gitee 的 tar 包升级，
`src/updater.js` 只替换代码目录、不跑 npm install、也不带 `node_modules`。
把 `ws` 写成静态依赖，老用户升级后代码一 import 就会让整只鸟起不来。
这里一律动态加载：缺 `ws` 时 `state = 'missing-deps'`，**机器人本体和插件
照常跑**，外接页提示「装一下就能用」。2026-11-12 确认按可选依赖走。

每只鸟一个端口，默认 `6800 + sha1(botId) % 100`（OneBot 是 6700–6799，不重叠）。

| 入口 | 作用 |
|---|---|
| `ws://host:port/` | **主通道**：握手后双向帧，收事件 + 调方法 |
| `GET /events` | SSE 兜底：只推事件，给不方便用 WS 的客户端 / 抓包排查 |
| `POST /rpc` | 一问一答调一个方法，curl 能直接打 |
| `GET /health` | 探活，不需要 token，只回极简状态 |

WS 帧统一带 `type`：`hello` / `welcome` / `event` / `req` / `res` / `gap` /
`ping` / `pong`。客户端连上后先发 `hello`（带 `since`），服务端回 `welcome`
并按 `since` 补缓冲里的事件。

`POST /rpc` 与 WS 的 `req/res` **调用的是同一个方法表**，帧里的方法名、
scope 校验、错误码完全一致，只是少一层 `id` 配对（HTTP 自带一问一答）。

协议版本写在 `welcome.protocol` 里，不放在 URL path 上——换 path 会让所有
客户端重新配一遍地址。

### 鉴权

- `Authorization: Bearer <token>` 或 `?access_token=<token>`，两者都认
- token 为空时**拒绝监听**（不是「不校验」），避免配置被手改成空串变成后门
- 比较用 `timingSafeEqual`，长度不等直接 false
- 非回环地址必须显式 `allowRemote: true` 才允许保存
- 不设 CORS 头；带 `Origin` 且不同源的请求直接拒

### scope

每个方法声明一个所需 scope，请求带的 scope 集合必须包含它。

| scope | 能干什么 | 默认 |
|---|---|---|
| `read` | 读状态、读配置（脱敏）、列插件、查身份、**只读官方 API** | 开 |
| `message` | 发消息、撤回、发流式片、上传/发送富媒体与素材 | 开 |
| `manage` | 改配置、启停插件、调插件工具、绑定身份、写级/不可逆官方 API | **关** |

`allowManage` 是总闸：`false` 时哪怕 `scopes` 里写了 `manage` 也不放行。
**一个 token 泄漏不应该等于框架被接管**，所以配置写、插件启停默认不给。

`qq.call` 是唯一按**目标 API 的风险**动态判权限的方法（见 §4），
查 `getMe` / `getGroupInfo` 这类只读接口只要 `read`，不必为了读交出全部写权限。

## 2. 帧

### 请求 `POST /rpc`

```jsonc
{"id": "c1", "method": "plugin.list", "params": {}}
```

成功：

```jsonc
{"id": "c1", "ok": true, "data": { "plugins": [] }}
```

失败：

```jsonc
{"id": "c1", "ok": false, "error": {"code": "NO_SCOPE", "message": "..."}}
```

- `id` 原样回带，客户端靠它配对；没给就回 `""`
- `params` 必须是对象，缺省 `{}`
- 请求体上限 1 MiB，超了 413
- 一次一个方法，不做批量（批量里一个失败会让整批语义变模糊）

### 事件流 `GET /events?since=<seq>`

```
id: 42
event: message
data: {"chat":{...},"sender":{...},"content":"..."}

id: 43
event: heartbeat
data: {"at":1731400000000}
```

- `id` 是单调递增的 `seq`，只增不减，进程内有效
- `event` 取帧的 `type`（`welcome` / `heartbeat` / `gap`）或事件帧的 `event` 名
  （`message` / `notice`）；`data` 是**完整帧**的 JSON，含 `type` / `seq` / `at` / `data`
- 断线重连时带 `Last-Event-ID`（或 `?since=`），服务端从环形缓冲补发
- 缓冲只留最近 200 条 / 1 小时。**差太多就发一条 `gap`**，让客户端自己
  决定重开会话——丢消息不能是静默的
- 25 秒一条 `heartbeat`，顺带当 SSE 的保活注释

### 错误码

| code | HTTP | 含义 |
|---|---|---|
| `BAD_REQUEST` | 400 | 报文不是合法 JSON / 缺 method / params 不是对象 |
| `UNAUTHORIZED` | 401 | token 不对 |
| `FORBIDDEN` | 403 | 跨源请求 |
| `NOT_FOUND` | 404 | 路径或方法不存在 |
| `NO_SCOPE` | 403 | 该 token 没有这个方法所需的 scope |
| `BAD_PARAMS` | 400 | 参数校验没过 |
| `NOT_READY` | 503 | 框架对象还没就绪（刚启动 / 已停止） |
| `INTERNAL` | 500 | 方法内部抛错，message 带原因 |

## 3. 事件的数据结构（原生，无翻译）

`message` 事件的 `data` 直接来自 `buildMessage()`，字段按白名单挑出，
不做 OneBot 化：

```jsonc
{
  "seq": 42,
  "at": 1731400000000,
  "chat": {
    "kind": "group",
    "chatId": "<group_openid>",
    "groupId": "<group_openid>",
    "groupUin": "763366431",       // 没绑就是空串
    "name": "测试群"
  },
  "sender": {
    "openid": "<member_openid>",
    "uin": "10001",                // 没绑就是空串
    "identityId": "u:10001",
    "aliases": ["..."],
    "name": "小明",
    "isBot": false
  },
  "msgId": "...",
  "eventId": "...",                // 账本 id，回查原文用它（msgId 是回复用的，别混）
  "traceId": "...",
  "content": "看图",
  "rawContent": "<@xxx> 看图",
  "addressed": true,
  "mentioned": true,
  "isCommand": false,
  "mentions": [{"id": "...", "name": "..."}],
  "attachments": [{"type": "image", "url": "..."}],
  "quoted": "被引用的原话",         // 拿不到是空串
  "scene": {"msgIdx": "REFIDX_...", "refMsgIdx": "...", "authToken": "..."},
  "replyTo": null,                 // 被引用那条的 message_id
  "event": "GROUP_AT_MESSAGE_CREATE"
}
```

三个字段容易混，说清楚：

| 字段 | 用途 | 传给谁 |
|---|---|---|
| `msgId` | 被动回复时挂原消息 | `msg.send` 的 `msgId` |
| `eventId` | 回查原文与前后邻文 | `ledger.context` / `msg.get` |
| `quoted` | 被引用的**内容** | 直接读，不用再查 |

`quoted` 只有 `replyTo` 是不够的——那只是个 id，拼不出「引用了哪句话」。
引用回复要引用原文时，用 `scene.msgIdx` 拼 `messageReference`。

`raw` 原始事件体**不进事件流**（它带平台内部字段且体积不可控），需要时
用 `msg.get` 查。`notice` 事件是 `{seq, at, event, data}`，`data` 是框架
回调原样传入的对象。

### `qq.call` —— 覆盖「框架全部协议 API」，按风险分级

```jsonc
{"id":"c9","method":"qq.call","params":{
  "method": "getGroupMembers",
  "args": ["<group_openid>", {"limit": 20}]
}}
```

方法名从 `QQApi.prototype` 现取，`constructor` 等一律排除，私有方法取不到。
**`src/api.js` 以后新增方法自动可用，协议层不用改一行。** 这是「全部 API」
的实现方式，不靠手写几十个包装。

权限由 `endpoints.js` 的 `riskOf()` 推出来（一个方法对应多条端点时取最严），
未登记端点的辅助方法按 `write` 处理：

| 风险 | 需要 scope | 额外条件 | 例子 |
|---|---|---|---|
| read | `read` | — | `getMe` / `getGroupInfo` / `listMediaImages` |
| write | `message` | — | `sendGroup` / `uploadMedia` |
| danger | `manage` | `confirm: true` | `retractGroupMessage` / `removeMembers` |

**拒绝名单**（返回 `FORBIDDEN`，不因为「反射得到」就放行）：

- `internal:true` 的三个素材端点 `prepareMediaImage` / `completeMediaImage` /
  `deleteMediaImage`——绕过本地预检会白耗 100 张配额，改用 `media.image.*`。
- 路径型上传 `uploadLocalFile` / `uploadLocalFileSharded` /
  `uploadMarkdownImage`——宿主在另一台机器，传框架本机路径等于让它读任意文件，
  跨进程请走 `media.upload` / `media.markdownImage`。
- `setGroupInvited` / `setMediaPlaceholderSpace`——改了框架状态却不落盘，请走
  `config.set`；`takeSeq` 会抢被动回复序号，只由 `msg.stream` 内部占用。

### `msg.send` 的字段

参数是**框架的 camelCase 命名**（`content` / `msgId` / `eventId` / `msgSeq` /
`msgType` / `markdown` / `media` / `card` / `ark` / `keyboard` /
`messageReference`），由 `api.sendGroup` 内部的 `buildSendPayload()` 转成官方
报文。传成 `msg_id` 这种 snake_case 会被静默丢掉——消息照样发得出去，但
被动回复退化成主动消息，白吃额度还容易撞频次限制。

发图 / 发卡片走 `media` / `card` 字段即可，只要 `message` 权限，不必为了它
去开 `qq.call` 的 `manage`。

**全部发送都经过框架的出站调度器 `R.outbound`，不是直连官方接口。**
`msg.send` / `media.send` / `media.image.send` 走同一条出口（`src/host/dispatch.js`），
因此以下规则自动生效，客户端不需要、也不应该自己实现：

| 机制 | 说明 |
|---|---|
| 离线判断 | 没连上直接拒，不打接口 |
| 限速 | 每秒 / 每分钟按 `kind:chatId` 记账 |
| 主动额度 | 默认 1000 条/天，用完报 `quota` |
| 被动窗口 | 群 5 分钟 / 单聊 60 分钟，快过期自动降级为主动（有开关） |
| 被动次数 | 群 5 次 / 单聊 4 次，本地先拦 |
| 审核 | `304023` 返回 `pending: true`，**不是失败** |
| 投递账本 | 有 `requestId` 才入账，`delivery.get` 查的就是它 |
| `dry` 演练 | 最顶层截住，连账本都不进 |

两个参数只对发送调度有意义：

- **`receivedAt`**（毫秒时间戳）：被动窗口判断只认它。不传会被当成「刚收到」，
  窗口检查就形同虚设，过期回复会被当新鲜消息发出去，最后撞官方 `40034xxx`。
  事件里的 `at` 就是这个值。客户端没传时，协议会用 `eventId` 去账本反查一次。
- **`requestId`**：投递账本的幂等键，**跨重启有效**，还能让 `delivery.get`
  查到审核终态。`clientMsgId` 只是进程内 5 分钟去重，比它弱；两者可以一起用。

返回值：

```jsonc
{
  "id": "新消息的 msg_id",     // 官方原始报文里的 id，撤回/引用它时用这个
  "msgId": "同上",             // 兼容别名，值一样
  "pending": true,             // 只有进审核（304023）才有这个字段
  "requestId": "rid-9",        // 带了才回，拿去问 delivery.get
  "reused": true               // 只有账本命中（同 requestId 重发）才有
}
```

`id` 是**发出去那条**的新消息 id，不是事件里的 `msgId`（那是收到的消息）。
要引用 / 撤回自己刚发的那条，用这个 `id`。

### 官方素材管理（Markdown 图片图床）

依据[官方素材管理文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/material-management.html)：
`prepare` → 预签名 PUT → `complete` 拿到 `qqbot-media://` 引用，另有查询与删除。
框架 `src/api.js` 原本已实现三步 + 删除，本轮补上 `listMediaImages()` 查询和
`uploadMarkdownImageBytes()` 字节入口——跨进程不用把图片落成框架本机路径，
扩展名按文件头补全，避免 jpeg/gif/webp 被官方 `40035001` 拒。

| 约束 | 值 |
|---|---|
| 单图 | ≤10MB；png / jpeg / gif / webp，扩展名必须与 `content_type` 一致 |
| 配额 | 单机器人 100 张，满了要 `media.image.delete` 释放 |
| 有效期 | 滑动 90 天；`upload_id` 4 小时；`preview_url` 短时效勿持久化 |
| 归属 | 引用与机器人绑定，别的机器人用会报 `40035010` |

`media.markdownImage` **默认 `retain:true`**（记入 `media-images-kept.json`）：
宿主拿到引用后自己发消息，框架不会替它删，也不会被重启后的孤儿回收误删。
用完调 `media.image.delete` 释放配额。`media.image.send` 相反，默认发完即删，
与框架内 `replyAuto` 的「自产自销」策略一致。

`media.image.delete` 要 `manage` + `confirm: true`，协议层还会先用
`listMediaImages()` 翻页确认 `image_id` 确实属于本机器人，才允许删非本进程
上传的素材——素材库是机器人级共享的，别误删其它插件的图。

### `config.set` 的边界

只接受**运行时设置**的白名单键：`name`、`commandPrefix`、`owners`、
`whitelist`、`rateLimit`、`dedupWindowSec`、`messageLog`、`groupManage`、
`media`。校验规则与面板「配置」页一致（布尔严格比类型、`owners` 逐项转
字符串等），改完 `saveBotConfig` 落盘并同步 api 层钩子。
要改插件配置走 `plugin.config.set`，要改插件过滤器走 `plugin.enable/disable`。

**不接受**：`appId`、`appSecret`、`baseUrl`、`connection`、`webui`、
`onebot.*`、`host.token`。改这些要么要重连网关、要么涉及密钥与自身入口，
走面板更安全。`config.get` 里这些字段一律脱敏成 `********`。

### `plugin.tool.call`

以宿主身份调用（等同管理员），所以是 `manage`。参数 `{name, args, msg?}`，
`msg` 可以给一个会话上下文，让需要会话身份的工具能跑；不给就用一个空上下文，
`ownerOnly` 工具会因为宿主身份被放行。

### `tool.<工具名>` —— 插件给协议加的新方法

插件用 `ctx.registerTool({ name, description, parameters, execute, ... })`
注册跨插件工具，协议**自动**多出一个同名的一等方法 `tool.<name>`：

- 出现在 `system.hello` 的 `features`、`system.capabilities` 的清单里；
  `system.hello` 多一个 `dynamicTools: true` 标记，老客户端可以忽略。
- `system.capabilities` 对动态方法额外返回 `parameters`（JSON Schema），
  客户端不用另调 `plugin.tool.list` 就知道参数怎么填。
- 参数可以直接给（`{"sides":6}`），也可以包一层（`{"args":{"sides":6}}`）；
  顶层 `required` 与基础 `type` 会先校验，插件的 `execute` 再自己把关。
- 返回 `{ tool, pluginId, result }`；工具报错统一变成 `INTERNAL`。
- **scope**：普通工具是 `message`（默认宿主令牌就有）；声明了
  `ownerOnly` / `admin` 的工具自动提到 `manage`。插件作者不要把危险操作
  注册成普通工具——`message` 令牌能发消息，也就能调它。
- **热更新**：方法表每次现读注册表，不缓存。插件卸载后同名调用立刻 404；
  工具集变化时事件流推一条 `capabilities.changed`（带新 `features` 与
  `tools`），客户端应重新拉一次清单，别把 `features` 当静态契约。
- `hidden: true` 的工具不投影（仍可通过 `plugin.tool.call` 显式调用）。
- 工具名全局唯一、跨插件重名在加载时就报错；加前缀后也不会和内置方法撞名。

## 5. 生命周期与安全

- `enabled: false` 时不监听，不占端口
- 缺 token / 非回环未授权 / 端口起不来 → `state = error`，**不影响机器人本体**
- 面板连点保存会并发 start/stop，用串行队列挡住（OneBot 踩过端口漂移的坑）
- 事件是**旁路推送**，本版不拦插件管线。ai-chat 中间层移除后 dsh-roost
  直连这个协议，不再有第二条回话链路；`exclusive` 语义留到后续版本
- SSE 连接数有上限，超了直接拒，不让一个客户端把端口占满
- 每次方法调用与拒绝都写日志，面板能看到调用计数

## 6. 与 OneBot 兼容层的关系

| | 宿主协议 | OneBot v11 兼容层 |
|---|---|---|
| 端口 | 6800+ | 6700+ |
| 事件 | 框架原生结构 | 翻译成 v11 事件 |
| openid | 原生给出 | 映射成 QQ 号，未绑用合成号 |
| 方法 | 框架能力总线（含管理面） | v11 动作表 |
| 服务对象 | 自己的宿主程序 | aurobot / NoneBot 等第三方 |
| 依赖 | 可选 `ws` | 可选 `ws` + `silk-wasm` |

两个出口**共用同一份 `ws` 依赖与同一张「依赖」卡片**：装一次，两边都能用。
外接页上半部分是宿主协议，下半部分仍是 OneBot。
