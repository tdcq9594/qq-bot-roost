# 事件与接口清单

对照官方文档逐条核对的审计结果。**结论：43 个事件全部能接收并转交插件，无遗漏。**

- 官方事件来源：[事件订阅与通知](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html)
- 官方接口来源：[botgo](https://github.com/tencent-connect/botgo)（腾讯官方 Go SDK）的 `openapi/v1/resource.go`

## 二、事件如何转交插件

两类事件的回调参数不同，这是刻意设计：

| 事件类型 | 插件收到的参数 | 说明 |
|----------|----------------|------|
| **消息类**（标了 `message` 的 6 个） | `Message` 对象 | 已规范化，有 `content` / `args` / `reply()` 等 |
| **其余事件** | `(原始 d, { event, intent, desc, api })` | 保持官方原始结构，需要什么取什么 |

```js
// 消息类：拿 Message
ctx.on('GROUP_AT_MESSAGE_CREATE', async (msg) => {
  await msg.reply('收到');
});

// 非消息类：拿原始 d
ctx.on('GUILD_MEMBER_ADD', async (d, info) => {
  ctx.logger.info(`${d.user.id} 加入了 ${d.guild_id}（intent=${info.intent}）`);
});
```

**内核不认识的未知事件也会转发**，只是日志里会打一条 WARN 提示补登记。
这样官方新增事件时，插件能第一时间用上，不会被内核卡住。

## 四、intents 订阅位

事件能不能收到，取决于连接时 `intents` 里有没有对应的位。

| 位 | 值 | 名称 | 事件数 | 权限 |
|----|----|------|--------|------|
| 0 | 1 | GUILDS | 6 | 默认可用 |
| 1 | 2 | GUILD_MEMBERS | 3 | 默认可用 |
| 9 | 512 | GUILD_MESSAGES | 2 | 需申请，仅私域 |
| 10 | 1024 | GUILD_MESSAGE_REACTIONS | 2 | 需申请 |
| 12 | 4096 | DIRECT_MESSAGE | 2 | 需申请 |
| 25 | 33554432 | GROUP_AND_C2C_EVENT | 10 | 需开通群聊能力 |
| 26 | 67108864 | INTERACTION | 1 | 需申请 |
| 27 | 134217728 | MESSAGE_AUDIT | 2 | 需申请 |
| 28 | 268435456 | FORUMS_EVENT | 8 | 需申请，仅私域 |
| 29 | 536870912 | AUDIO_ACTION | 4 | 需申请 |
| 30 | 1073741824 | PUBLIC_GUILD_MESSAGES | 2 | 默认可用 |

**勾了没权限的位，WebSocket 鉴权会被拒并断开（关闭码 4014）。** 默认 `33554432` 就够群聊用。

面板「配置 → 事件订阅」是勾选式的，不用自己算位掩码。

## 六、怎么加一个新事件

官方加了新事件时，**只改一处**：

1. `src/events.js` 的 `EVENTS` 里加一条：

```js
NEW_EVENT_NAME: {
  intent: 'GROUP_AND_C2C_EVENT',   // 属于哪个订阅位
  group: '群聊',                    // 面板分组
  desc: '一句话说明',                // 面板和文档显示
  message: 'group',                 // 可选：是消息类就写会话类型
},
```

2. 更新本文档的表格
3. `npm test` —— 自检会校验事件表完整性（intent 合法、位值一致、消息类型合法）

`message.js`、分发器、面板都从这个表读，不用改别处。
