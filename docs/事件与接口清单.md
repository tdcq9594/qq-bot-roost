## 二、事件如何转交插件

两类事件的回调参数不同，这是刻意设计：

| 事件类型 | 插件收到的参数 | 说明 |
|----------|----------------|------|
| **消息类**（标了 `message` 的 6 个） | `Message` 对象 | 已规范化，有 `content` / `args` / `reply()` 等 |
| **其余事件** | `(原始 d, { event, intent, desc, api })` | 保持官方原始结构，需要什么取什么 |

```js
// 消息类：拿 Message
ctx.on('GROUP_AT_MESSAGE_CREATE', async (msg) => {
  await msg.reply('收到');
});

// 非消息类：拿原始 d
ctx.on('GUILD_MEMBER_ADD', async (d, info) => {
  ctx.logger.info(`${d.user.id} 加入了 ${d.guild_id}（intent=${info.intent}）`);
});
```

**内核不认识的未知事件也会转发**，只是日志里会打一条 WARN 提示补登记。
这样官方新增事件时，插件能第一时间用上，不会被内核卡住。

## 六、怎么加一个新事件

官方加了新事件时，**只改一处**：

1. `src/events.js` 的 `EVENTS` 里加一条：

```js
NEW_EVENT_NAME: {
  intent: 'GROUP_AND_C2C_EVENT',   // 属于哪个订阅位
  group: '群聊',                    // 面板分组
  desc: '一句话说明',                // 面板和文档显示
  message: 'group',                 // 可选：是消息类就写会话类型
},
```

2. 更新本文档的表格
3. `npm test` —— 自检会校验事件表完整性（intent 合法、位值一致、消息类型合法）

`message.js`、分发器、面板都从这个表读，不用改别处。
