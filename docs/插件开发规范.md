# 插件开发规范 v1

本文是**唯一**的插件约定文档。照着写就能被内核加载，不需要改内核代码。

---

## 1. 插件是什么

一个插件 = `plugins/` 下的**一个文件夹**，内含 `index.js`：

```
plugins/
└── my-game/
    ├── index.js         必需，入口
    ├── data/            可选，插件自带静态资源（只读）
    └── lib/             可选，自己的子模块
```

内核启动时扫描 `plugins/*/index.js`，依次调用每个插件的 `setup()`。
**删除文件夹 = 卸载插件**，不需要额外操作。

---

## 2. 最小可用插件

```js
// plugins/hello/index.js
export default {
  id: 'hello',
  name: '打招呼',
  version: '1.0.0',
  description: '最小示例',

  setup(ctx) {
    ctx.command('hello <名字>', { desc: '跟某人打招呼' }, async (msg, { args }) => {
      await msg.reply(`你好，${args[0]}！`);
    });
  },
};
```

发 `/reload hello` 立即生效，无需重启进程。

---

## 3. 导出字段

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 插件唯一标识，**必须与文件夹名一致** |
| `name` | string | 否 | 显示名，默认等于 `id` |
| `version` | string | 否 | 语义化版本，如 `1.2.0` |
| `description` | string | 否 | 一句话说明，出现在 `/plugins` |
| `setup(ctx)` | function | 是 | 注册命令/监听，**加载时调用一次** |
| `teardown(ctx)` | function | 否 | 卸载时调用，用来清理定时器、关闭连接 |

### id 命名规则

- 全小写，单词用短横线连接：`douluo-game`、`group-guard`
- 只允许 `[a-z0-9-]`，长度 2–32
- **全局唯一**，重复会导致后加载的失败
- 与命令名不要重名（命令是全局共享的）

---

## 4. 生命周期

```
扫描 plugins/
   ↓
读取 data/plugins.json 里的启用状态（缺省 = 启用）
   ↓
import(index.js) → 校验导出 → 创建 ctx → setup(ctx)
   ↓
运行中：收事件、跑命令
   ↓
/disable  → teardown(ctx) → 注销该插件全部命令与监听
/reload   → 先 unload 再 load（代码改动即时生效）
```

**注意**：`reload` 会重新 `import` 模块，模块顶层变量会重置；
需要跨重载保留的数据必须放 `ctx.storage`。

## 5. ctx 能力清单

### 5.1 `ctx.command(模式, 选项, 处理函数)`

```js
ctx.command('attack <目标> [次数]', {
  desc: '攻击目标',
  usage: '/attack <目标> [次数]',   // 可选，默认由模式生成
  admin: false,                      // true = 仅主人可用
}, async (msg, { args, raw }) => {
  const [目标, 次数 = 1] = args;
});
```

**模式语法**（只影响帮助展示与必填校验）：

| 写法 | 含义 |
|------|------|
| `attack` | 命令名，无参数 |
| `<目标>` | 必填参数；缺了内核会自动回复用法 |
| `[次数]` | 可选参数 |
| `<内容...>` | 必填，吃掉剩余全部内容 |

- 命令名取模式串的**第一个词**，大小写不敏感
- 实际参数通过 `msg.args` 数组拿（按空白切分），**模式里的名字只是提示**
- 需要保留空格原文时用 `msg.content`

**命令名冲突**：同名命令后注册的会抛错，`/plugins` 能看到是哪个插件报的。

### 5.2 `ctx.on(事件名, 处理函数)`

```js
ctx.on('message', async (msg) => { ... });          // 所有消息（命令除外）
ctx.on('GROUP_AT_MESSAGE_CREATE', async (msg) => { ... });  // 仅群 @
ctx.on('GROUP_ADD_ROBOT', async (d) => { ... });    // 机器人被拉进群
```

可用事件名见 [§7](#7-可用事件名)。

> 注意：`GROUP_MESSAGE_CREATE` 可能是**全量群消息**，不只是 @ 机器人的。
> 内核不会提前过滤，而是全部交给插件判断，**没人回应才丢弃**。

**分发顺序**（重要）：

1. 是命令且已注册 → **只**执行该命令的处理函数，不再触发监听
2. 是命令但未注册 → 回复「没有这个命令」
3. 不是命令 → 依次触发 `message` 监听、再触发原始事件监听
4. **没有任何监听者回应 → 判定为噪音，静默丢弃**

### 怎么表达「这条消息我处理了」

两种方式，满足任一即可：

```js
// 方式一：发消息（reply / push / replyImage 等都算）
ctx.on('message', async (msg) => {
  if (msg.content === '打卡') await msg.reply('打卡成功');
});

// 方式二：显式 return true（适合你不想回复、但想占用这条消息的场景）
ctx.on('message', async (msg) => {
  if (msg.content.startsWith('【系统】')) return true; // 吞掉，不回复
});
```

**这决定了要不要加 `msg.mentioned` 判断**：

- 做「被动关键词」玩法（不 @ 也能触发）→ 不要判断 `mentioned`，直接匹配关键词
- 做「主动搭话」（有人 @ 才接话）→ 先 `if (!msg.mentioned) return;`，否则群里聊到相关词就会插嘴

```js
ctx.on('message', async (msg) => {
  if (msg.isCommand) return;          // 命令已由命令路由处理
  if (!msg.mentioned) return;         // 没 @ 就闭嘴
  if (msg.content.includes('你好')) await msg.reply('你好呀');
});
```

### 5.3 `ctx.storage`

插件私有键值存储，落盘到 `data/plugins/<id>.json`，300ms 防抖写入。

```js
await ctx.storage.set('user:123', { level: 5 });
const u = await ctx.storage.get('user:123', { level: 1 });  // 第二个参数是默认值
await ctx.storage.delete('user:123');
const all = await ctx.storage.all();   // 整个命名空间
```

- 键名建议加前缀：`user:<id>`、`group:<id>`、`global:xxx`
- **不要在每次读写时 `all()` 全量遍历**，数据大了会很慢
- 数据量超过几千条、需要查询/事务时，插件里直接引 SQLite，不要硬塞 JSON

### 5.4 其他

| 成员 | 说明 |
|------|------|
| `ctx.menu(分组名, 条目[])` | 追加菜单分组，用于非命令玩法（见第 6 节） |
| `ctx.schedule(名称, 毫秒, 函数)` | 定时任务，**卸载时自动清理**，不会残留 |
| `ctx.isGroupAdmin(群openid, userId)` | 该用户是否是这个群的管理者（默认是邀请机器人入群的人） |
| `ctx.getGroup(群openid)` | 读取群档案：邀请人、管理者、是否启用、最后活跃时间 |
| `ctx.onTeardown(fn)` | 注册卸载回调（关连接、停外部轮询等） |
| `ctx.api` | 原始 HTTP API：`sendGroup` / `sendC2C` / `uploadMedia` |
| `ctx.logger` | `info/warn/error/debug`，自动带 `plugin:<id>` 前缀 |
| `ctx.isOwner(userId)` | 判断是否机器人主人 |
| `ctx.prefix` | 当前命令前缀（默认 `/`） |
| `ctx.id` / `ctx.name` / `ctx.version` | 自身元信息 |

## 6. 必须提供菜单（强制要求）

**每个插件都必须让用户能看到它能做什么。** 内核在加载插件后会检查：

- 只要插件注册了命令，或调用过 `ctx.menu()`，就算通过
- 两者都没有 → 日志打 WARN，`/help` 和 `/plugins` 里显示「未提供菜单」

### 命令会自动进菜单

`ctx.command()` 注册的命令会**自动**出现在菜单的「指令」分组里，不用重复声明：

```js
ctx.command('roll [面数]', { desc: '掷一次骰子' }, handler);
// 菜单里自动出现：/roll [面数]  掷一次骰子
```

### 非命令玩法要用 ctx.menu 补

游戏类插件常有「不用斜杠触发」的玩法，或者纯展示的说明，这些要显式补：

```js
ctx.menu('玩法', [
  { text: '攻击',        desc: '对当前目标发起攻击' },
  { text: '直接说「掷骰子」', desc: '不用加前缀也能触发' },
]);

ctx.menu('说明', [
  { text: '每个玩家的数据独立保存' },   // 纯文本条目，不是命令
]);
```

渲染效果（`/help 插件id`）：

```
掷骰子 v1.1.0
演示参数解析、玩家数据持久化与关键词被动触发

【指令】
  /roll [面数]  掷一次骰子，默认 100 面
  /rank  查看掷骰子排行榜（前 5）

【玩法】
  掷骰子  群里直接说这三个字，不用加前缀

【说明】
  每个玩家的次数与最高值单独记录
```

### 条目格式

| 写法 | 含义 |
|------|------|
| `{ cmd: 'roll [面数]', desc: '...' }` | 命令条目，渲染时自动加前缀 `/roll [面数]` |
| `{ text: '攻击', desc: '...' }` | 纯文本条目，原样显示 |
| `'一句说明'` | 纯文本条目，无描述 |

> 用 `cmd` 还是 `text` 的区别只在于**要不要加命令前缀**。
> 已经用 `ctx.command` 注册过的命令不要再写进 `ctx.menu`，会重复。

## 7. Message 对象

| 字段 | 类型 | 说明 |
|------|------|------|
| `msg.id` | string | 消息 id，被动回复必需 |
| `msg.kind` | string | `group` / `c2c` / `guild` |
| `msg.event` | string | 原始事件名 |
| `msg.userId` | string | 发送者 openid |
| `msg.groupId` | string | 群 openid（私聊为空） |
| `msg.chatId` | string | `groupId || userId`，用作会话键最方便 |
| `msg.content` | string | 去掉 @机器人 和前缀后的正文 |
| `msg.args` | string[] | 按空白切分后的参数 |
| `msg.isCommand` | boolean | 是否以命令前缀开头 |
| `msg.command` | string | 命令名（小写） |
| `msg.mentioned` | boolean | 正文里是否 @ 了机器人 |
| `msg.replied` | boolean | 本条消息是否已经发过回复（内核据此判断有没有人回应） |
| `msg.raw` | object | 官方原始事件体，需要什么取什么 |
| `msg.at` | number | 消息时间戳（毫秒） |

### 发送方法

| 方法 | 说明 |
|------|------|
| `msg.reply(text, opts?)` | **被动回复**，带 `msg_id`，`msg_seq` 自动递增。5 分钟内有效 |
| `msg.push(text, opts?)` | **主动推送**，不带 `msg_id`，有频次限制 |
| `msg.replyMarkdown(md, keyboard?)` | Markdown 消息，可带按钮 |
| `msg.replyImage(url)` | 发图片（传 URL，或本地路径配 `{local:true}`） |
| `msg.replyVideo(url)` | 发视频（mp4） |
| `msg.replyVoice(url)` | 发语音（silk） |
| `msg.replyFile(url)` | 发文件（官方暂未开放） |

富媒体走「先上传拿 `file_info`，再以 `msg_type=7` 发送」，失败只记日志不抛异常。

> **被动回复窗口是 5 分钟**。超时后再调 `reply` 会失败——长耗时任务请用 `push`，
> 或先 `reply('处理中…')` 再异步补发。

## 8. 可用事件名

**消息类**（会被规范化成 Message）：

| 事件 | 场景 |
|------|------|
| `GROUP_AT_MESSAGE_CREATE` | 群里 @机器人（官方文档写法） |
| `GROUP_MESSAGE_CREATE` | 群里 @机器人（平台实际下发的事件名，结构相同） |
| `C2C_MESSAGE_CREATE` | 用户私聊机器人 |

**系统类**（回调参数是官方原始 `d` 对象）：

| 事件 | 场景 |
|------|------|
| `GROUP_ADD_ROBOT` | 机器人被拉进群（内核会自动登记群档案并可能认主） |
| `GROUP_DEL_ROBOT` | 机器人被移出群（内核会标记该群为已移出） |
| `FRIEND_ADD` / `FRIEND_DEL` | 加/删好友 |

> 事件能不能收到，取决于连接时订阅的 `intents`。默认 `1 << 25`（群聊 @ + 私聊），
> 需要更多事件时改 `config.json` 的 `intents`，并在开放平台申请对应权限。

## 9. 错误处理

内核在调用你的处理函数时已经包了 `try/catch`：

- 命令抛错 → 日志记录堆栈，并回复「执行出错: xxx」给用户
- 监听器抛错 → 只记日志，不影响其他监听器

**但你仍然要自己做业务级校验**：

```js
ctx.command('buy <物品>', { desc: '购买' }, async (msg, { args }) => {
  const item = SHOP[args[0]];
  if (!item) return msg.reply(`没有「${args[0]}」这个物品`);   // 预期内错误，直接回
  const gold = await getGold(msg.userId);
  if (gold < item.price) return msg.reply('金币不够');
  // ...
});
```

**规范**：

- 用户能看懂的失败 → `msg.reply('...')` 说清楚
- 真正的 bug → 让它抛，内核会记堆栈
- 不要 `catch` 之后什么都不做

## 10. 日志规范

```js
ctx.logger.info('玩家 %s 升到 %d 级', uid, level);
```

- 用 `ctx.logger`，不要 `console.log`（否则不带插件前缀，排查困难）
- 正常流程用 `info`，可疑但可恢复用 `warn`，出错用 `error`
- 高频路径（每条消息都走）用 `debug`，默认不输出

## 11. 性能与约束

| 约束 | 说明 |
|------|------|
| **单进程** | 插件与内核同进程，**禁止死循环、禁止同步阻塞**（`while(true)`、大文件同步读） |
| **不要 sleep 太久** | 命令处理超过 5 秒会错过被动回复窗口 |
| **定时任务** | 用 `setInterval`，**必须在 `teardown` 里 `clearInterval`**，否则 reload 后会有多份在跑 |
| **并发** | 同一用户可能连发多条，写存档要防并发（简单做法：按 userId 串行化） |
| **内存** | 别把整张配置表读进内存反复复制；共享一份只读对象 |

定时任务用 `ctx.schedule`，卸载时会自动清理：

```js
export default {
  id: 'tick',
  setup(ctx) {
    ctx.schedule('heartbeat', 60_000, () => ctx.logger.info('心跳'));

    // 需要手动控制时，返回值是停止函数
    const stop = ctx.schedule('fast', 5_000, () => { /* ... */ });
    // stop();
  },
};
```

> 不要用裸 `setInterval`。虽然 `teardown` 里也能清，但容易漏；
> `ctx.schedule` 会登记到插件生命周期，`/reload` 和 `/disable` 都会自动停掉。

## 12. 权限

权限模型分两个维度：**作用域**决定「在哪管」，**等级**决定「能管谁」。

### 等级

| 等级 | 值 | 说明 |
|------|----|------|
| 主人 | 100 | 只来自 `config.json` 的 `owners`，命令不能授予 |
| 管理员 | 80 | 可授予协管、助手 |
| 协管 | 60 | 可授予助手 |
| 助手 | 40 | 只能用被授权的功能，不能管人 |
| 普通成员 | 0 | 默认 |

**核心规则：只能授予严格低于自己的等级。** 上级可以设下级，同级和下级设不了同级或上级。

### 作用域

| 写法 | 含义 |
|------|------|
| `global` | 全局 |
| `group:<群openid>` | 某个群 |
| `channel:<频道id>` | 某个频道 |
| `user:<用户openid>` | 某人的私聊 |
| `feature:<插件id>` | 某个功能的管理权 |

**有效等级 = max(全局等级, 当前作用域等级)。**
全局管理员在任何地方都是 80；只是 A 群协管的人，在 B 群就是 0。

### 插件里怎么用

```js
ctx.command('kick <openid>', { desc: '踢人' }, async (msg, { args }) => {
  if (!(await ctx.can(msg))) return msg.reply('需要管理员权限');   // 默认 80
  if (!(await ctx.can(msg, 'manager'))) return;                    // 指定 60
  // ...
});

// 拿到具体等级做更细的判断
const lv = await ctx.levelOf(msg);
if (lv >= 80) { /* 管理员 */ }

// 当前作用域
const scope = ctx.scopeOf(msg); // group:xxx / channel:xxx / user:xxx
```

### 命令选项

| 选项 | 含义 |
|------|------|
| `admin: true` | 需要**当前作用域**管理员（80）及以上 |
| `globalAdmin: true` | 需要**全局**管理员（80）及以上，用于影响全局的操作（如启停插件） |

```js
ctx.command('purge', { desc: '清理本群数据', admin: true }, handler);
ctx.command('shutdown', { desc: '全局停机', admin: true, globalAdmin: true }, handler);
```

### 谁来配置

- 聊天里：`/admin set <openid> <admin|manager|helper> [作用域]`，上级设下级
- 群主/邀请机器人入群的人，会自动获得该群的**管理员**权限
- 面板「权限」页可可视化增删

## 13. 发布规范

一个可分发的插件目录应该长这样：

```
plugins/group-guard/
├── index.js
├── README.md          说明功能、命令、配置项
└── data/              静态资源（可选）
```

**要求**：

1. `index.js` 里 `version` 必须是语义化版本，改行为就升版本
2. `README.md` 必须列出：所有命令、所需权限、数据存哪、是否有定时任务
3. **不要依赖 npm 包**（当前内核无依赖管理）。确实需要时，在 README 里写清安装步骤
4. 不要在 `setup` 里做网络请求等慢操作，会拖慢启动——需要预热就异步做
5. 不要读写其他插件的数据文件

## 14. 完整示例：游戏插件骨架

```js
// plugins/douluo/index.js
const CONFIG = {
  startHp: 100,
  startGold: 10,
};

export default {
  id: 'douluo',
  name: '斗罗大陆',
  version: '0.1.0',
  description: '文字游戏示例：注册角色、打怪、看属性',

  async setup(ctx) {
    // 读玩家存档
    const load = async (uid) =>
      (await ctx.storage.get(`user:${uid}`)) ?? null;
    const save = (uid, p) => ctx.storage.set(`user:${uid}`, p);

    ctx.command('注册 [名字]', { desc: '创建角色' }, async (msg, { args }) => {
      const uid = msg.userId;
      if (await load(uid)) return msg.reply('你已经有角色了，发 /属性 查看');

      const player = {
        name: args[0] ?? `魂师${uid.slice(-4)}`,
        level: 1,
        hp: CONFIG.startHp,
        maxHp: CONFIG.startHp,
        gold: CONFIG.startGold,
        createdAt: Date.now(),
      };
      await save(uid, player);
      await msg.reply(`角色创建成功：${player.name}\n生命 ${player.hp}，金币 ${player.gold}`);
    });

    ctx.command('属性', { desc: '查看自己的角色' }, async (msg) => {
      const p = await load(msg.userId);
      if (!p) return msg.reply('还没有角色，先发 /注册');
      await msg.reply(
        `【${p.name}】Lv.${p.level}\n生命 ${p.hp}/${p.maxHp}\n金币 ${p.gold}`,
      );
    });

    ctx.command('打怪', { desc: '打一只魂兽' }, async (msg) => {
      const uid = msg.userId;
      const p = await load(uid);
      if (!p) return msg.reply('还没有角色，先发 /注册');
      if (p.hp <= 0) return msg.reply('你已阵亡，发 /复活 恢复');

      const dmg = 5 + Math.floor(Math.random() * 10);
      const hurt = Math.floor(Math.random() * 8);
      p.hp = Math.max(0, p.hp - hurt);
      p.gold += 3;
      if (p.hp === 0) p.level = Math.max(1, p.level); // 简化：不掉级
      await save(uid, p);

      await msg.reply(
        `你造成 ${dmg} 点伤害，受到 ${hurt} 点伤害\n生命 ${p.hp}/${p.maxHp}，金币 ${p.gold}`,
      );
    });

    ctx.command('复活', { desc: '恢复满血' }, async (msg) => {
      const p = await load(msg.userId);
      if (!p) return msg.reply('还没有角色');
      p.hp = p.maxHp;
      await save(msg.userId, p);
      await msg.reply(`已复活，生命 ${p.hp}/${p.maxHp}`);
    });

    // 入群欢迎：演示系统事件监听
    ctx.on('GROUP_ADD_ROBOT', async (d) => {
      ctx.logger.info('被拉进群', d.group_openid);
    });
  },

  teardown() {
    // 清理定时器 / 关闭连接
  },
};
```
