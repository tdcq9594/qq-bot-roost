# 插件开发规范 v1

本文是**唯一**的插件约定文档。照着写就能被内核加载，不需要改内核代码。

---

## 0. 先选插件类型

本平台有两种插件，**写法完全不同**：

| | 内建插件 | 外部插件 |
|---|---|---|
| 识别 | 目录下有 `index.js` | 目录下有 `plugin.json` |
| 语言 | 只能 JavaScript | **任意语言** |
| 运行 | 主进程内 | 独立子进程 |
| 崩溃 | 拖垮整个机器人 | 只影响自己 |
| 文档 | **本文** | **[插件协议.md](插件协议.md)** |

本文讲内建插件。要写 Python / Go / Rust 插件，看 `插件协议.md`。

---

## 1. 插件是什么

一个插件 = `plugins/` 下的**一个文件夹**，内含 `index.js`：

```
plugins/
└── my-game/
    ├── index.js         必需，入口
    ├── requirements.txt 可选，Python 依赖（外部插件用）
    ├── assets/          可选，插件自带静态资源（只读）
    └── lib/             可选，自己的子模块
```

内核启动时扫描 `plugins/*/index.js`，依次调用每个插件的 `setup()`。
**删除文件夹 = 卸载插件**，不需要额外操作。

### 插件的配置、日志、数据分别在哪

这三样**不在**插件文件夹里，由内核统一放在三个目录，插件代码里不要自己拼路径：

| 内容 | 位置 | 谁写 | 拿到的方式 |
|------|------|------|-----------|
| 配置 | `config/bots/<机器人id>/plugins/<id>.json` | 用户改，内核补默认值 | `ctx.config` / `ctx.setConfig()` |
| 日志 | `logs/bots/<机器人id>/plugins/<id>.log` | 内核自动写 | `ctx.logger.info()` |
| 存档 | `data/plugins/<id>.json` | 插件写 | `ctx.storage` |

**为什么分三处**：

- `config/` 是**用户**写的设置 → 备份/迁移时单独搬，不会带上几百 MB 存档
- `data/` 是**程序**写的存档 → 删了等于重置玩家数据，不该和配置混在一起
- `logs/` 是可丢的排查材料 → 轮转覆盖，不进备份

> 插件文件夹里**只放代码**。写业务数据一律走 `ctx.storage`，读配置一律走 `ctx.config`。
> 直接 `fs.writeFile` 到插件目录会在插件更新时被覆盖掉。

### 完整目录（以两个插件为例）

bot/

## 2. 最小可用插件

```js
// plugins/hello/index.js
export default {
  id: 'hello',
  name: '打招呼',
  version: '1.0.0',
  description: '最小示例',

  setup(ctx) {
    ctx.command('hello <名字>', { desc: '跟某人打招呼' }, async (msg, { args }) => {
      await msg.reply(`你好，${args[0]}！`);
    });
  },
};
```

发 `/reload hello` 立即生效，无需重启进程。

## 3. 导出字段

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 插件唯一标识，**必须与文件夹名一致** |
| `name` | string | 否 | 显示名，默认等于 `id` |
| `version` | string | 否 | 语义化版本，如 `1.2.0` |
| `description` | string | 否 | 一句话说明，出现在 `/plugins` |
| `config` | object | 否 | 默认配置，会生成 `config/bots/<机器人id>/plugins/<id>.json`（见 §5.7） |
| `setup(ctx)` | function | 是 | 注册命令/监听，**加载时调用一次** |
| `teardown(ctx)` | function | 否 | 卸载时调用，用来清理定时器、关闭连接 |

### id 命名规则

- 全小写，单词用短横线连接：`douluo-game`、`group-guard`
- 只允许 `[a-z0-9-]`，长度 2–32
- **全局唯一**，重复会导致后加载的失败
- 与命令名不要重名（命令是全局共享的）

---

## 4. 生命周期

```
扫描 plugins/
   ↓
读取 data/bots/<机器人id>/plugins.json 里的启用状态（缺省 = 启用）
   ↓
import(index.js) → 校验导出 → 创建 ctx → setup(ctx)
   ↓
运行中：收事件、跑命令
   ↓
/disable  → teardown(ctx) → 注销该插件全部命令与监听
/reload   → 先 unload 再 load（代码改动即时生效）
```

**注意**：`reload` 会重新 `import` 模块，模块顶层变量会重置；
需要跨重载保留的数据必须放 `ctx.storage`。

## 5. ctx 能力清单

### 5.1 `ctx.command(模式, 选项, 处理函数)`

> **命令名是全局唯一的。** 两个插件不能注册同名命令，后注册的会直接抛错
> （`命令 "xxx" 已被插件 yyy 注册`）。写插件前先想清楚命名，
> 通用词（`kun`、`shop`、`rank`）容易被别人占用，必要时加自己的前缀。

```js
ctx.command('attack <目标> [次数]', {
  desc: '攻击目标',
  usage: '/attack <目标> [次数]',   // 可选，默认由模式生成
  admin: false,                      // true = 需要本作用域管理员（≤1）
  globalAdmin: false,                // true = 需要全局管理员（≤1），用于影响全局的操作
}, async (msg, { args, raw }) => {
  const [目标, 次数 = 1] = args;
});
```

**模式语法**（只影响帮助展示与必填校验）：

| 写法 | 含义 |
|------|------|
| `attack` | 命令名，无参数 |
| `<目标>` | 必填参数；缺了内核会自动回复用法 |
| `[次数]` | 可选参数 |
| `<内容...>` | 必填，吃掉剩余全部内容 |

- 命令名取模式串的**第一个词**，大小写不敏感
- 实际参数通过 `msg.args` 数组拿（按空白切分），**模式里的名字只是提示**
- 需要保留空格原文时用 `msg.content`

**命令名冲突**：同名命令后注册的会抛错，`/plugins` 能看到是哪个插件报的。

### 5.2 `ctx.on(事件名, 处理函数)`

```js
ctx.on('message', async (msg) => { ... });          // 所有消息（命令除外）
ctx.on('GROUP_AT_MESSAGE_CREATE', async (msg) => { ... });  // 仅群 @
ctx.on('GROUP_ADD_ROBOT', async (d) => { ... });    // 机器人被拉进群
```

可用事件名见 [§8](#8-可用事件名)。

> 注意：`GROUP_MESSAGE_CREATE` 可能是**全量群消息**，不只是 @ 机器人的。
> 内核不会提前过滤，而是全部交给插件判断，**没人回应才丢弃**。

**分发顺序**（重要）：

1. 是命令且已注册 → **只**执行该命令的处理函数，不再触发监听
2. 是命令但未注册 → 回复「没有这个命令」
3. 不是命令 → 依次触发 `message` 监听、再触发原始事件监听
4. **没有任何监听者回应 → 判定为噪音，静默丢弃**

### 怎么表达「这条消息我处理了」

两种方式，满足任一即可：

```js
// 方式一：发消息（reply / push / replyImage 等都算）
ctx.on('message', async (msg) => {
  if (msg.content === '打卡') await msg.reply('打卡成功');
});

// 方式二：显式 return true（适合你不想回复、但想占用这条消息的场景）
ctx.on('message', async (msg) => {
  if (msg.content.startsWith('【系统】')) return true; // 吞掉，不回复
});
```

**这决定了要不要加 `msg.mentioned` 判断**：

- 做「被动关键词」玩法（不 @ 也能触发）→ 不要判断 `mentioned`，直接匹配关键词
- 做「主动搭话」（有人 @ 才接话）→ 先 `if (!msg.mentioned) return;`，否则群里聊到相关词就会插嘴

```js
ctx.on('message', async (msg) => {
  if (msg.isCommand) return;          // 命令已由命令路由处理
  if (!msg.mentioned) return;         // 没 @ 就闭嘴
  if (msg.content.includes('你好')) await msg.reply('你好呀');
});
```

### 5.3 `ctx.storage`

插件私有键值存储，落盘到 `data/bots/<机器人id>/plugins/<id>.json`，300ms 防抖写入。

```js
await ctx.storage.set('user:123', { level: 5 });
const u = await ctx.storage.get('user:123', { level: 1 });  // 第二个参数是默认值
await ctx.storage.delete('user:123');
const all = await ctx.storage.all();   // 整个命名空间
```

- 键名建议加前缀：`user:<id>`、`group:<id>`、`global:xxx`
- **不要在每次读写时 `all()` 全量遍历**，数据大了会很慢
- 数据量超过几千条、需要查询/事务时，插件里直接引 SQLite，不要硬塞 JSON

#### 改数据必须用 `update()`，别自己 get → 改 → set

```js
// ✗ 并发下会丢更新
const p = await ctx.storage.get('user:123');
p.points += 10;
await ctx.storage.set('user:123', p);

// ✓ 同一个 key 串行执行，不丢
await ctx.storage.update('user:123', (p) => {
  const cur = p ?? { points: 0 };   // key 不存在时 p 是 undefined
  cur.points += 10;
  return cur;                        // 返回新值；返回 undefined/null 表示不写入
});
```

**为什么**：玩家连发两条命令时，两个 handler 可能都读到同一份旧数据，
后写入的会把前一条的结果盖掉。`update()` 按 key 排队，保证「读-改-写」是原子的。

返回 `null` 可以中途放弃写入（比如「节操不够」的情况），数据保持原样。

`update()` 只保证**单个 key** 的原子性。要同时改两个玩家的数据（比如 PvP 抢体重），
两次 `update()` 之间仍可能被插队，对游戏类场景通常可以接受。


### 5.9 面板：配置与数据（自动生成）

插件**不需要写任何前端代码**，面板会自动给它生成一个「设置」页，分两个标签：

**配置**：在 `config` 里声明字段，面板按类型渲染控件、保存后立刻生效。

```js
export default {
  id: 'kun',
  // 简写：只有默认值，类型自动推断
  config: { 买蛋价: 80, 开启PvP: true },

  // 完整写法：带说明和可选值
  config: {
    买蛋价: { type: 'number', default: 80, desc: '买一颗蛋要多少节操' },
    难度:   { type: 'select', default: '普通', options: ['简单', '普通', '困难'] },
    规则:   { type: 'json', default: { 上限: 100 } },
  },
};
```

支持的 `type`：`number` / `text` / `boolean` / `select` / `json`。
不写 `type` 就按默认值的类型推断。

**玩家数据**：`ctx.storage` 里的每条记录都会列出来，可以直接改 JSON 或删除。
改完立即生效，不用重载插件。

外部插件（`plugin.json`）同样支持：

```json
{
  "config": {
    "买蛋价": { "type": "number", "default": 80, "desc": "买一颗蛋要多少节操" }
  }
}
```

> 面板接口在 `/api/plugins/<id>/panel`（读）、`/config`（改配置）、`/data`（改存档）。
> 只有能访问面板的人能用——面板默认只监听 127.0.0.1，别对外暴露。

### 5.10 面板：运行数据（插件自定义）

插件想让面板显示自己的指标——「已回复 1234 条」「平均 320ms」「在线玩家 8 人」——
不用写任何前端代码，给一份数据就行。面板会把它渲染成指标卡，插件列表里还会露前 3 个。

**写法一：导出 `dashboard`（每次拉取现算）**

```js
const stats = { replied: 0 };

export default {
  id: 'ai',
  name: 'AI 助手',

  dashboard() {
    return {
      metrics: [
        { label: '已回复', value: stats.replied, unit: '条' },
        { label: '平均耗时', value: 320, unit: 'ms', hint: '最近 100 次' },
      ],
      note: '模型：xxx\n当前队列：0',
    };
  },

  setup(ctx) { /* … */ },
};
```

`dashboard` 也可以是普通对象（静态数据）。

**写法二：`ctx.setDashboard()` 主动推**

数据算不出来（要等外部服务回调、或由子进程上报）时用这个，后推的覆盖先推的：

```js
ctx.setDashboard({ metrics: [{ label: '在线玩家', value: 8, unit: '人' }] });
```

**字段说明**

| 字段 | 说明 |
|---|---|
| `metrics[].label` | 指标名，必填；没有 label 的项会被丢弃 |
| `metrics[].value` | 指标值，数字或字符串；`0` 会正常显示 |
| `metrics[].unit` | 单位，显示在数值右侧 |
| `metrics[].hint` | 补充说明，显示在数值下方 |
| `note` | 一段多行文本，原样显示（等宽字体） |

限制：最多 12 个指标，label 24 字、value 40 字、note 800 字，超长自动截断。
洗不出有效内容就当作「没提供」，面板显示空状态。

**外部插件**（Python / Go）发一条协议消息：

```json
{"t":"dashboard","data":{"metrics":[{"label":"已回复","value":123,"unit":"条"}]}}
```

> 面板每几秒拉一次 `/api/plugins/dashboard`，框架有 1 秒缓存，插件函数不会被轮询打爆。
> 但**别在 `dashboard()` 里做重活**——它是同步渲染路径，卡住会拖慢面板。

### 5.4.1 群管：禁言 / 踢人 / 群成员

`ctx.api` 上有一组群管方法。**禁言是公开接口**，随时可用；
群成员列表、踢人、群黑名单是官方内邀接口，默认关闭。

```js
// 禁言 10 分钟（RFC3339 到期时间）
const until = new Date(Date.now() + 10 * 60 * 1000).toISOString();
await ctx.api.muteMember(msg.groupId, msg.mentions[0].id, until);

// 立即解除
await ctx.api.muteMember(msg.groupId, uid, '');

// 批量：一次最多 20 个
await ctx.api.muteMembers(msg.groupId, [
  { op: 'add', member_openid: uid, mute_expire_at: until },
  { op: 'del', member_openid: uid2, mute_expire_at: '' },
]);

// 查禁言状态
const { mute_list } = await ctx.api.getMuteStatus(msg.groupId);

// 群信息 / 机器人在群内的状态
const info = await ctx.api.getGroupInfo(msg.groupId);
const { is_admin } = await ctx.api.getBotGroupState(msg.groupId);
```

内邀的几个（`getGroupMembers` / `getGroupMember` / `removeMembers` /
`getGroupBlacklist` / `operateGroupBlacklist`）**没开开关时会抛错**，
错误信息会说明去哪开。别默默吞掉：

```js
try {
  const { members, next_index } = await ctx.api.getGroupMembers(msg.groupId, { limit: 30 });
} catch (e) {
  if (/未开启/.test(e.message)) return msg.reply('群管内邀功能没开，面板里打开才能用');
  throw e;
}
```

**框架不核验机器人身份**——「机器人是不是群管理员」由服务端判，
失败返回 `40062003`。要提前知道，可以调 `getBotGroupState()` 看 `is_admin`。

完整的接口清单、频率限制、错误码见
[官方接口限制.md](./官方接口限制.md) 的「群管理接口现状」。

### 5.5 多轮对话：`ctx.prompt`

文字游戏的核心是「问一句、等回答」。官方接口下这本来很难做——每条消息都是独立事件，
没有上下文。`ctx.prompt` 解决了这个问题：

```js
ctx.command('战斗', { desc: '开始战斗' }, async (msg) => {
  const ans = await ctx.prompt(msg, '用哪个技能？\n1 蓝银缠绕\n2 昊天锤');

  if (!ans) return;                    // 超时，prompt 已经替你把提示发出去了
  if (ans.content === '1') { /* ... */ }
  else if (ans.content === '2') { /* ... */ }
  else return msg.reply('没有这个选项');
});
```

**返回值**：用户的下一条消息（完整的 Message 对象），超时返回 `null`。

**选项**：

| 选项 | 默认 | 说明 |
|------|------|------|
| `from` | `'user'` | `'user'` 只认这个人；`'chat'` 这个会话里谁都算（多人共玩的场景） |
| `timeoutMs` | 120 秒 | 等多久 |
| `onTimeout` | 一句默认提示 | 超时后发什么，传 `false` 不提示 |

**关键行为**：

- 等待期间会**自动续上免@窗口**，用户回话不需要再 @ 一次
- 同一个人的等待会被新的覆盖，不会出现「回答被上一条提示吃掉」
- 被等待的消息**不会**再走命令分发——用户回 `1` 不会被当成命令
- 不同会话、不同用户之间完全隔离，不会串台

**注意**：`prompt` 是阻塞的，一次交互会占用这条消息的处理流程。不要在一个命令里
连着 `prompt` 十几次（每次 120 秒），用户会觉得机器人卡死。复杂流程建议把状态存进
`ctx.storage`，用命令推进，而不是一路 `prompt` 到底。

### 5.6 中间件：`ctx.use`

在消息到达你的命令之前插一层逻辑，不调 `next()` 就能把它拦下来：

```js
setup(ctx) {
  // 本群禁言词：命中就吞掉，不回复
  ctx.use('屏蔽词', async (c, next) => {
    if (c.msg.content.includes('广告')) return;
    await next();
  });
}
```

- 中间件只对本插件生效，不影响别人
- 名称会加上插件前缀（`douluo:屏蔽词`），不会冲突
- 插件卸载或重载时自动摘掉
- 中间件里抛错会被内核捕获，跳过该中间件继续往下走，不会吞掉消息

可用的 `c` 字段：`c.msg`（消息对象）、`c.cfg`（机器人配置）、`c.commandEntry`（命中的命令条目，可能为 `null`）。

### 5.7 插件配置：`ctx.config` / `ctx.setConfig`

插件**不要**把可调参数写死在代码里，也不要自己读 JSON 文件。声明一份默认值，内核会替你
生成配置文件、合并用户修改、并保证插件升级后新增的配置项自动出现。

```js
export default {
  id: 'douluo',
  name: '斗罗大陆',

  // 默认值。用户在 config/bots/<机器人id>/plugins/douluo.json 里改，这里不用动
  config: {
    startHp: 100,
    startGold: 10,
    drop: { rate: 0.3, maxLevel: 60 },
  },

  setup(ctx) {
    const hp = ctx.config.startHp;          // 已合并用户的修改
    const rate = ctx.config.drop.rate;

    ctx.command('设置掉率 <值>', { desc: '调整掉落率', admin: true }, async (msg, { args }) => {
      const v = Number(args[0]);
      if (!(v >= 0 && v <= 1)) return msg.reply('掉率要在 0 到 1 之间');
      await ctx.setConfig({ drop: { rate: v } });   // 只改这一项，其余保留
      await msg.reply(`掉率已改为 ${v}`);
    });
  },
};
```

**内核怎么处理**：

| 情况 | 行为 |
|------|------|
| 首次加载，文件不存在 | 按 `config` 生成 `config/bots/<机器人id>/plugins/<id>.json`，用户打开就能看到有哪些项 |
| 文件已存在 | 与 `config` 深合并：**缺失的补上，用户多写的保留** |
| 插件升级加了新配置项 | 下次加载自动写进文件，用户不用手动加 |
| 插件没声明 `config` | 不生成空文件，`ctx.config` 是 `{}` |

**`ctx.setConfig(patch)`**：只改传入的键（深合并），立刻落盘，并原地更新 `ctx.config`，
已经拿到的引用也会跟着变。写失败会抛错，重要配置建议 `try/catch`。

> **不要**把插件配置写进 `data/`。`data/` 是程序写的存档，`config/` 是用户写的设置。
> 分开放是为了备份时能分开搬：带走 `config/` 就是带走全部设置。

### 5.8 第三方依赖：自动安装

插件需要第三方库时，**把依赖声明放在插件目录里**，首次加载会自动装到隔离环境，
不需要用户手动 `pip install`。

**Python 插件** —— 放 `requirements.txt`：

```
plugins/my-plugin/
├── plugin.json
├── main.py
└── requirements.txt     ← 写 requests 之类的包名
```

内核会：建 `plugins/my-plugin/.venv` → 用 venv 里的 pip 装 → 之后一直用 venv 的解释器启动插件。
**不会**碰系统 Python，也不会影响别的插件。

**Node 插件** —— 放 `package.json`：

```json
{ "name": "my-plugin", "dependencies": { "dayjs": "^1.11.0" } }
```

内核会在插件目录里跑 `npm install --omit=dev`。

**幂等**：依赖文件的哈希存进插件目录的 `.deps.json`，内容没变就跳过，不会每次启动都联网。
改了 `requirements.txt` 会自动重装。

**关掉自动安装**：`config/bot.json` 里 `plugins.autoInstallDeps = false`。
关掉后缺依赖只会给一条警告，插件可能起不来——自己装的话装到插件目录的 `.venv` 里。

**装不上时**：内核会把 pip/npm 的原始报错贴出来，并给出手动执行的命令，
不会让你对着「插件加载失败」四个字猜。

## 6. 必须提供菜单（强制要求）

**每个插件都必须让用户能看到它能做什么。** 内核在加载插件后会检查：

- 只要插件注册了命令，或调用过 `ctx.menu()`，就算通过
- 两者都没有 → 日志打 WARN，`/help` 和 `/plugins` 里显示「未提供菜单」

### 命令会自动进菜单

`ctx.command()` 注册的命令会**自动**出现在菜单的「指令」分组里，不用重复声明：

```js
ctx.command('roll [面数]', { desc: '掷一次骰子' }, handler);
// 菜单里自动出现：/roll [面数]  掷一次骰子
```

### 非命令玩法要用 ctx.menu 补

游戏类插件常有「不用斜杠触发」的玩法，或者纯展示的说明，这些要显式补：

```js
ctx.menu('玩法', [
  { text: '攻击',        desc: '对当前目标发起攻击' },
  { text: '直接说「掷骰子」', desc: '不用加前缀也能触发' },
]);

ctx.menu('说明', [
  { text: '每个玩家的数据独立保存' },   // 纯文本条目，不是命令
]);
```

渲染效果（`/help 插件id`）：

```
掷骰子 v1.1.0
演示参数解析、玩家数据持久化与关键词被动触发

【指令】
  /roll [面数]  掷一次骰子，默认 100 面
  /rank  查看掷骰子排行榜（前 5）

【玩法】
  掷骰子  群里直接说这三个字，不用加前缀

【说明】
  每个玩家的次数与最高值单独记录
```

### 条目格式

| 写法 | 含义 |
|------|------|
| `{ cmd: 'roll [面数]', desc: '...' }` | 命令条目，渲染时自动加前缀 `/roll [面数]` |
| `{ text: '攻击', desc: '...' }` | 纯文本条目，原样显示 |
| `'一句说明'` | 纯文本条目，无描述 |

> 用 `cmd` 还是 `text` 的区别只在于**要不要加命令前缀**。
> 已经用 `ctx.command` 注册过的命令不要再写进 `ctx.menu`，会重复。

## 7. Message 对象

| 字段 | 类型 | 说明 |
|------|------|------|
| `msg.id` | string | 消息 id，被动回复必需 |
| `msg.kind` | string | `group` / `c2c` / `guild` |
| `msg.event` | string | 原始事件名 |
| `msg.userId` | string | 发送者 openid |
| `msg.groupId` | string | 群 openid（私聊为空） |
| `msg.chatId` | string | `groupId || userId`，用作会话键最方便 |
| `msg.content` | string | 去掉 @机器人 和前缀后的正文 |
| `msg.args` | string[] | 按空白切分后的参数 |
| `msg.isCommand` | boolean | 是否以命令前缀开头 |
| `msg.command` | string | 命令名（小写） |
| `msg.mentioned` | boolean | 正文里是否 @ 了机器人 |
| `msg.mentions` | `{id, isBot}[]` | 本条消息 @ 了**谁**（已排除机器人自己）。做点名、PvP 直接用 `msg.mentions[0].id` |
| `msg.sticky` | boolean | 本条消息是否因为在免@窗口内才算「对着机器人说」 |
| `msg.addressed` | boolean | **推荐用这个**：`mentioned \|\| isCommand \|\| sticky`，即「这条消息是不是冲着机器人来的」 |
| `msg.receivedAt` | number | 收到这条消息的时间戳，出站调度器用它算 5 分钟窗口 |
| `msg.replied` | boolean | 本条消息是否已经发过回复（内核据此判断有没有人回应） |
| `msg.raw` | object | 官方原始事件体，需要什么取什么 |
| `msg.at` | number | 消息时间戳（毫秒） |

> **`msg.mentioned` 和 `msg.addressed` 的区别**：官方已开放免@唤醒，
> 用户 @ 过一次后，接下来几分钟内不 @ 也算在跟机器人说话。
> 做「主动搭话」时判断 `addressed` 比判断 `mentioned` 更符合用户预期。

### 发送方法

| 方法 | 说明 |
|------|------|
| `msg.reply(text, opts?)` | **被动回复**。会攒着，本次处理结束统一发（见下） |
| `msg.replyNow(text, opts?)` | 绕过合并，立刻发一条 |
| `msg.push(text, opts?)` | **主动推送**，不带 `msg_id`，**消耗每日额度** |
| `msg.replyMarkdown(md, keyboard?)` | Markdown 消息，可带按钮（会先把手头攒的发掉） |
| `msg.replyImage(url)` | 发图片（传 URL，或本地路径配 `{local:true}`） |
| `msg.replyVideo(url)` | 发视频（mp4） |
| `msg.replyVoice(url)` | 发语音（silk） |
| `msg.replyFile(url)` | 发文件（官方暂未开放） |

#### `msg.reply` 会合并，不是立刻发

一条消息可能被多个插件同时回应（命令 + 监听器 + 被动关键词），
逐条发出去会刷屏。所以内核的处理是：

```
收到一条消息
  ├─ 插件A msg.reply('...')  → 攒起来
  ├─ 插件B msg.reply('...')  → 攒起来
  ├─ 插件C msg.reply('...')  → 攒起来
  └─ 处理结束 → 合并成一条发出：「插件A\n插件B\n插件C」
```

所以：

- **不要在 `reply()` 后 `await` 发送结果**，它只返回 `null`，真正的发送在处理结束时才发生
- 需要立刻发（比如要先发一张图、再继续算），用 `msg.replyNow()`
- 超过 1500 字会自动按行拆成多条，不会丢内容
- `ctx.prompt()` 会自动 flush，提示语不会卡在缓冲里

**一次处理只会产生一条文本消息**（除非超长或用了 `replyNow` / 富媒体）。
这既是省额度，也是不让群里刷屏。

富媒体走「先上传拿 `file_info`，再以 `msg_type=7` 发送」，失败只记日志不抛异常。

#### Markdown 与「可点击指令」

群聊和单聊的**自定义 Markdown 已对所有机器人开放，无需申请**（2026-04 官方调整）；
频道仍需内邀。框架把常用能力包成了两个东西：`msg.replyMenu()` 和 `ctx.md`。

```js
// 一行发出带可点击指令的菜单
await msg.replyMenu('养鲲', [
  { title: '日常', items: [
    { text: '/签到', desc: '每天一次' },
    { text: '/kun',  desc: '看看我的鲲' },
  ]},
]);
```

渲染结果（群聊）：

```markdown
# 养鲲

## 日常
- <qqbot-cmd-input text="%2F签到" show="%2F签到" /> 每天一次
- <qqbot-cmd-input text="%2Fkun" show="%2Fkun" /> 看看我的鲲
```

用户点一下，指令就**填进输入框**，自己按发送即可。

需要更自由地拼 markdown 时用 `ctx.md`：

| 成员 | 作用 |
|------|------|
| `ctx.md.cmdInput(text, show?)` | 点击后插入输入框。**群聊只有这个可用** |
| `ctx.md.cmdEnter(text)` | 点击后直接发送。**群聊不支持**，仅单聊/频道 |
| `ctx.md.at(openid)` | @某人 |
| `ctx.md.esc(text)` | 转义 `\` ` * _ ~，拼用户昵称时用 |
| `ctx.md.quote(text)` | 转成引用块 |
| `msg.replyMarkdown({content}, keyboard?)` | 发原始 markdown |
| `msg.replyMenu(title, groups)` | 上面那个菜单渲染器 |

**平台硬限制，踩了会静默失效**：

1. 这两个标签**只能在 markdown 消息里生效**。普通文本消息里会原样显示成
   `<qqbot-cmd-input ... />` 这串东西。
2. `cmd-enter`（点了直接发）**群聊不支持**——所以 `replyMenu` 会自动按会话类型选：
   群聊用 `cmd-input`，单聊/频道用 `cmd-enter`。
3. `text` 和 `show` **必须 urlencode**，最长 100 字符（`ctx.md` 已处理）。
4. markdown **不支持表格和 HTML**。支持：`#`/`##` 标题、`**加粗**`、`_斜体_`、
   `~~删除线~~`、`[链接](url)`、`![图](url)`、有序/无序列表、嵌套、`> 引用`、`***` 分割线。
5. markdown 是独立消息类型，**不参与回复合并**——它会先把手头攒的文本发掉再发自己。

**所有发送都经过出站调度器**，它会自动处理 5 分钟窗口、每秒限速、主动消息额度
（详见 [§16](#16-官方接口限制与平台兜底)）。你不需要自己算时间：

```js
ctx.command('抽卡', { desc: '抽卡（耗时 8 分钟）' }, async (msg) => {
  await msg.reply('抽卡中，稍后把结果发你');
  setTimeout(async () => {
    // 这时早就过了 5 分钟，但不用你操心：
    // 调度器会把它降级成主动消息，额度不够则记日志
    await msg.reply('抽到 SSR 了！').catch(() => {});
  }, 8 * 60 * 1000);
});
```

## 8. 可用事件名

**消息类**（会被规范化成 Message）：

| 事件 | 场景 |
|------|------|
| `GROUP_AT_MESSAGE_CREATE` | 群里 @机器人（官方文档写法） |
| `GROUP_MESSAGE_CREATE` | 群里 @机器人（平台实际下发的事件名，结构相同） |
| `C2C_MESSAGE_CREATE` | 用户私聊机器人 |

**系统类**（回调参数是官方原始 `d` 对象）：

| 事件 | 场景 |
|------|------|
| `GROUP_ADD_ROBOT` | 机器人被拉进群（内核会自动登记群档案并可能认主） |
| `GROUP_DEL_ROBOT` | 机器人被移出群（内核会标记该群为已移出） |
| `FRIEND_ADD` / `FRIEND_DEL` | 加/删好友 |

> 事件能不能收到，取决于连接时订阅的 `intents`。默认 `1 << 25`（群聊 @ + 私聊），
> 需要更多事件时改 `config/bot.json` 的 `intents`，并在开放平台申请对应权限。

## 9. 错误处理

内核在调用你的处理函数时已经包了 `try/catch`：

- 命令抛错 → 日志记录堆栈，并回复「执行出错: xxx」给用户
- 监听器抛错 → 只记日志，不影响其他监听器

**但你仍然要自己做业务级校验**：

```js
ctx.command('buy <物品>', { desc: '购买' }, async (msg, { args }) => {
  const item = SHOP[args[0]];
  if (!item) return msg.reply(`没有「${args[0]}」这个物品`);   // 预期内错误，直接回
  const gold = await getGold(msg.userId);
  if (gold < item.price) return msg.reply('金币不够');
  // ...
});
```

**规范**：

- 用户能看懂的失败 → `msg.reply('...')` 说清楚
- 真正的 bug → 让它抛，内核会记堆栈
- 不要 `catch` 之后什么都不做

## 10. 日志规范

```js
ctx.logger.info(`玩家 ${uid} 升到 ${level} 级`);
```

- 用 `ctx.logger`，不要 `console.log`（否则不带插件前缀，不会进插件日志文件，排查困难）
- 多个参数会用空格拼接：`ctx.logger.warn('掉率异常', rate, uid)`
- 正常流程用 `info`，可疑但可恢复用 `warn`，出错用 `error`
- 高频路径（每条消息都走）用 `debug`，控制台默认不输出，但**会写进日志文件**

### 日志去哪了

插件日志会自动分流到两个文件：

| 文件 | 内容 |
|------|------|
| `logs/bots/<机器人id>/plugins/<id>.log` | **只有**本插件的日志 |
| `logs/bot.log` | 全部日志（本体 + 所有插件），排查跨插件问题时看这个 |

- 文件里一律记 `debug` 及以上，不受控制台 `logLevel` 影响 —— 出问题时能回溯
- 按大小轮转（默认 5 MB），旧的改名成 `.1`，只保留一份历史
- 插件进程的 stderr 也会自动收进它的日志文件，所以外部插件里 `print()` / `sys.stderr` 不会丢

## 11. 性能与约束

| 约束 | 说明 |
|------|------|
| **单进程** | 插件与内核同进程，**禁止死循环、禁止同步阻塞**（`while(true)`、大文件同步读） |
| **长任务要异步** | 处理超过 5 分钟会错过被动回复窗口。调度器会自动降级为主动消息，但主动额度有限，别指望它 |
| **定时任务** | 用 `ctx.schedule`，**卸载时自动清理**，不会出现 reload 后多份在跑 |
| **并发** | 同一用户可能连发多条，写存档要防并发（简单做法：按 userId 串行化） |
| **内存** | 别把整张配置表读进内存反复复制；共享一份只读对象 |

定时任务用 `ctx.schedule`，卸载时会自动清理：

```js
export default {
  id: 'tick',
  setup(ctx) {
    ctx.schedule('heartbeat', 60_000, () => ctx.logger.info('心跳'));

    // 需要手动控制时，返回值是停止函数
    const stop = ctx.schedule('fast', 5_000, () => { /* ... */ });
    // stop();
  },
};
```

> 不要用裸 `setInterval`。虽然 `teardown` 里也能清，但容易漏；
> `ctx.schedule` 会登记到插件生命周期，`/reload` 和 `/disable` 都会自动停掉。

## 12. 权限

权限模型分两个维度：**作用域**决定「在哪管」，**等级**决定「能管谁」。

### 等级

**数字越小权限越高。**

### 等级空间是分区管理的

| 区间 | 归属 | 说明 |
|------|------|------|
| 0 – 3 | **内核独占** | 主人 / 管理员 / 群管 / 助手，插件只能读（`ctx.CORE_LEVELS`），不能改语义 |
| 4 – 9 | 内核预留 | 以后加「超管」「审计」不用重排 |
| 10 – 998 | **插件区** | 主程序启动时按插件 id 排序，**每个插件分 10 个号位** |
| 9999 | 无权限 | 普通成员 |

号段分配示例（按 id 字典序）：

```
dice   10-19
echo   20-29
game   30-39
```

**为什么按 id 排序**：目录读取顺序不保证稳定，如果按加载顺序分配，重启后号段会漂移，
用户已经配好的权限就对不上了。按 id 排是确定性的，同一插件永远拿到同一段。

### 插件怎么用自己的等级

```js
setup(ctx) {
  // 只写偏移量，主程序自动加上本插件号段的起点
  const L = ctx.defineLevels({
    管理员: 0,   // dice → 10
    玩家: 2,     // dice → 12
  });

  ctx.command('reset', { desc: '清空排行榜' }, async (msg) => {
    if (!(await ctx.can(msg, L.管理员))) {
      return msg.reply(`需要本插件管理员（等级 ${L.管理员}）`);
    }
    // ...
  });
}
```

`ctx.defineLevels` 会自动在菜单里加一个「权限等级」分组，用户 `/help 插件id` 就能看到怎么授权。

也可以直接用底层方法：

| 成员 | 说明 |
|------|------|
| `ctx.levelBase` | 本插件号段起点，如 `10` |
| `ctx.levelRange` | `{ base: 10, end: 19 }` |
| `ctx.level(n)` | 号段内第 n 档，`ctx.level(0)` 是最高权限 |
| `ctx.CORE_LEVELS` | 内核等级常量（只读）：`{ owner:0, admin:1, manager:2, helper:3 }` |

### 等级表

| 等级 | 值 | 说明 |
|------|----|------|
| 主人 | 0 | 只来自 `config/bot.json` 的 `owners`，命令不能授予 |
| 管理员 | 1 | 可授予 2 及以上 |
| 群管 | 2 | 可授予 3 及以上 |
| 助手 | 3 | 可授予 4 及以上 |
| 插件区 | 10 ~ 998 | 由插件自己定义，主程序分配号段 |
| 无权限 | 9999 | 默认 |

**核心规则：只能授予数字更大的等级。** 也就是只能给比自己权限低的人授权，
同级和更高权限都改不了。

### 作用域

| 写法 | 含义 |
|------|------|
| `global` | 全局 |
| `group:<群openid>` | 某个群 |
| `channel:<频道id>` | 某个频道 |
| `user:<用户openid>` | 某人的私聊 |
| `feature:<插件id>` | 某个功能的管理权 |

**有效等级 = min(全局, 当前会话, 本插件)**（取数字最小的）。

`ctx.levelOf(msg)` 会同时看三个作用域，取最优：
- 全局 `global`
- 当前会话 `group:xxx` / `channel:xxx`
- 本插件 `feature:<id>`

所以「群主」和「只被授予本插件权限的人」都能通过插件自己的检查，
无关的人拿到的还是 9999。

### 一个人可以在多个插件里有不同等级

每个插件的权限存在自己的 `feature:<id>` 作用域里，互不干扰：

```
group:xxx      群管 2
feature:dice   10   ← 掷骰子的管理员
feature:echo   20   ← 回声里只是普通成员
```

`dice` 里的检查只看 `feature:dice`（以及全局/会话），拿不到 `echo` 的等级。
想查某人的全部权限用 `/admin whois <openid>`。

### 插件里怎么用

```js
ctx.command('kick <openid>', { desc: '踢人' }, async (msg, { args }) => {
  if (!(await ctx.can(msg))) return msg.reply('需要管理员权限');   // 默认 1
  if (!(await ctx.can(msg, 'manager'))) return;                    // 指定 2
  // ...
});

// 拿到具体数字做更细的判断（越小权限越高）
const lv = await ctx.levelOf(msg);
if (lv <= 1) { /* 管理员及以上 */ }
if (lv === 9999) { /* 无权限 */ }

// 当前作用域
const scope = ctx.scopeOf(msg); // group:xxx / channel:xxx / user:xxx
```

### 命令选项

| 选项 | 含义 |
|------|------|
| `admin: true` | 需要**当前作用域**管理员（≤1）及以上 |
| `globalAdmin: true` | 需要**全局**管理员（≤1），用于影响全局的操作（如启停插件） |

```js
ctx.command('purge', { desc: '清理本群数据', admin: true }, handler);
ctx.command('shutdown', { desc: '全局停机', admin: true, globalAdmin: true }, handler);
```

### 谁来配置

- 聊天里：`/admin set <openid> <等级数字> [作用域]`，上级设下级（只能设数字更大的）
- 群主/邀请机器人入群的人，会自动获得**该群**的管理员（1 级），不会变成全局主人
- 面板「权限」页可可视化增删

## 13. 发布规范

一个可分发的插件目录应该长这样：

```
plugins/group-guard/
├── index.js
├── README.md          说明功能、命令、配置项
└── data/              静态资源（可选）
```

**要求**：

1. `index.js` 里 `version` 必须是语义化版本，改行为就升版本
2. `README.md` 必须列出：所有命令、所需权限、数据存哪、是否有定时任务
3. 需要第三方库就**声明依赖**（`requirements.txt` / `package.json`），首次加载会自动装到插件目录里（见 §5.8）。
   **不要**假设用户已经全局装好了某个包
4. 不要在 `setup` 里做网络请求等慢操作，会拖慢启动——需要预热就异步做
5. 不要读写其他插件的配置、日志、存档文件
6. 可调参数写进 `config`，不要写死在代码里；用户改配置不需要改代码

## 14. 完整示例：游戏插件骨架

```js
// plugins/douluo/index.js
const CONFIG = {
  startHp: 100,
  startGold: 10,
};

export default {
  id: 'douluo',
  name: '斗罗大陆',
  version: '0.1.0',
  description: '文字游戏示例：注册角色、打怪、看属性',

  async setup(ctx) {
    // 读玩家存档
    const load = async (uid) =>
      (await ctx.storage.get(`user:${uid}`)) ?? null;
    const save = (uid, p) => ctx.storage.set(`user:${uid}`, p);

    ctx.command('注册 [名字]', { desc: '创建角色' }, async (msg, { args }) => {
      const uid = msg.userId;
      if (await load(uid)) return msg.reply('你已经有角色了，发 /属性 查看');

      const player = {
        name: args[0] ?? `魂师${uid.slice(-4)}`,
        level: 1,
        hp: CONFIG.startHp,
        maxHp: CONFIG.startHp,
        gold: CONFIG.startGold,
        createdAt: Date.now(),
      };
      await save(uid, player);
      await msg.reply(`角色创建成功：${player.name}\n生命 ${player.hp}，金币 ${player.gold}`);
    });

    ctx.command('属性', { desc: '查看自己的角色' }, async (msg) => {
      const p = await load(msg.userId);
      if (!p) return msg.reply('还没有角色，先发 /注册');
      await msg.reply(
        `【${p.name}】Lv.${p.level}\n生命 ${p.hp}/${p.maxHp}\n金币 ${p.gold}`,
      );
    });

    ctx.command('打怪', { desc: '打一只魂兽' }, async (msg) => {
      const uid = msg.userId;
      const p = await load(uid);
      if (!p) return msg.reply('还没有角色，先发 /注册');
      if (p.hp <= 0) return msg.reply('你已阵亡，发 /复活 恢复');

      const dmg = 5 + Math.floor(Math.random() * 10);
      const hurt = Math.floor(Math.random() * 8);
      p.hp = Math.max(0, p.hp - hurt);
      p.gold += 3;
      if (p.hp === 0) p.level = Math.max(1, p.level); // 简化：不掉级
      await save(uid, p);

      await msg.reply(
        `你造成 ${dmg} 点伤害，受到 ${hurt} 点伤害\n生命 ${p.hp}/${p.maxHp}，金币 ${p.gold}`,
      );
    });

    ctx.command('复活', { desc: '恢复满血' }, async (msg) => {
      const p = await load(msg.userId);
      if (!p) return msg.reply('还没有角色');
      p.hp = p.maxHp;
      await save(msg.userId, p);
      await msg.reply(`已复活，生命 ${p.hp}/${p.maxHp}`);
    });

    // 入群欢迎：演示系统事件监听
    ctx.on('GROUP_ADD_ROBOT', async (d) => {
      ctx.logger.info('被拉进群', d.group_openid);
    });
  },

  teardown() {
    // 清理定时器 / 关闭连接
  },
};
```

## 16. 官方接口限制（插件视角）

完整清单、原理和排查方法见 **[官方接口限制.md](官方接口限制.md)**。这一节只讲
**写插件时要知道的部分**。

### 这些限制不用你管

| 官方限制 | 内核已经处理 |
|----------|--------------|
| 被动回复 **5 分钟**有效期 | 超过 4 分 45 秒自动降级为主动消息 |
| 同一会话 **每秒 5 条** | 按会话排队，超出自动等待 |
| 必须 WebSocket 在线才能发 | 离线直接拒发，不产生无效请求 |
| 主动消息返回 `304023`（审核中） | 识别为 `pending`，**不当失败** |
| 同一条消息被重复投递 | 按 `msg.id` 去重，窗口 120 秒 |
| 命令被刷屏 | 每会话每分钟限流 + 命令冷却 |

所以你正常 `await msg.reply(...)` 就行，不用算时间、不用自己排队。

### 这两个要你管

**主动消息额度**：默认每会话每天 20 条，用完就发不出去。定时推送前先查：

```js
if ((await ctx.quotaLeft(msg.chatId)) <= 0) {
  ctx.logger.warn('今日主动额度已用完，跳过推送');
  return;
}
await ctx.push(msg.chatId, '每日提醒');
```

**发送失败的错误码**：`SendError` 带 `code`，据此决定要不要提示用户。

| `code` | 含义 | 建议 |
|--------|------|------|
| `offline` | 机器人没连上 QQ | 记日志，别重试 |
| `expired` | 超窗且额度用完 | 告诉用户「稍后 @ 我一次」 |
| `quota` | 主动额度用完 | 同上 |

```js
import { SendError } from '../../src/outbound.js';

try {
  await ctx.push(groupId, '每日提醒');
} catch (e) {
  if (e instanceof SendError && e.code === 'quota') {
    ctx.logger.warn('今日主动额度已用完，跳过');
  } else throw e;
}
```

### 免@粘性会影响你的玩法设计

用户 @ 过一次后，该会话 180 秒内不 @ 也算「在跟机器人说话」。**粘性按会话算，不是按人算**：

```
用户 A: @机器人 开始游戏     ← mentioned=true，开启本会话免@窗口
用户 A: 攻击                ← 没 @，但窗口内 → addressed=true
用户 B: 今天吃啥             ← 也在窗口内 → addressed=true（同样会传给插件）
```

做「主动搭话」类玩法时，除了 `msg.addressed`，最好再确认是不是同一个人：

```js
const lastPlayer = await ctx.storage.get('global:lastPlayer');
if (!msg.addressed) return;
if (msg.userId !== lastPlayer) return;   // 不是正在玩的人，别接话
```

想彻底关掉粘性：`config/bot.json` 里把 `session.stickySec` 设为 `0`。

### 做不到的事

官方**没有开放**「查询机器人所在群列表」和「用户 QQ 号」。这些不要向用户承诺，
也不要试图用其他接口绕——绕不过去。

群管理（禁言 / 撤回他人消息）**已经开放**，但要求机器人是群管理员；
群成员列表、踢人、群黑名单还在内邀。详见
[官方接口限制.md](./官方接口限制.md) 的「群管理接口现状」。
