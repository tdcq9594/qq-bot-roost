# 官方接口限制与应对

用 QQ 官方接口而不是第三方协议（OneBot 那类），换来的是合规和稳定，代价是一堆硬限制。
这份文档说明**哪些限制内核已经替你处理了**、**哪些只能绕**、**哪些根本做不到**。

---

## 一、已被内核兜底的

插件和业务代码都不用关心这些，`msg.reply()` 照常调即可。

| 官方限制 | 数值 | 内核怎么处理 |
|----------|------|--------------|
| 被动回复有效期 | **5 分钟** | 发送前查消息年龄，超过 4 分 45 秒自动降级为主动消息 |
| 同一会话发送频率 | **每秒 5 条** | 按会话排队，默认压到 4 条/秒留余量 |
| 主动消息额度 | **每会话每天 20 条** | 本地记账落盘 `data/bots/<机器人id>/quota.json`，用完抛 `quota` 错误 |
| 必须 WebSocket 在线才能发 | — | 离线时直接拒发，不浪费一次网络请求 |
| 主动消息需审核 | 返回 `304023` | 识别为 `pending`，**不当失败** |
| 同一条消息被重复投递 | — | 按 `msg.id` 去重，窗口 120 秒 |

具体实现在 `src/outbound.js`。发送失败抛 `SendError`，带 `code` 字段：

| `code` | 含义 | 建议处理 |
|--------|------|----------|
| `offline` | 机器人没连上 QQ | 记日志，别重试 |
| `expired` | 超窗且主动额度用完 | 告诉用户「稍后 @ 我一次」 |
| `quota` | 主动额度用完 | 同上 |

```js
import { SendError } from '../../src/outbound.js';

try {
  await ctx.push(groupId, '每日提醒');
} catch (e) {
  if (e instanceof SendError && e.code === 'quota') {
    ctx.logger.warn('今日主动额度已用完，跳过');
  } else throw e;
}
```

## 二、官方没开放、只能绕的

| 能力 | 现实情况 | 应对 |
|------|----------|------|
| **群列表** | 确实没有「查询机器人所在群」的接口（21 个群接口里没有这个） | 靠 `GROUP_ADD_ROBOT` 和消息事件被动发现，内核自动登记到「群组」页 |
| **用户 QQ 号** | openid 不可读，且每个机器人下同一用户的 openid 都不同 | 用 `msg.userName` 显示昵称 |
| **必须 @ 才能触发** | 官方已全量开放免@唤醒，但受群设置和机器人权限影响 | 内核做「免@粘性」兜底，见下 |

> 群管理（禁言 / 踢人 / 群成员）**不是没开放**，而是分批开放。详见下一节，
> 这份文档早期写的「踢人 / 禁言 / 撤回他人消息明确未开放」已经过时。

## 二·补、群管理接口现状（2026-10-23 核对）

官方群聊管理接口一共 21 个，分三档状态。**别再说「官方没给」**——
被内邀卡住的只是群成员那几个，禁言和撤回早就能用了。

### 已开放，可以直接用

| 接口 | 方法 | 路径 | 频率限制 |
|------|------|------|----------|
| 获取群基本信息 | GET | `/v2/groups/{group_openid}/info` | 30 QPM |
| 获取机器人群内状态 | GET | `/v2/groups/{group_openid}/bot_state` | — |
| 查询群禁言状态 | GET | `/v2/groups/{group_openid}/restrict_chat_setting` | — |
| **设置群成员禁言** | POST | `/v2/groups/{group_openid}/restrict_chat_setting` | 60 QPM |
| **撤回群聊消息** | DELETE | `/v2/groups/{group_openid}/messages/{message_id}` | 10 QPS |
| 入群申请列表拉取 | GET | `/v2/groups/{group_openid}/join_request_list` | — |
| 入群申请审批 | POST | `/v2/groups/{group_openid}/approval_join_request/{member_openid}` | — |
| 入群自动审批策略（增删改查 / 执行 / 白名单） | 多个 | `/v2/groups/join_approval_strategy...` | — |

**禁言的硬约束**（`restrict_chat_setting`）：

- 机器人**必须拥有群管理员身份**，否则 `40062003 无操作权限`
- 最长禁言 **30 天**；到期时间用 RFC3339，如 `2026-08-05T11:23:05+08:00`
- 单次最多 **20 个**成员，通过 `op` 控制：`add` 增加 / `update` 改到期时间 / `del` 解除
- **只能操作普通成员**，群主、管理员、机器人都不能动

```json
POST /v2/groups/{group_openid}/restrict_chat_setting
{
  "members": [
    { "op": "add", "member_openid": "EC58...", "mute_expire_at": "2026-08-05T11:23:05+08:00" }
  ]
}
```

**撤回的硬约束**：

- 发送超过 **2 分钟**的消息不可撤回（`40064004`）
- 机器人是**群管理员**时，可以撤回自己的消息**和普通群成员的消息**；
  是普通成员时只能撤回自己发的
- 群成员的消息 ID 从 `GROUP_AT_MESSAGE_CREATE` / `GROUP_MESSAGE_CREATE` 事件的 `d.id` 取
  自己发的消息 ID 从发送接口的响应里取

> 撤回这条内核封装了（`retractGroupMessage`），但**只做了裸请求，没有预检**——
> 2 分钟时限和群管理员身份都是服务端判，失败了看错误码：`40064004` 超时、
> `40062003` 无权限。

### 内邀中，普通机器人调不通

页面明确标注「该能力正在内邀接入中，敬请期待」，调了会返回 `11253 应用无接口访问权限`：

| 接口 | 方法 | 路径 |
|------|------|------|
| 获取群成员列表 | GET | `/v2/groups/{group_openid}/members` |
| 获取群成员信息 | GET | `/v2/groups/{group_openid}/members/{member_openid}` |
| 群成员批量移除（踢人） | POST | `/v2/groups/{group_openid}/batch_remove_members` |
| 群黑名单查询 / 操作 | GET / POST | `/v2/groups/{group_openid}/member_blacklist` |

群成员列表每次最多返回 30 条、支持分页；批量移除单次最多 20 个、可同时加入黑名单。
要这些能力得找平台运营申请白名单。

**所以「群成员列表」的应对仍然有效**：只能记录发过言的人，主动授权用 `/admin set <openid>`。

### 内核目前没封装的

上面这些接口 `src/api.js` 里只封装了撤回（`retractGroupMessage`）。
禁言、群信息、入群审批都还没包，而 `QQApi` 的 `#request` 是私有的，
插件**没法自己发请求**——要先用得先在 `src/api.js` 补公开方法，例如：

```js
// src/api.js
async muteMembers(groupOpenid, members) {
  return this.#request('POST', `/v2/groups/${groupOpenid}/restrict_chat_setting`, { members });
}
```

## 三、免@粘性怎么工作

用户 @ 过一次后，该会话在 `session.stickySec`（默认 180 秒）内，
即使不 @ 也算「在跟机器人说话」。

```
用户 A: @机器人 开始游戏     ← mentioned=true，开启本会话 180 秒免@窗口
用户 A: 攻击                ← 没 @，但窗口内 → sticky=true, addressed=true
用户 B: 今天吃啥             ← 也在窗口内 → addressed=true（同样会传给插件）
```

**粘性按会话算，不是按人算**。最后一行是关键：同一个群里别人说话也会被标记成 `addressed`。

所以做「主动搭话」类玩法时，除了 `msg.addressed`，最好再确认是不是同一个人：

```js
const lastPlayer = await ctx.storage.get('global:lastPlayer');
if (!msg.addressed) return;
if (msg.userId !== lastPlayer) return;   // 不是正在玩的人，别接话
```

想关掉粘性：`config/bot.json` 里 `session.stickySec = 0`。

## 四、事件名的一个坑

官方文档写的是 `GROUP_AT_MESSAGE_CREATE`，但平台实际下发的是 **`GROUP_MESSAGE_CREATE`**
（推测是新增的「全量群消息」事件，或新版事件名）。两者载荷结构一致，代码里都认。

`GROUP_MESSAGE_CREATE` 有可能是**群里所有消息**而不只是 @ 机器人的。
内核的处理方式是「**先给插件机会，没人理才丢弃**」：

1. 群消息一律先登记群档案
2. 命令（带前缀）走命令路由
3. 其余消息全部交给插件的 `message` 监听
4. 有插件回应了（发了消息，或 `return true`）→ 这条消息就算被消费
5. 没有任何插件回应 → 判定为噪音，静默丢弃，不产生任何输出

这样既能让「掷骰子」「打卡」这类关键词玩法在不 @ 的情况下生效，
也不会让机器人对群里每句话都插话。

> 插件想表达「这条我管了」有两种方式：调用 `msg.reply()` 等发送方法，
> 或者处理函数 `return true`。

## 五、实现要点（对照官方文档）

| 环节 | 实现 |
|------|------|
| 获取凭证 | `POST /app/getAppAccessToken`，`{appId, clientSecret}` |
| 鉴权头 | `Authorization: QQBot {access_token}` |
| 提前刷新 | 有效期 7200s，提前 120s 刷新；401 强制刷新重试一次 |
| 网关 | `GET /gateway/bot` → `wss://...` |
| 握手 | `op10 Hello` → `op2 Identify`（`token: "QQBot xxx"`） |
| 心跳 | 按 `heartbeat_interval` 发 `op1`，带最新 `s` |
| 断线 | 指数退避，有 session 走 `op6 Resume` 补事件 |
| 发群消息 | `POST /v2/groups/{group_openid}/messages` |
| 发私聊 | `POST /v2/users/{openid}/messages` |
| 富媒体 | `POST /v2/{groups,users}/.../files`，`file_type` 1图 2视频 3语音 4文件 |
| 被动回复 | 带 `msg_id`，`msg_seq` 同一 msg_id 递增 |
| 群禁言 | `GET/POST /v2/groups/{group_openid}/restrict_chat_setting`，需群管理员身份，最长 30 天 |
| 撤回群消息 | `DELETE /v2/groups/{group_openid}/messages/{message_id}`，2 分钟内，群管理员可撤普通成员 |
| 群基本信息 | `GET /v2/groups/{group_openid}/info`（未封装） |
| 群成员列表 / 踢人 / 黑名单 | **内邀中**，普通机器人返回 `11253` |
| 默认 intents | `1 << 25` = `GROUP_AND_C2C_EVENT` |

## 六、其他已知限制

- **群主识别**：消息报文里 `author.member_role` 为 `owner` 的就是群主（只授予该群管理员），
  机器人收到该人消息时会自动记下来，比「谁邀请机器人」更准。没发过言的群主识别不到。
- **单进程**：插件与内核同进程，插件里写死循环会拖垮整个机器人。后续可换 `worker_threads`。
- **频道消息只收不发**：`guild` 场景没接 v2 发送接口，主要面向群聊/私聊。
- **未做分片**：单连接够用；进几千个群再考虑 `shard`。
- **存储是 JSON**：适合中小规模。大型游戏存档建议插件里直接接 SQLite。
- **面板无登录态**：只有访问密钥校验，没有会话。别直接暴露到公网。
