# 斗罗插件 · 优化建议

> 状态：**分析稿，未改任何代码**。
> 基线：86 个动词 / 90 条命令 / 22 张内容表 / 14 个运行时表。
> 判断标准：**对「群里玩 7 天」这个目标，哪一条最影响留存**，而不是哪一条听起来先进。

---

## 先说结论

现在的功能面已经不缺了（同类插件有的我们都有，而且结构更干净）。
**缺的不是功能，是三件事**：

1. **首小时体验**：新玩家要点十几次指令才看到"成长"，中途就走了
2. **操作疲劳**：一场战斗 4 条消息 4 次操作，群里刷屏
3. **数值护栏**：改一个系数可能让 100 级玩家 1 回合秒怪，而没人会发现

下面按 P0 / P1 / P2 排。

---

## P0 · 直接影响留存（建议先做这四条）

### 1. 战斗批量结算：`自动` / `连击 <次数>`

**问题**：现在每回合一条消息。4 回合战斗 = 4 次 `攻击` + 4 条消息。群里三个人同时打怪就是 12 条。

**现代做法**：AFK 类游戏（《剑与远征》《放置奇兵》）默认自动战斗，玩家只在**需要决策时**才被打断。

**具体建议**：
- 加 `自动`：连续普攻直到怪死 / 玩家血低于 30% / 回合数到上限，**合并成一条消息**
- 保留 `攻击`（想手动的人还在）
- 自动时若玩家血低于阈值，自动切 `防御` 并提示"要不要用药"
- 实现上 `resolveRound()` 已经是纯函数，循环调用即可，改动集中在一个新指令

**收益**：消息量降 70%，操作量降 70%。这是当前性价比最高的一条。

---

### 2. 新手 3 步引导

**问题**：`开始穿越` → `属性` → `魂兽` → `挑战魂兽` → `攻击`×4 → `附加魂环`。
玩家要**自己想到**下一步。我们在 `属性` 末尾写了"下一步"，但新号不会先发 `属性`。

**现代做法**：首局强制引导（《原神》元素教学、《明日方舟》第一关）。

**具体建议**：
- 建号成功后**直接进第一场战斗**（送一只弱怪，自动结算），一次性让玩家看到"打怪→掉环→变强"
- 建号那条消息里就带可点击的「打第一只怪」
- 前 3 次击杀给双倍经验（`newbie_bonus_kills`），让第一次升级发生在 2 分钟内

**收益**：首小时流失是文游最大漏斗，这一步比加十个系统都值。

---

### 3. 数值体检（模拟器）

**问题**：`cfg` 里 30 多个系数，运营改一个（比如 `attr_to_damage_div`）就可能让曲线崩掉。
现在**没有任何检测手段**，只能靠玩家反馈。

**现代做法**：策划必带平衡模拟（TTK 曲线、胜率矩阵）。

**具体建议**：面板加「数值体检」页
- 对每只魂兽 × 每个等级段（1/10/20/…/90）模拟 1000 场
- 输出：**实际回合数分布**（对比 `target_rounds`）、玩家胜率、TTK 曲线
- 偏离目标 ±2 回合就标红
- 改完系数点一下就能看，不用进游戏

**为什么我们特别适合做**：`engine/battle.js` 的 `resolveRound()` 是纯函数、`rng` 可注入。
别人要重构才能测，我们直接调就行。这是**架构红利**，不用掉可惜。

---

### 4. 邮件系统（奖励兜底）

**问题**：现在奖励直接进背包/钱包。玩家下线时被发奖（任务完成、拍卖成交、月卡），
**他不会知道**，也看不到"我为什么多了 500 魂币"。

**现代做法**：所有非即时奖励走邮件（《魔兽世界》《原神》都这样），带有效期。

**具体建议**：
- 一张 `mail` 表（openid, title, body, attachments, read, expire_at）
- `发放` / 拍卖成交 / 月卡 / 任务奖励 → 走邮件
- 上线时提示"你有 3 封未读邮件"
- 面板能看到"这个玩家收到过什么"（现在只能看 tx_log，没有"为什么"）

**收益**：解决"奖励发了玩家不知道"，也给了运营一个补偿渠道（出错时补发）。

## P1 · 长线留存（做完 P0 再做）

### 5. 日常 / 周常 / 赛季

**现状**：`quest` 表是静态的（2 条主线），`签到` 只有一个档，`排位` 不重置。

**建议**：
- 任务加 `kind: daily/weekly`，每日从池子抽 3 条（`quest_pool` + 每日种子）
- 排位加 `season` 表，赛季结束按分段发奖并**软重置**（分数 ×0.5）
- 通行证先不做——文游的通行证需要"在线时长"数据，我们还没有

### 6. 关系要有实际收益

**现状**：情侣/师徒只是记录，没有加成。玩家没有动力去建立关系。

**建议**：
- 情侣同时在线打怪 → 双方 +10% 经验（`couple_exp_bonus`）
- 师徒：徒弟升级时师父得经验（`apprentice_levelup_exp`）
- 这些都能接进现有的 `mods()` / `gainExp()`，不用新表

### 7. 内容批量编辑

**现状**：22 张表只能一行一行点。迁 29 个 INI 时会疯。

**建议**：
- 面板加「导入 / 导出 JSON」，按表导出、整表覆盖导入（带校验和预览）
- 「从 CSV 粘贴导入」——策划手里多半是表格
- `content_meta.pack` 已经有版本号字段，可以拿来做"内容包升级"

### 8. 上下文指令提示

**现状**：86 个动词，新玩家不知道 `打环`、`配方` 存在。

**建议**：
- 战斗中只显示战斗相关指令（`攻击/魂技/防御/逃跑`）
- 菜单按等级过滤未解锁项（等级到了才出现 `宗门`、`斗魂`）
- `帮助 <关键词>` 支持模糊搜索

## P2 · 功能补全（同类有，我们还没有）

| 缺什么 | 说明 | 优先级理由 |
|---|---|---|
| **副本 / 组队** | 麒麟有「副本」，多打怪共享掉落 | 群里社交的核心场景，但要做队伍状态机，成本高 |
| **玩家间直接交易** | 现在只有拍卖（有手续费） | 拍卖已覆盖 80% 需求，直接交易容易出诈骗纠纷 |
| **世界 BOSS** | `monster.tier='boss'` 已有，但没有全服事件 | 需要"全服共享血量"，是很好的社群事件 |
| **离线收益** | 只有领地挖矿 | 文游玩家习惯挂机，缺这块会流失 |
| **成就 / 图鉴** | 称号是静态表，图鉴只有集卡 | 收集感是长线动力，但要有足够内容量才有意义 |
| **仓库** | 没做 | 背包无上限，加仓库等于凭空造限制，不建议做 |

## 技术债（不影响玩法，但影响后续速度）

| 问题 | 现状 | 建议 |
|---|---|---|
| `handlers.js` 2000+ 行 | 86 个处理器挤在一个文件 | 按域拆成 `cmd/char.js` `cmd/battle.js` `cmd/econ.js` `cmd/social.js` |
| 86 条框架命令 | `/help` 会很长 | 保留高频 30 个注册为命令，其余只走前缀 |
| `recalc()` 调用点分散 | 发装备/伙伴/升级/卸装都要记得调 | 已在 `grant*` 里补上；建议统一到「写 player 表后必调」的封装 |
| 无 `battle` 恢复提示 | 有进行中的战斗，玩家不知道 | 上线/发任意指令时提示"你还有一场没打完" |

---

## 如果只做一件事

**做第 1 条（战斗批量结算）**。

理由：它同时解决"群里刷屏"和"操作疲劳"两个最痛的问题，
改动集中（一个指令 + 复用 `resolveRound`），当天能验证，
而且**不引入任何新系统**——纯体验优化，风险最低。
