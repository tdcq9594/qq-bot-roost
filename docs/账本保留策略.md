# 账本保留策略：默认永久 + 面板手动管理

> 2026-11-05 设计稿。起因：用户问「账本能不能也改成不删，然后在面板里管理删除」。
> 状态：**方案已定，未写代码。**
>
> **2026-11-05 决定**：默认改为**永久保留**（`retentionDays: 0`），
> 面板提供「自定义 / 7 天 / 30 天 / 永久」四档。

---

## 一、这条决定改掉了一条既有承诺

7 天原本不是随手定的数字，代码和文档都把它写成了**隐私设计**：

- `src/config.js:258`：「保留期也短得多——**全文落库是隐私成本**，只留够做上下文和幂等的窗口即可，
  长期记忆的证据由 dsh-roost 的 journal 自己留快照。」
- `docs/地基三块方案.md:138`：「**③ 保留策略：events 一律 7 天滚动删，证据由 B 侧自己留**」

用户已经决定改掉它，所以这不是「悄悄改个默认值」，是**改一条对用户做过的承诺**。
由此定三条规矩：

1. **四处必须同步改**，不能只改代码：`src/config.js` 的注释、
   `docs/地基三块方案.md:138`、README 的隐私说明、发版说明（单列一条）。
   漏一处，以后看代码的人会以为 7 天还是硬约束。
2. **面板要显式显示当前档位**，不能只藏在配置 JSON 里——
   「永久」意味着这台机器会一直留着所有群聊原文（含别人的私聊），
   这句话要写在开关旁边，不是埋在文档里。
3. **默认值只改一次，不给老用户静默切换**：升级说明里写「默认保留期已从 7 天改为永久，
   可在面板「账本」页改回 7 天/30 天/自定义」。

方向本身是**更安全**的（不丢数据），代价是隐私面变大、磁盘会一直涨。
后者由面板的「占用」和「压缩」来管，见 §四。

---

## 二、现状（实测，2026-11-05）

| 指标 | 实测值 |
|---|---|
| 行数 | 447 条 / 7 天 |
| `payload` 合计 | 417 KB（均值 934 B，上限 1908 B） |
| 数据库文件 | 1.1 MB（含索引与 `event_refs`） |
| 增长速率 | ≈ 64 条/天、≈ 2.5 KB/条 → **约 58 MB/年** |

推论：按现在这个量，永久保留完全不是问题。但这是**一个群、一周 447 条**的量级；
热闹群按 10 倍算就是 580 MB/年，所以面板必须能看到「占多少」，不能只有开关。

## 三、三个必须认的代价

### 3.1 SQLite 删了不缩文件，而且**不能**在请求里压

`DELETE` 只把页标成空闲，文件大小不变。所以「面板删掉 100MB」之后磁盘还是占着——
必须显式 `VACUUM`。

但**不能把 `VACUUM` 放进 HTTP 路由**：`DatabaseSync` 是同步 API，VACUUM 锁几秒会把整个进程卡住，
所有机器人的收消息一起停。`host.js:4188` 对 journal 已经有同样的裁定，原话是
「磁盘上的旧页由巩固时的 `vacuum()` 压掉，**不在请求里做**」。

照 journal 的现成做法（`journal.js:236-243`）：**写一个标记文件 + 由定时器消费**。

```
面板点「压缩」 → 写 data/bots/<id>/.vacuum 标记 → 立刻返回「已排队」
定时器（每小时那次 prune 之后） → 看见标记就 VACUUM + checkpoint → 删标记
```

`PRAGMA wal_checkpoint(TRUNCATE)` 有一个坑：它**返回一行结果**，
用 `db.exec` 拿不到，必须 `db.prepare('PRAGMA wal_checkpoint(TRUNCATE)').get()`。
全仓目前没有 checkpoint 先例（grep 只有注释），这是第一处。

### 3.2 WAL 会涨

`events.db-wal` 现在 41 KB。长期写入 + 不 checkpoint 会持续涨。
面板的「压缩」按钮顺带做一次 `wal_checkpoint(TRUNCATE)`。

### 3.3 删除不可逆

面板删除是**主人本机操作**，没有回收站。所以删除流程必须：

1. 先显示「将删除 N 条，时间范围 X→Y，涉及 M 个会话」；
2. 提供「先导出再删」——导出 CSV/JSONL 到 `data/exports/`；
3. 二次确认要输入数字（`N`），不是点两下确定；
4. 删除后提示「文件大小未变，需要压缩」。

## 四、设计

### 4.1 配置

```jsonc
"ledger": {
  "enabled": true,
  "retentionDays": 0,        // 0 = 永久（默认）；7 / 30 / 任意天数
  "autoVacuum": false        // 默认关：压缩要锁库，交给面板手动触发
}
```

面板上不暴露这个原始数字，而是**四档**（选中即写回 `retentionDays`）：

| 面板选项 | 写入值 |
|---|---|
| 永久保留（默认） | `0` |
| 7 天 | `7` |
| 30 天 | `30` |
| 自定义… | 用户输入的天数（`1–36500`，0 和负数一律拒） |

「自定义」不放在下拉里当第五个选项，而是选完弹一个输入框——
下拉里出现「自定义…」再让用户填数字，比给一个空输入框更不容易填错。

`src/ledger.js:128` 现在是 `Math.max(1, Number(retentionDays) || 7)`，
**这个钳制会把 0 吃掉两次**（`Number(0) || 7` → 7，再 `Math.max(1,7)` → 7），必须改成：

```js
const n = Number(p.retentionDays);
this.retentionDays = n === 0 ? 0 : Math.max(1, n || 0);
```

**但只改这一行不生效**——默认值有四处各自兜 7 天，漏一处就是「面板显示永久、库里照删」：

| 位置 | 现在 | 改成 |
|---|---|---|
| `ledger.js:124` | 解构默认 `retentionDays = 7` | `= 0` |
| `ledger.js:128` | `Math.max(1, Number(...) \|\| 7)` | 见上 |
| `bot.js:235` | `cfg.ledger?.retentionDays ?? 7` | `?? 0` |
| `config.js:265` / `:517` | 两处 `retentionDays: 7` | `0` |

`config.js:463` 是 `deepMerge(BOT_DEFAULTS, file)`，所以 `cfg.ledger.retentionDays`
永远存在——**它不会走到 `?? 0`**，真正生效的是 `config.js` 那两处默认值。

**`prune()` 的 guard 不能放在第一行**：`prune()` 里第一件事是 `this.resolveRefs()`（`ledger.js:328`），
而它是全仓唯一的引用边解析入口（另一个调用点是测试）。放在前面会让引用边永远不解析，
`stats().unresolvedRefs` 单调涨到全量。正确写法：

```js
async prune() {
  if (!this.available || this.closed) return 0;
  this.resolveRefs();              // ← 先解析
  if (!this.retentionDays) return 0;  // ← 再决定删不删
```

### 4.2 数据层（`src/ledger.js`）

**先纠正一处**：`stats()` **不是新增，是扩展现有方法**。它现在返回
`{ available, total, oldestAt, newestAt, seqMax, unresolvedRefs, retentionDays }`
（`ledger.js:467`），而 `total` / `seqMax` 被 5 处测试和面板兜底吃掉了
（`test/selftest.mjs:4364/4494/4505/4508` 用 `.total`，`:4497` 用 `.seqMax`，
`web/server.js:2268` 的兜底是 `{ available:false, total:0 }`）。
所以只能**加字段**，不能换结构，否则面板概览变 `undefined`。

| 方法 | 状态 | 用途 |
|---|---|---|
| `stats()` | **扩展**：加 `rows` / `bytes` / `byChat`，保留 `total` / `seqMax` | 概览 + 按会话汇总 |
| `recent({chatId, limit, beforeSeq})` | **现成**（`ledger.js:418`） | 面板列表直接用；`limit` 被夹到 1–500，`beforeSeq` 就是游标 |
| `get(id)` | 现成，**别动返回形状** | 返回原始行（snake_case + 整包 payload），ai-chat 的 `/r/context` 正吃它 |
| `remove({chatId, before, keepLast, ids})` | 新增 | 四种删除口径，返回 `{ removed }` |
| `requestVacuum()` | 新增 | 只写标记文件，见 §3.1 |
| `exportRows({...})` | 新增 | 生成 CSV 文本（不落盘，交给 server 写响应） |

`recent()` 返回的是**正序**（内部倒序取再 reverse），所以「下一页」的游标要拿
`items[0].seq`，不是最后一条——这一条最容易写反，写反的表现是翻页原地打转。

`stats()` 里的 `name` 从 `data/bots/<id>/groups.json` 和 `sessions.json` 取，
取不到就显示 openid 短码——面板上不能只有一串乱码。

### 4.3 面板：新页签「账本」

放在「数据」组里（现在有 统计 / 事件 / 可达性 / 投递 / 日志），加第六个「账本」。
注意**「事件」页是 QQ intent 订阅列表，不是账本**，两回事，别混。

**加一个页签要动 4 处**（CSS 不用动，`.panel` / `.table-wrap` 都是通用的）：

1. `index.html:57-61` 导航里加 `data-tab="ledger"`；
2. `index.html` 里加 `<div class="panel" data-panel="ledger">`（照 `:692-717` 的投递页）；
3. `app.js:562-607` 的 `activateTab` 加一条 `if (name === 'ledger') loadLedger();`；
4. `app.js:232-239` 的 `selectBot`（切机器人重拉）也要加，否则换机器人后页面不刷新。

**「投递」页不能直接抄全**：它是纯只读（`app.js:3181-3234` 只有 `loadDelivery` +
`renderDelivery`），**没有分页、没有确认弹窗、没有删除**。能抄的只有表格和状态卡片的外观；
删除确认用全局的 `confirmDialog`（`app.js:44`），`deleteBot`（`app.js:253-260`）是
「danger + okText」的用法范例。

页面结构：

```
┌ 概览 ─────────────────────────────────────┐
│ 447 条 · 1.1 MB · 10-29 → 11-04 · 永久保留 │
│ 保留：[永久▾]  [压缩数据库]                │
└───────────────────────────────────────────┘
┌ 会话 ─────────────────────────────────────┐
│ roost交流群   329 条  11-01→11-04  [查看][删]│
│ 机器人测试     97 条  10-29→11-04  [查看][删]│
│ 私聊 FC7BB5    21 条  10-29→11-03  [查看][删]│
└───────────────────────────────────────────┘
┌ 记录（点某个会话后展开）──────────────────┐
│ 时间 / 谁 / 内容（截断）/ 类型             │
│ [上一页] [下一页]        [导出本会话]      │
└───────────────────────────────────────────┘
```

删除对话框（三种口径，互斥）：

- **删这个会话的全部**；
- **删 X 之前**（日期选择器）；
- **只保留最近 N 条**（数字输入）。

每种都先给预览数字，再要输入该数字确认。

### 4.4 API（`src/web/server.js`，沿用现有写操作校验）

**插在哪**：现有三条账本路由在 `server.js:2267-2289`，全是 `pathname === '…'` 的 if 链，
新路由插在 2289 之后即可。**千万不要写成 `startsWith('/api/ledger')`**——那会把现有三条一起吃掉。

**写操作要过四道闸**（`server.js:1089/1095/1105-1116/1118`）：
授权、page token 白名单、**非 GET 必须 `application/json`（否则 415）**、同源。
前端 `api()` 封装已经带了 JSON 头，照用即可。

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/ledger/stats` | GET | 概览 + 按会话汇总 |
| `/api/ledger/rows` | GET | `chatId` / `beforeSeq` / `limit` / `q` |
| `/api/ledger/export` | GET | `format=csv`（默认，给人看）/ `format=jsonl`（**给导回用**） |
| `/api/ledger/import` | POST | 收 JSONL 解析后的 `{rows}`；幂等（有 msgId 按它去重，没有按 at+正文指纹） |
| `/api/ledger/delete` | POST | `{ chatId?, before?, keepLast?, confirm }` |
| `/api/ledger/vacuum` | POST | 压缩 + checkpoint |

`confirm` 必须是**将要删除的条数**，服务端重新数一遍再比对——
前端算错了就直接拒，不做「尽力而为」的删除。

### 4.5 隐私与权限

- 面板本来就是主人本机管理面，能看到全部会话（含别人的私聊）是合理的——
  这是「机器所有者」权限，和 `chat_look` 工具那条「别人私聊永不返回」不冲突，
  因为后者是**给模型**的边界，前者是**给人**的。
- page token 白名单（`server.js:701` 的 `pageTokenAllows`）默认不含新路由，
  所以带 page token 的分享链接打不到账本接口，**保持现状即可，别加进白名单**。

## 五、连带简化（值得一起想）

账本一旦永久保留，`chat_look` 的 `source:'journal'` 就失去了「长期」这个唯一优势：

| | 现在 | 账本永久后 |
|---|---|---|
| 7 天内的全量事实 | 账本 | 账本 |
| 7 天前的原文 | 只有日记（且被拼装物污染） | **账本也有，而且是干净的** |
| 她自己说过什么 | 日记 / A 之后账本 | 账本 |

所以如果这个改动先落地，`chat_look` 可以**只留一个源**，`source` 参数直接去掉。
但要注意顺序：`source:'journal'` 现在的价值是「A 落地前能看到她的回话」，
账本永久化不解决这一点（永久化 ≠ 有出站），所以**只有 Part A 也落地后**才能真的砍掉日记源。

结论：先不动 `chat_look`，等 A 落地后再评估能不能砍。别为了「少一个参数」提前做。

## 七、已决定（2026-11-05）

1. **默认永久**（`retentionDays: 0`）。面板四档：自定义 / 7 天 / 30 天 / 永久。
   连带要改 `config.js` 注释、`docs/地基三块方案.md:138`、README 隐私说明、发版说明（见 §一）。
2. **入口在面板**，不藏配置项：档位可见、代价写清（§一 第 2 条）。
3. **删除三种口径**（整会话 / 某时间前 / 保留最近 N 条），不做「按关键词删」——
   误删风险高、收益低。
4. **不自动备份整库**，只保证「先导出再删」这条退路（导出 CSV/JSONL 到 `data/exports/`）。

> 还有一个**没做但要知道**的后果：默认永久之后，`events.db` 只增不减。
> 面板的「占用」和「压缩」是唯一的刹车，所以这两个不能省，也不能放到第二版。
