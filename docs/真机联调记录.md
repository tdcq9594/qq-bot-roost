## 八、图片补齐（15:23–15:30）

### 为什么之前没图

内容表 `image` 列一直是空的——内容包从 INI 生成时只带文字，没有美术资源，
所以真机发出来的全是纯文本。之前只写了匹配脚本，没实际生成。

### 尝试过的方案

| 方案 | 结果 |
|---|---|
| PowerShell + System.Drawing 渲染中文 | ✗ `Add-Type` 被安全策略拦（禁止运行时编译 .NET） |
| 纯 Node 手写 PNG 编码器 | 能做，但没有字体渲染，图上看不到名字 |
| `placehold.co` | ✗ 超时 |
| `ui-avatars.com` | ✓ 支持中文、配色可控、约 10KB/张 |

### 最终做法

`fill-images.mjs` 加 `--fetch`：从模板**下载成本地文件**，而不是写远程 URL。
本地文件让 QQ 上传的是文件本身，不依赖第三方服务长期在线。

按类型配色（武魂紫金 / 地图青绿 / 魂兽暗红 / 装备钢蓝 / NPC 暖褐），
共 **273 张 · 2.7MB · 10KB/张**，覆盖率 100%。

图库两处：机器人自己的 `data/bots/<id>/plugins/douluo/images/`（优先）
+ 插件自带 `plugins/douluo/images/`（随插件分发）。`media.js` 先查前者，找不到回落后者。

真机验证：

```
/武魂            → [图片]【武魂】蓝银草 · 控制系 · 普通 · 生命 112 …
/地图            → [图片]【圣魂村】
/挑战魂兽 哥布林  → [图片]【哥布林】战斗开始
```

QQ 返回 `https://multimedia.nt.qq.com.cn/download?...` —— 本地 PNG 上传成功，图文同条。

## 十一、回复里露出 mqqapi:// 长串（17:09 修）

### 现象

群里部分回复直接显示了 `(mqqapi://aio/inlinecmd?command=%2F%E9%AD%82%E5%85%BD&...)`。

### 根因

`clink()` 生成的是 markdown 链接，只有 **markdown 消息**才会被渲染成按钮。
`msg.reply()` / `media.send({ text })` 是**纯文本**，里面的 `[文字](url)` 原样露出。

三处踩坑：
1. `武魂觉醒` 没角色 → 「先 [创建账号](…)」
2. `武魂觉醒` 钱不够 → 「去打怪攒钱：[魂兽](…)」
3. `删号` 确认提示 → 「确定要删就点 [删号 确认](…)」

### 修复

- 前两处改成纯文本指令名
- 第三处改成 `replyMarkdown`（内容本来就是 markdown：`##` + `**`）

### 真机对比

```
# 修前（纯文本，链接裸露）
──────── 发：/删号 ────────
  │ ## 确认删号？
  │ > 确定要删就点 [/删号 确认](mqqapi://...)

# 修后（markdown，链接渲染成按钮）
──────── 发：/删号 ────────
  │ [markdown]## 确认删号？
  │ **确定要删就点** [/删号 确认](mqqapi://...)
```

注意 `[markdown]` 前缀——onebot 用这个标记消息类型，说明走的是 markdown 通道。

### 防止再犯

新增 `scripts/lint-links.mjs`：按**括号配对**找 `msg.reply()` / `media.send()` 的参数范围，
检查里面有没有 `clink(`。已接进 `test/journey.mjs`。

**为什么按括号配对**：按行扫会把后面语句里的 clink 也算进来，误报率极高
（第一版就误报了 4 处，全是 `replyMarkdown` 里的链接）。
